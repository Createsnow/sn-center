# 多工厂 SN 防重管控

总部统一生成并分配 SN（可代任一工厂领取、打印、转厂），工厂按 PI 领取、打印；**SN 全局不重复**。

- 前端：Vue 3 + TypeScript + Vite + Element Plus（简体中文 / English / Tiếng Việt）
- 后端：Python 3.12 + FastAPI + PyMySQL + structlog（目录结构与 `main` 分支相同：`app/{api,core,db,middleware,models,schemas,services}`；SQL 直接写在 services 里，不另设仓储层）
- 数据库：**MySQL 8**（启动时自动建表，Flyway 兼容的 `flyway_schema_history`；操作痕迹按月分区）
- 外部：金蝶 K3 Cloud 生产订单 / 组织机构（只读同步到本地快照）

## 快速开始

```bash
cp .env.example .env     # 填 DB_HOST / DB_PORT / DB_NAME（开发 sn_dev、测试 sn_test、正式 sn_prod）/ DB_USER / DB_PASSWORD、SN_SECRET（≥ 32 位随机串）、K3_*
python start.py          # Windows 可双击 start.bat；需要 Python 3.12+、Node.js 20+
```

浏览器打开 `http://127.0.0.1:8000`，用 `.env` 里的 `SN_INIT_ADMIN_EMP_NO` + `SN_INIT_ADMIN_PASSWORD`（默认 `admin` / `Admin@123`）登录，再在「账户」页创建其他账户（只有这个内置管理员能建、改账户，它建的管理员不能再建账户）。同一台机器可在不同浏览器标签页同时登录不同账户（新标签页要自己登录）；同一账户只在最后登录的那个页面有效，之前的页面会自动退出。
本机没有金蝶时可设 `SN_DEMO_SEED=true` 灌入演示工厂、规则、订单与账户（**连公司库务必关闭**）。

服务器：`docker compose up -d --build`（详见运维手册；Docker 方式为 `ENVIRONMENT=production`，`SN_SECRET` 为空、为示例值或不足 32 位会拒绝启动）。接口文档：`/docs`（对外接口在 `open` 分组）。

## 功能一览

| 页面 | 角色 | 功能 |
| --- | --- | --- |
| 首页 | 全部（按可看范围） | 在途状态枚数（待分配只给总部看）、待处理转厂、今日作业量、累计生成（不绑厂的账户）、最近生成任务（总部） |
| 生产订单 | 总部、查询员 | 金蝶快照：左表按单据汇总数量 / 已生成 / 可生成，右表物料行（查询员只读，绑厂的只看所绑工厂的订单）；总部新开页面或登录后首次进入自动全量同步一次，也可手动全量或按单据同步；可开启定时全量同步（总部设置间隔 10 分钟–7 天） |
| 生成与分配 | 总部 | 每张 PI 一行，五个页签：全部 / 待生成 / 生成中 / 待分配 / 已完成（除「生成中」外只列最近下单的 3 页，更早的用搜索找）；可搜 PI / 客户 / 单据 / PO。行上按钮写下一步：「生成」「选规则」「分配」或「查看」（「分配」直接整张 PI 分配，其余打开详情）。详情抽屉：步骤条（SN 规则 → 生成 → 分配）+ 当前一步的面板 + 订单 / 生成任务 / 分配记录三个标签页。规则未定时从规则库选模板或自定义规则（前缀 + 进制 + 位数 + 后缀），可「绑定」给 PI、可解绑；数量默认填满额度（超过 1 万默认限制、可解除），停顿后自动预演，按单据号顺序占用各订单额度、号段接续；整张 PI 在一个事务里生成，任何一张失败全部回滚（大批量后台任务 + 进度，可取消）；整张 PI 一次分配，各订单分到各自的生产组织；分配前可撤回最近一次生成（只撤流水排在最后、号全部仍待分配的一次，号删除、额度退回，原因必填） |
| 规则库 | 总部 | 规则库新建的都是通用规则（可多条），只做分类：未分类 / 客户 / PI（同一对象可多条，只用于筛选和在生成页查找，不影响生效）；列表按全部 / 未分类 / 客户 / PI 筛选，选客户或 PI 后可再选具体对象，另列只读的生效绑定。前缀必填且不能互为开头；绑定在生成页做（按 PI ＞ 给该 PI 指定 ＞ 按客户 生效），自定义规则生成成功后按 PI 归档为 `PI号_v1`；同一规则被多张 PI 沿用时后缀自动加 `_v版本号`；未用过的版本就地修改，用过的另出一版，改名不出版本；没生成过号、也没指定给 PI 的规则可删除（留痕） |
| 领取与打印 | 全部（查询员只读） | 每个「工厂 + PI」一行，显示「待领取 → 待打印」进度，四个页签（全部 / 申请中 / 待领取 / 待打印，各只列最近有动作的 3 页，更早的按 PI 搜索），行上按钮执行下一步：按「工厂 + PI」整批领取、打印（下载打印文件）；可勾选多张 PI 批量操作（批量按钮与行按钮一致：每张 PI 只算进它行按钮那一步）；点 PI 打开号段（按「工厂 + PI + 物料 + 连续号段 + 状态」分行，可只读看各厂分布、按物料带入转厂） |
| 转厂 | 全部（查询员只读） | 转厂单列表（总部默认看待处理）；新建时按「转哪些号 → 转到哪里 → 原因」填写，转入目标从订单快照搜索或手工填写，右侧实时校验；工厂申请 / 撤回；总部确认 / 驳回 / 直接转移；整张 PI、PI + 物料、单枚 SN 三种范围；转出厂可查已转出的号 |
| SN 查询 | 全部 | SN 明细：按工厂（仅总部有工厂筛选，其他账户按可看范围自动过滤）/ 客户 / PI / 物料 / 状态 / SN / 来源订单 / 批次筛选，可按流水号范围查（如 0001-0030，须填 PI），附范围内各状态枚数与缺号数，厂区可只读查看同 PI 各厂，导出 xlsx / csv；领取批次、打印记录：按批次号 / 打印单号 / 请求号 / 来源（页面或 MES 接口）查找，看批次明细、导出批次文件（格式同打印文件，只读；MES 回调打印的号从这里取文件）、重新下载打印文件 |
| 操作痕迹 | 全部（按范围） | 登录、账户、工厂、订单同步、规则、SN、转厂全流程留痕（含失败）；筛选、导出；保存期与归档 |
| 账户 / 工厂 | 总部（账户仅内置管理员） | 只有内置管理员能建（任一角色）、改、停用账户；工号唯一；厂区操作员绑一个工厂，查询员可绑一个、多个或不绑（= 全部工厂）；新建账户直接可用，管理员重置密码后下次登录须改密；只停用不删除，可重新启用；工厂从金蝶同步（每次进入工厂页自动同步一次）或手工建档，可改名、停用 / 启用（停用后不能再作为生成、分配、转入、账户绑定的目标） |

对外接口（MES / 打印系统）：`POST /api/open/acquire`（按 PI 整批领取，请求号幂等）、`GET /api/open/batches/{batch_no}/items`（分页明细）、`POST /api/open/callback`（打印回调）、`GET /api/open/sn`（只读拉取）。

## 开发与测试

```bash
uv sync && uv run uvicorn app.main:app --reload --port 8000   # 后端（读仓库根 .env）
cd frontend && npm install && npm run dev      # 前端 5173，代理 /api 到 8000

uv run pytest -q                               # 单元 + 集成测试（集成测试需 MySQL，默认 127.0.0.1:3306/sndb_test_py，会整库重建，不要指向 sn_dev / sn_test / sn_prod；连不上自动跳过）
uv run ruff check app tests                    # 代码检查
node --test frontend/src/*.test.js             # 前端测试
python3 frontend/scripts/gen_locales.py        # 改了词条 / 错误码后重新生成三种语言文件
```
