# 爱德泰·溯码中台（多生产组织 SN 防重管控）

总部按金蝶生产订单的物料行统一生成 SN，分配到订单的生产组织：**对接 MES 的组织由本系统分批推送（MES 也可主动取批），已分配的号都可在 SN 分配页的「已分配」页签下载**；每一批都有回执或人工处理的出口，**SN 全局不重复、同一枚号不会重复交付**。

- 前端：Vue 3 + TypeScript + Vite + Element Plus（简体中文 / English / Tiếng Việt）
- 后端：Python 3.12 + FastAPI + PyMySQL + structlog（`app/{api,core,db,middleware,models,schemas,services}`；SQL 直接写在 services 里）
- 数据库：**MySQL 8**（启动时自动建表，Flyway 兼容的 `flyway_schema_history`；操作痕迹按月分区）；业务时间一律按 UTC 存储，页面按生产组织的时区显示
- 外部：金蝶 K3 Cloud 生产订单 / 组织机构（只读同步到本地快照）；各生产组织的 MES（推送 + 拉取 + 回执）

## 快速开始

```bash
cp .env.example .env     # 填 DB_HOST / DB_PORT / DB_NAME（开发 sn_dev、测试 sn_test、正式 sn_prod）/ DB_USER / DB_PASSWORD、SN_SECRET（≥ 32 位随机串）、K3_*
python start.py          # Windows 可双击 start.bat；需要 Python 3.12+、Node.js 20+
```

浏览器打开 `http://127.0.0.1:8000`，用 `.env` 里的 `SN_INIT_ADMIN_EMP_NO` + `SN_INIT_ADMIN_PASSWORD`（默认 `admin` / `Admin@123`）登录。系统管理员只有这一个，只有它能建、改账户和授权生产组织（角色与权限见运维手册第 6 节）；同一账户只在最后登录的那个页面有效。
本机没有金蝶时可设 `SN_DEMO_SEED=true` 灌入演示数据（**连公司库务必关闭**）。

> 开发阶段只保留一个完整的建表脚本 `V1__init.sql`（已按 PRD V31 重写），不用 ALTER 补丁；旧的演示 / 测试库不能原地升级，须清空本系统的表后重建（见运维手册 8.1），重建后只有系统管理员账户。

服务器：`docker compose up -d --build`（详见运维手册）。接口文档：`/docs`（MES 接口在 `open` 分组）。

## 功能一览

侧栏按业务模块分组（与 new.md 一致）：**工单管理**（生产订单）、**SN 管理**（SN 生成 / 分配（含导出）/ 转移 / 查询 / 规则库）、**箱号管理**、**托号管理**（建设中，占位页）、**日志管理**（操作日志）、**账户管理**（用户、用户组）、**组织管理**（生产组织、生产部门）。菜单配置在 `frontend/src/router/index.ts` 的 `MENU`，新模块加一组即可，已有页面路径不变。

| 页面 | 角色 | 功能 |
| --- | --- | --- |
| 首页 | 全部（按授权组织） | 各状态枚数（待分配不给审计员看）、暂停交付、推送中断、拉取未回执、待处理转组织、订单变更提醒、交付告警、今日作业量、最近生成任务与最近失败批次 |
| 生产订单 | 系统管理员、普通操作员（授权组织） | 金蝶快照（只含已审核单据）：上表按单据汇总（含生产部门）、按金蝶修改日期越新越前，下表物料行（附件项次、物料、产品名称、规格型号、规格描述、米数、产品单位、数量、客户 P/N、客户产品描述、生产部门；后几项只显示）；进页触发一次比对同步，另可按单据同步、立即比对、全量重建；附件项次、米数、产品单位为空的标红「缺失」、米数和产品单位含中文的标红（在生成页填写 / 改掉，米数含中文时改过才能生成，规则带单位时中文或空的产品单位填了不含中文的单位才能生成）；订单变更提醒（PI / 生产组织 / 客户 / 数量 / 物料 / 附件项次变化、反审核、删除）与处理，相关单据暂停交付 |
| SN 生成 | 系统管理员、普通操作员（只含授权组织的单据） | 每张 PI 一行（待生成 / 生成中 / 已生成完）；详情按单据 → 物料行展示，金蝶缺失的附件项次（必填）和米数（选填，默认 000，按字符串原样写入 SN）在物料行里直接填写，产品单位为空或是中文（条、个等）时规则带单位须填写不含中文的单位（M、m、L 等），物料行有号后置灰（撤销生成后可改，分配后不能改），规则按「物料行选定 ＞ PI 绑定 ＞ 客户默认」生效，「选规则」默认自定义页签，前缀默认取本 PI 第一张单据编码后 7 位、同一 PI 各张单据共用（沿用已用的格式，流水接续），保存和确认生成时后台查前缀全局唯一、冲突弹窗提示，也可从规则库选（已用于别的 PI 的版本须换新前缀）；勾选单据或物料行作为范围，按物料行整行预演、生成（不填数量，大批量后台执行、可取消）；行末改规则、撤销，也可勾选后批量：从流水最末往前撤到所选行为止（流水在其后的行一并撤）；只撤未分配的号；待处理页签中还没有号的行可撤销配置（物料行规则、手填的附件项次、米数和产品单位恢复为未配置），单行或勾选后批量；详情按单据 → 物料行（单据头带生产部门），页签名不带数字，页签、弹窗不放提示文字；底部操作栏三个页签相同：「选规则」「撤销」「生成 N 枚」 |
| SN 分配 | 系统管理员、普通操作员（授权组织） | 左侧单据列表（按号取，只按 PI / 单据编号筛选；列单据、SN 枚数、状态：待分配 / 待处理（已分配但推送未完成，含推送失败）/ 已分配；页签：待分配（含待处理）、已分配），右侧为所选单据所在的 PI。待分配页签：单据 → 物料行（SN 枚数、号段、分到的生产组织、推送进度条，单据头也有进度条），勾选物料行或整张 PI 分配到订单的生产组织（对接 MES 的自动分批推送，中断时顶部提示并续推）；下方「推送进度」页签只在还有待推送的号时显示（分配后出现，推完消失，有失败批次时一直显示）：各组织第 i / N 次，依次分页列出推送批次（批次号、状态、时间，未确认、失败的批次可人工确认或作废）。已分配页签：不分子页签，上方单据、下方逐枚 SN（SN 导出，见下行）。右侧始终跟随左侧列表，列表为空时右侧也为空 |
| 规则库 | 系统管理员、普通操作员（全局规则只能选用；授权组织的规则可增删改） | 规则（前缀 + 流水（补 0）+ 米数前分隔符 + 米数（补 0，可选）+ 米数后分隔符 + 单位（可选）+ 后缀，不限制字符，10 / 16 / 32 / 36 进制）只做分类（未分类 / 客户 / PI）；前缀全局不能相同（只是开头相同如 SD 与 SDD 可以）；用过的版本改格式须另出一版并换新前缀 |
| SN 导出（并入 SN 分配页「已分配」页签） | 系统管理员、普通操作员（授权组织；审计员在 SN 查询导出，旧地址 `/export` 自动转过去） | 与 SN 分配后的推送、拉取相互独立：所选 PI 的号一经分配（不论是否对接 MES、推送是否成功）就按「生产组织 + 单据」一行列出（不显示交付方式），枚数旁只提示申请中、暂停的枚数；下方直接逐枚列出所选单据的全部 SN（不按号段合并；SN、进制、进制流水、十进制流水、状态、交付批次；可按物料编码、SN 起止号筛选），或直接下载 xlsx（列与 SN 查询导出统一：含组织编号、中文生产组织名称，物料编码后带附件项次、米数）；只读、不改状态、可反复下载 |
| SN 转移 | 系统管理员、普通操作员（涉及的组织须在授权范围内，目标不在范围内的转组织走申请） | 转单与转组织合在一页：一张记录表（按类型、状态筛选，待处理标色），一个「新建转移」入口（总部先选转单或转组织，左来源、右目标）。来源按 PI → 单据筛选，整张单据、单据 + 物料编码下全部号、或单枚 / 连续号段三选一；目标 PI、单据、生产组织、物料编码必填，号改挂到目标物料行（已生成数随号移动）。转单：生产组织取目标单据的；转组织：生产组织申请、总部确认 / 驳回或直接转；已交付 MES 的号按改派、新号或转出批次通知新旧 MES；转出号清单供来源现场作废旧标签 |
| SN 查询 | 全部（审计员只有 SN 明细） | SN 明细（按组织 / 客户 / PI / 单据 / 物料 / 米数 / 状态 / 交付方式 / 批次 / 流水范围筛选，导出）；交付批次（推送、拉取、转出）明细与回执，总部人工确认或作废；交付告警（每日自检问题）核查后关闭 |
| 操作痕迹 | 系统管理员、审计员（授权组织） | 登录、账户、生产组织与 MES 配置、订单同步与变更、规则、生成、分配、推送、拉取、回执、转单、转组织全流程留痕（含失败）；筛选、导出；保存期与归档 |
| 用户组 | 系统管理员 | 按功能模块分权：各用户组（即账户角色：系统管理员、普通操作员、审计员、MES 接口账户）能用的模块与启用账户数，只读，与侧栏菜单、接口权限同一套规则 |
| 生产部门 | 系统管理员、普通操作员（授权组织） | 订单快照中出现过的生产车间（金蝶明细 FWorkShopID），按生产组织列出单据数、物料行数，只读 |
| 箱号 / 托号管理 | 按角色 | 建设中：生成、转移、查询、规则库的占位页，只说明规划功能 |
| 账户（用户）/ 生产组织 | 系统管理员 | 页面账户（系统管理员（唯一）/ 普通操作员 / 审计员，后两者授权一个或多个生产组织）与 MES 接口账户（绑一个生产组织，可在开启对接 MES 之前先建，密钥加密保存、可随时查看或重置，可设来源地址白名单，连续认证失败锁定）；生产组织从金蝶同步，总部为每个组织配置 MES 对接（地址、认证方式、凭证加密保存、批次大小、超时、并发、时区），连接测试通过后才能开启 |

MES 接口（`/api/mes/v1`，每次请求带 `Authorization: Bearer <工号>:<密钥>`）：`POST /batches/next`、`POST /receipts`、`POST /sn/delivered`、`POST /batches/items`（一律 POST + JSON 请求体，地址中不带参数）；本系统推送到 MES 提供的地址。接口见 [MES 对接接口文档](docs/MES对接接口文档.md)，处理规则见 [MES 对接说明](docs/MES对接说明.md)。

## 开发与测试

```bash
uv sync && uv run uvicorn app.main:app --reload --port 8000   # 后端（读仓库根 .env）
cd frontend && npm install && npm run dev      # 前端 5173，代理 /api 到 8000

uv run pytest -q                               # 单元 + 集成测试（集成测试需 MySQL，默认 127.0.0.1:3306/sndb_test_py，会整库重建，不要指向 sn_dev / sn_test / sn_prod；连不上自动跳过）
uv run ruff check app tests devtools           # 代码检查
node --test frontend/src/*.test.js             # 前端测试
python3 frontend/scripts/gen_locales.py        # 改了词条 / 错误码后重新生成三种语言文件

uv run python -m devtools.mes_mock serve --port 9001 --secret 110=SN110:key-110   # 模拟 MES（接收推送、注入故障、取批）
uv run python -m devtools.mes_conformance --url <MES 地址> --org 110 --pi <PI> --secret <令牌>   # MES 接收接口契约测试
```

MES 方未接入时的联调方法见 [MES 联调指南](<docs/MES 联调指南.md>)。
