# 决策与变更日志

## DEC-20260929-010 持久操作、任务与文件恢复

承接用户“继续下一阶段”。采用MySQL持久模板和TaskHandler端口，framework不访问system业务表；system固定导出行快照作为首个消费者。主体+动作+operationId唯一，规范化摘要控制同号重放；每条入口仍检查当前完整快照权限，不能凭历史成功越权。@Idempotent标记模板契约，不额外引入Redis或AOP幂等状态。

提交事务先锁容量控制行；领取SKIP LOCKED并递增owner/epoch/租约，执行持有任务行锁再进入业务，租约过期不绕过在途事务。成功业务/审计/最终任务/操作结果同事务；进度独立表/新事务，失败在执行结束后锁行复核代次/终态。只有QUEUED且未领取可取消，HTTP断连不取消；有限重试/预算，优雅关闭停止领取。

文件采用受控临时产物、fsync/摘要/原子发布、数据库READY。文件和数据库非原子，发布后回滚通过核对同一产物恢复。成功操作的丢失/损坏文件从原快照按原摘要/原fileId重建，不重复业务审计；不同摘要不替换原文件。下载同句柄校验并逐读取块复核当前授权。目录拒绝链接/NTFS联接，损坏产物隔离，清理仅限持锁的同任务临时文件；共享盘、保留期和磁盘监控需后续验收。

V6只增量建表/导出权限并递增平台角色账号security_version，不改密码。导出两权限范围取交集，单次<=31天/10000行/16MiB，超限拒绝；CSV保留原ID字符，不保证表格软件自动类型识别。前端只持久保存每用户最近操作UUID，响应未知查原号，新意图需明确确认。48单元/架构、49真实IT、12前端单元和6真实浏览器流程通过；人工重点审查、实际强杀、多机及性能仍未完成。见[本阶段报告](../docs/reports/2026-09-29-S2-持久任务与文件恢复.md)。接续S3工厂/ERP/规则，保留S2错误码映射与综合审查待办。

## DEC-20260929-009 在线操作日志与入口失败审计

承接用户“继续下一阶段”授权。审计读取以 system:audit:list 的五类 SQL 数据范围为边界，不要求全局配置权；部门取日志追加时快照，SELF 取事件 user_id。V5 只追加字段/索引，历史 NULL 部门不回填推测值。列表、COUNT、详情及筛选元数据逐条登记 Mapper 策略，详情对白名单历史 diff 再次投影，异常结构省略并提示。

入口失败只取完成认证的 Actor；限流/CSRF/无效令牌等身份尚未验证的拒绝保持匿名。路由为服务器模板，未知或安全防火墙拒绝固定 /api/**，不保存原始请求内容。失败 REQUIRES_NEW，既有失败独立提交后才标记已记录，避免重复；身份快照单独一致性读，避免跨事务账号锁等待。审计不可写保留拒绝且仅输出 traceId/异常类型告警，不保证故障期间留痕。成功业务审计与 HTTP 失败可能同时存在，不能以响应结果推断事务已回滚。

页面三语只读，默认7天/单次31天，每页最多100、最多10000页，元数据各200项。归档、SN 审计、应用外拒绝、防篡改和性能/人工审查仍待做；详细证据见 [本阶段报告](../docs/reports/2026-09-29-S2-操作日志与入口失败审计.md)。接续持久操作号/幂等、任务与文件，不提前关闭 F-23 或全部 S2。
