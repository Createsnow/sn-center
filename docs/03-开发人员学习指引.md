# Adtek 开发人员学习指引 0.1.0

目标是独立交付一次完整功能。需要理解 Java 21、Spring 依赖注入与事务、HTTP/JSON、SQL 索引和隔离级别、TypeScript/React hooks、Git，以及前后端调试。不要求先熟悉 SN。

本指南可以直接照做。按用户 2026-10-04 的要求，本轮以指南、可运行样板和已验证命令交付为完成；下面的练习供自学，不要求另一位开发人员执行、填写记录或评审后才能结束本轮工作。

## 直接使用

1. 按[新项目创建指南](02-新项目创建指南.md)在新目录复制模板，准备独立数据库与 Redis，执行检查、启动、登录并修改初始密码。
2. 在设备台账中新增 `TRAIN-001`，查看详情并编辑名称、启用状态；按[业务开发样例](04-业务开发样例.md)追踪这次操作的前后端代码和事务。
3. 开发自己的功能时，对照[开发框架规范](01-开发框架规范.md)落实模块分层、权限、数据范围、并发和审计；需要练习时可完成下述工装台账。
4. 执行[常用命令与问题排查](05-常用命令与问题排查.md)中的格式、契约、后端、前端和浏览器检查，用[开发自查清单](开发自查清单.md)核对结果。

## 学习顺序与成果

| 阶段 | 实操 | 可检查成果 |

## 可选完整练习：工装台账

在复制的新工程中新增独立 tooling 模块，保留设备样板作为参考。工装具有稳定编码（64）、名称（128）、位置（128）、启用状态、版本、服务器所属部门/创建人。新建 `V3__tooling_register.sql`，编码唯一；详情/列表/新增/编辑分别授权，普通用户仅本人范围，管理员全部范围。

完成 Entity、Create/UpdateDTO、Query、VO、MapStruct、Mapper、Service 接口/实现、Controller；不要把设备 Entity 跨模块复用。增加父 POM/server 依赖和 MapperScan，登记准确 DataPermissionRules、菜单/按钮、后端组件注册表、React 路由。为 tooling 分配未占用错误号段并扩展目录测试。

前端增加运行时契约检查、Query key、三语文案、分页/状态过滤、详情与编辑弹窗。新增审计字段“位置”，同时完善允许字段、投影与三语名称。后端输出服务端部门/所有者，客户端不赋予权限。

至少覆盖：正常流程；超长输入；大于 2^53 的 ID；重复编码和并发创建；两次原版本编辑仅一次成功；本人账号不能读改另一个人的工装；读权限不扩大写权限；权限撤销后拒绝写入；成功审计写失败时工装回滚。浏览器测试必须操作真实页面和独立 MySQL/Redis。

## 后续功能开发的交付建议

实际开发新功能时，建议随代码记录采用的模板版本/提交、新目录与隔离库说明、变更提交、迁移文件、接口契约、检查输出和完成页面截图。说明哪个约束由数据库保证、哪个在服务检查、审计失败如何回滚，以及没有执行的环境。

自查或代码评审时核对模块边界、授权来源、独立读写范围、更新版本条件、审计白名单、三语/精确 ID、可运行命令及证据。检查应发现并执行预期用例，不能只看退出码。模板已执行的验证见[本地验收记录](reports/模板验收记录.md)。
