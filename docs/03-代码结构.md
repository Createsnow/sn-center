### 业务模块分层

system 与每个业务模块使用相同的包结构：

```text
com.adtek.{module}
├── controller      XxxController        HTTP 入口，调用 Service，返回 Result
├── service         XxxService           用例接口（跨模块可见）
│   └── impl        XxxServiceImpl       用例实现：权限、范围、事务、并发、审计（仅本模块）
├── mapper          XxxMapper            MyBatis-Plus Mapper 接口（仅本模块）
├── domain          XxxEntity            持久实体
├── dto             XxxCreateDTO / XxxUpdateDTO   写入参数
├── query           XxxQuery             查询过滤与分页
├── vo              XxxVO                返回视图
├── convert         XxxConvert           MapStruct 映射
└── constant        ErrorCodeConstants 等 模块常量与错误码
src/main/resources/mapper/{module}/XxxMapper.xml                     自定义 SQL（只访问本模块的表）
src/main/resources/db/migration/{module}/V{yyyyMMddHHmm}__{说明}.sql  本模块迁移（只建改本模块的表）
```

调用方向：`controller → service → service.impl → mapper → domain`。Controller 不依赖 mapper、domain 与 service.impl；domain 不依赖上层；dto/query/vo 不依赖 controller、service、mapper、domain。类名后缀与所在包必须一致；`service` 包只放以 `Service` 结尾的接口，`service.impl` 类以 `ServiceImpl` 结尾。以上规则均由 `ArchitectureTest` 强制。

### 新增业务模块

1. 复制 `backend/adtek-sample` 为 `backend/adtek-{业务}`，包名改为 `com.adtek.{业务}`，修改 `artifactId`。`adtek-sample` 本身保持为空骨架。
2. 在父 POM 的 `<modules>` 与 `<dependencyManagement>`、`adtek-server/pom.xml` 的依赖中登记新模块（登记后才会被打包，也才会被 `ArchitectureTest` 检查）。
3. `@MapperScan("com.adtek.**.mapper")` 自动覆盖任意层级的 mapper 包。
4. 在模块 `constant` 包新增实现 `ErrorCode` 的枚举（如 `XxxErrorCode`），分配独立号段（common 1000、system 1001，业务模块从 1002 起），翻译键 `error.{module}.{name}` 同步写入三语字典（`ErrorCodeCatalogTest` 检查）；表名统一使用 `{module}_` 前缀，实体显式 `@TableName`；迁移放在本模块 `src/main/resources/db/migration/{module}/V{yyyyMMddHHmm}__{说明}.sql`（`DataOwnershipTest` 检查）。
5. 前端在 `src/features/{业务}` 下新增页面与 API 封装，并在 `App.tsx` 注册路由。

## 前端

```text
frontend/
├── src/
│   ├── main.tsx              根渲染：StrictMode、QueryClientProvider、BrowserRouter
│   ├── app/
│   │   ├── App.tsx           应用外壳：Provider、布局与路由装配
│   │   └── queryClient.ts    TanStack Query 全局默认值（不自动重试）
│   ├── api/                  client.ts（统一客户端与信封校验）；按需新增 {feature}.ts、generated/schema.d.ts
│   ├── features/{feature}/   （按需新增）pages/、组件、hooks
│   ├── components/           （按需新增）跨功能复用组件
│   ├── stores/               （按需新增）Zustand 最小会话状态
│   ├── i18n/                 index.ts、locales/{zh-CN,en,vi}.json、三语一致性测试
│   └── styles.css
├── openapi/                  （按需新增）后端导出的 OpenAPI JSON
├── e2e/                      （按需新增）Playwright *.spec.ts
├── patches/                  依赖类型补丁
└── eslint / prettier / tsconfig / vite / vitest / playwright 配置
```

- 功能页面放在 `src/features/{feature}/pages/XxxPage.tsx`，在 `App.tsx` 中按路由 `lazy` 加载。
- 每个功能的 API 调用集中在 `src/api/{feature}.ts`，通过 `client.ts` 的 `apiGet`/`apiPost` 并为 data 提供解析函数，使用生成类型并对响应做运行时校验；失败为 `ApiError`（`key`、`args`、`traceId`），页面以 `t(error.key, error.args)` 呈现。
- 单元测试与被测文件同目录，命名 `*.test.ts`；浏览器测试放 `e2e/*.spec.ts`。
- `src/api/generated/` 为生成目录，不手工修改，不参与 lint/format。
