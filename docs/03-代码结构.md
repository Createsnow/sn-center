### 业务模块分层

system 与每个业务模块使用相同的包结构：

```text
com.adtek.{module}
├── controller      XxxController        HTTP 入口，类级 @RequestMapping("/api/v1/{module}/...")，调用 Service，返回 Result
├── service         XxxService           用例接口（供本模块 controller；跨模块经 framework 端口）
│   └── impl        XxxServiceImpl       用例实现：权限、范围、事务、并发、审计（仅本模块）
├── mapper          XxxMapper            MyBatis-Plus Mapper 接口（仅本模块）
├── domain          XxxEntity            持久实体
├── dto             XxxCreateDTO / XxxUpdateDTO   写入参数
├── query           XxxQuery             查询过滤与分页
├── vo              XxxVO                返回视图
├── convert         XxxConvert           MapStruct 映射
└── constant        ErrorCodeConstants 等 模块常量与错误码
src/main/resources/mapper/{module}/XxxMapper.xml                     自定义 SQL（只访问本模块的表）
src/main/resources/db/migration/{module}/V{yyyyMMddHHmm}__{说明}.sql  本模块迁移（只建改本模块的表）
```

调用方向：`controller → service → service.impl → mapper → domain`。Controller 不依赖 mapper、domain 与 service.impl；domain 不依赖上层；dto/query/vo 不依赖 controller、service、mapper、domain。类名后缀与所在包必须一致；`service` 包只放以 `Service` 结尾的接口，`service.impl` 类以 `ServiceImpl` 结尾。以上规则均由 `ArchitectureTest` 强制。

### 新增业务模块

1. 复制 `backend/adtek-sample` 为 `backend/adtek-{业务}`，包名改为 `com.adtek.{业务}`，修改 `artifactId`。`adtek-sample` 本身保持为空骨架。
2. 在父 POM 的 `<modules>` 与 `<dependencyManagement>`、`adtek-server/pom.xml` 的依赖中登记新模块（登记后才会被打包和被边界门禁检查；漏登记由 `ModuleRegistrationTest` 报错）。
3. `@MapperScan("com.adtek.**.mapper")` 自动覆盖任意层级的 mapper 包。
4. 在模块 `constant` 包新增实现 `ErrorCode` 的枚举（如 `XxxErrorCode`），分配独立号段（common 1000、system 1001，业务模块从 1002 起），翻译键 `error.{module}.{name}` 同步写入三语字典（`ErrorCodeCatalogTest` 检查）；表名统一使用 `{module}_` 前缀，实体显式 `@TableName`；迁移放在本模块 `src/main/resources/db/migration/{module}/V{yyyyMMddHHmm}__{说明}.sql`（`DataOwnershipTest` 检查）。
5. 前端在与模块同名的 `src/features/{业务}/` 下新增 `routes.tsx`（路径 `/{业务}`）、`api.ts`、页面与 `locales/{zh-CN,en,vi}.json`；`App.tsx` 自动汇总，不需要修改。
6. 在 `.gitlab/CODEOWNERS` 为新模块与前端功能目录登记所有者。

## 前端

```text
frontend/
├── src/
│   ├── main.tsx              根渲染：StrictMode、QueryClientProvider、BrowserRouter
│   ├── app/                  装配层（只有它可以引用功能）
│   │   ├── App.tsx           应用外壳：Provider、布局，自动汇总各功能 routes.tsx
│   │   ├── queryClient.ts    TanStack Query 全局默认值（不自动重试）
│   │   └── featureBoundaries.test.ts  功能只用本功能或共享命名空间的文案
│   ├── features/{feature}/   （按需新增）一个业务功能的全部前端代码，与后端模块同名
│   │   ├── routes.tsx        导出 routes（路径必须位于 /{feature} 下，页面 lazy 加载）
│   │   ├── api.ts            本功能接口封装（经 src/api/client.ts，带 data 解析函数）
│   │   ├── pages/、components/、hooks/
│   │   └── locales/{zh-CN,en,vi}.json  本功能 i18n 命名空间（与目录同名）
│   ├── api/                  共享：client.ts（统一客户端与信封校验）、generated/schema.d.ts
│   ├── routing/              共享：功能路由契约与汇总校验
│   ├── components/           共享：（按需新增）跨功能复用组件
│   ├── stores/               共享：（按需新增）Zustand 最小会话状态
│   ├── i18n/                 共享：初始化、共享 translation 命名空间（含错误码文案）、三语一致性测试
│   └── styles.css
├── openapi/                  （按需新增）后端导出的 OpenAPI JSON
├── e2e/                      （按需新增）Playwright *.spec.ts
├── patches/                  依赖类型补丁
└── eslint / prettier / tsconfig / vite / vitest / playwright 配置
```

- 依赖方向（`eslint-plugin-boundaries` 强制）：`main.tsx → app → features / 共享`，`features/{a} → features/{a} 与共享`，`共享 → 共享`。功能之间不能互相引用，共享代码不能引用功能；多个功能都需要的代码上移到共享目录，跨功能的数据通过后端接口获取。`src/` 下新增的目录须先在 `eslint.config.js` 中分类，否则 lint 报未知文件。
- 功能页面放在 `src/features/{feature}/pages/XxxPage.tsx`，由本功能 `routes.tsx` 按路由 `lazy` 加载；`App.tsx` 通过 `import.meta.glob` 自动汇总，新增功能不修改 `App.tsx`。路由不在 `/{feature}` 下或重复注册时启动即报错。
- 每个功能的 API 调用集中在 `src/features/{feature}/api.ts`，通过 `client.ts` 的 `apiGet`/`apiPost` 并为 data 提供解析函数，使用生成类型并对响应做运行时校验；失败为 `ApiError`（`key`、`args`、`traceId`），页面以 `t(error.key, error.args)` 呈现。
- 文案：功能使用 `useTranslation('{feature}')` 读取本功能命名空间，共享文案与错误码文案在默认命名空间；不得读取其他功能的命名空间（`featureBoundaries.test.ts` 检查），每个命名空间三语键一致（`locales.test.ts` 检查）。
- 单元测试与被测文件同目录，命名 `*.test.ts`；浏览器测试放 `e2e/*.spec.ts`。
- `src/api/generated/` 为生成目录，不手工修改，不参与 lint/format。
