日期：2026-09-29。项目：adtek-platform-sn。承接用户“继续下一阶段”授权，完成 S2 在线操作日志与统一入口失败审计切片。完整 S2、F-23 和全量 SN 迁移仍未完成；没有生产发布、旧业务库写入或开发管理员密码重置。

## 本次实现

新增 `/api/v1/system/audits` 的列表、详情和筛选元数据三个只读接口，以及中文、英文、越文 React 页面。支持时间窗、工号、动作、模块、结果和服务器追踪号过滤；列表总数、日志编号及关系 ID 保持精确字符串。页面按已授权菜单发布，SELF 审计员可访问，不要求全局安全管理权限。

三个查询入口及分页 COUNT 均由精确 Mapper 策略在 SQL 层执行五类数据范围。V5 增加 actor_dept_id/actor_username 快照、HTTP 方法/路由模板/状态/错误码和索引；历史部门缺失继续为 NULL，不把当前部门冒充历史。详情重新投影已知 diff 字段，省略畸形、超限或未知结构并返回 redacted 提示，列表不读取原始 JSON。

安全过滤链新增入口失败捕获，覆盖当前同步 /api/ 请求的认证、CSRF、限流、方法权限、参数/JSON、业务拒绝和未处理异常；链外安全防火墙拒绝另以匿名主体记录。只有完成认证的 Actor 可作为主体；只保存受控方法、服务器模板、状态、错误码、traceId，不保存凭据、请求体或原始 URL。system 经 REQUIRES_NEW 追加，既有登录/管理失败在独立事务提交后标记已留痕，防止同请求重复记录。成功管理 diff 继续随业务事务提交。

追加审计时单独查询非秘密身份快照，避免 INSERT…SELECT 与外层账号锁形成等待。数据库无法写审计时保留原拒绝，认证、管理及入口审计的兜底日志均只输出追踪号和异常类型，不输出底层异常文本/SQL。此机制不保证数据库故障期间仍能持久留痕，也不把 HTTP 失败等同于业务回滚。
