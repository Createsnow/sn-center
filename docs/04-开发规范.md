# 开发规范 0.1.0

本规范是代码评审依据。架构与模块边界见[技术架构](01-技术架构.md)，包结构见[代码结构](03-代码结构.md)。

## 接口与契约

- 路径使用 `/api/v1/{module}/...`；查询用 GET，写命令用 POST（修改为 `/{id}/update` 等显式动作）。
- 统一 `Result` 信封：整数 `code`、翻译键、参数、`traceId`。成功 `code=0`；业务失败返回对应 HTTP 状态与错误码，不用 HTTP 200 表示失败。
- 业务 ID、数据库计数和版本在 JSON 中使用十进制字符串；只有有界页码/页大小使用 number。前端不从 number 恢复精确 ID。
- 每个模块分配独立的百万级错误码号段（如 `1004xxxxxx`），同步错误码目录测试、三语错误字典与生成契约。
- 契约以后端导出的 OpenAPI 为准：导出到 `frontend/openapi/`，执行 `pnpm api:generate` 生成 `src/api/generated/schema.d.ts`；不手写生成文件。
- `local` profile 开放 `/v3/api-docs`；项目实现安全配置（SecurityFilterChain）时须只在 local 放行该路径，否则默认安全链返回 401。
- 公开 Service 与端口的注释说明权限、事务、输入来源、失败与返回含义。

## 分层与对象

- Controller 只绑定参数并调用 Service；不访问 Mapper，不返回 Entity，不接收持久实体作为请求体。
- DTO 是写入参数，Query 是过滤条件，VO 是返回视图，Entity 是持久对象；MapStruct 显式映射，未映射目标字段编译报错。
- 业务模块之间只通过对方 `service` 接口或 framework 端口交互，不读取对方 Mapper/Entity。

## 身份、权限与数据范围

- 请求主体只从服务端会话解析的当前主体读取；禁止把客户端提交的权限、操作者、所有者作为授权依据。
- 权限在服务用例中检查；每个权限独立合并授权角色的范围，全局读角色不能扩大局部写权限。
- 数据范围（部门、指定部门、部门树、本人、全部）由服务端可信数据决定；列表与 total 使用相同范围；不可见的详情与不存在同样返回 404。
- 每条受范围约束的 Mapper 语句按准确 statement ID 登记表、部门列和所有者列；未登记的新语句默认拒绝。内部豁免必须写明调用路径和限制，不能整体豁免一个 Mapper。
- 可选的资源维度授权通过端口扩展，默认空集合并拒绝非空绑定。

## 写入、并发与事务

- 写用例使用 READ_COMMITTED 事务：先锁定当前主体授权，再取得业务锁；检查当前权限，再检查对象范围与版本。
- 安全配置修改与业务写入遵守相同的加锁顺序，协调锁持有到事务结束。
- 唯一性由数据库唯一约束保证；并发冲突返回 409，不静默覆盖。
- 编辑使用乐观锁：`WHERE id = ? AND version = ?` 并原子递增版本，影响 0 行返回 409。
- 服务端设置所属部门、创建人、更新人与版本，忽略请求中的同名字段。
- 写失败不自动重试。

## 数据库与 SQL

- MySQL 是最终状态。迁移文件 `V{n}__{说明}.sql` 发布后不可改写，只能追加新版本；禁止用 clean/baseline 掩盖校验和差异。
- SQL 一律参数绑定；不拼接客户端提供的列名或排序，排序字段使用白名单。分页大小有上限。
- 基础单表 CRUD 优先使用 MyBatis-Plus 已有方法；自定义 SQL 统一放在所属模块 `src/main/resources/mapper/*Mapper.xml`。
- Mapper 接口只保留方法、参数与必要的结果类型，禁止 SQL/结果映射注解与 SQL 字符串常量（`ArchitectureTest` 强制）。
- 自定义语句参数显式 `@Param`；实体参数统一命名 `entity`，XML 中使用 `#{entity.field}`，自增主键回填 `useGeneratedKeys="true" keyProperty="entity.id"`。
- XML `namespace` 等于接口全名，语句 `id` 等于方法名；重复投影用 `<sql>`/`<include>`，批量用 `<foreach>`，小于号写 `&lt;`。
- 不同权限用途的方法即使 SQL 相同也不合并（例如列表 `count` 与导出 `visibleCount`）。

## 审计、任务与文件

- 操作审计声明允许记录的字段，只记录受控的 before/after；不把整个 DTO 写入日志。新增审计字段时同步投影白名单与三语标签。
- 成功审计与业务同事务提交，审计失败回滚业务。
- 请求拒绝审计只登记路径模板，不保存动态 ID、查询串或请求体。
- 后台任务以持久 operation/task 执行，记录执行权、租约、attempt、终态与恢复；执行时重新检查当前主体和权限。
- 文件先生成完整快照再发布；下载时复核任务所有者与当前完整范围。

## 前端

- 只使用 React 函数组件与 hooks；TypeScript strict，禁止 `any`。
- 服务端状态由 TanStack Query 管理，query key 包含用户与授权版本；退出或身份变化时清理缓存。Zustand 只保存最小内存会话。
- 所有 API 使用生成类型，并对运行时 `unknown` 响应做校验。
- 页面明确呈现 pending、空、失败、冲突与成功状态；写失败不自动重试。
- 所有可见文案走 i18n，zh-CN、en、vi 三语同时维护（`locales.test.ts` 检查键与插值参数一致）。
- 禁止把访问令牌写入 localStorage/sessionStorage；敏感输入不进入日志、URL、网络 trace 或测试截图。

## 配置与秘密

- 无内置账号、默认密码或默认密钥；不引用相邻工程路径。
- 秘密只通过本地受保护文件（`deploy/.secrets/`，已忽略）或部署 Secret 注入，不打印、不提交。
- 运行账号只有 DML 权限，迁移账号单独持有 DDL 权限。
- 不安全 Cookie 只允许在本机 loopback 的 local / integration-test profile 使用；部署使用 TLS 与安全 Cookie。
- 日志按 traceId 关联，不记录密码、Cookie、Authorization、会话或完整数据转储。
