# 命令手册

## 生产订单全量同步配置

先按[接入说明](17-生产订单全量同步接入.md)在受保护文件中准备K3五字段，勿在命令行填写密钥。

```powershell
./tools/configure-k3.ps1 -JsonPath ./deploy/.secrets/k3-input.json
./tools/configure-k3.ps1
./tools/stop-test.ps1
./tools/start-test.ps1
# 容器已使用当前Compose配置时，单独重新加载API配置
./tools/container-test.ps1 restart-api
# 隔离合成配置测试，不连接ERP
./tools/verify-k3-configuration.ps1
```

配置工具不自动发起同步；重启后到“生产订单快照”点击“全量同步”。`configure-k3.ps1 -Disable`仅关闭下次启动的连接，原快照和凭据文件保留。

以下命令使用 **PowerShell 7**，工作目录为 adtek-platform-sn。当前执行状态见 reports；首次下载需要网络，系统安装需 UAC。

| 命令 | 前提与结果 | 副作用 |
| --- | --- | --- |
| ./tools/bootstrap-build.ps1 | Node 24/npm；得到已校验的 JDK21/Maven/pnpm | 下载到 .tools，固定 tools/build-tools.lock.json，不改系统 PATH |
| ./tools/install-docker.ps1 | Windows x64/虚拟化；安装 Docker Desktop/WSL | 当前用户安装、启用系统虚拟机平台；可能要求手动重启 |
| ./tools/infra.ps1 start | Docker Engine 就绪；两个服务健康 | 创建秘密、首次拉镜像及命名卷；不会清空旧卷 |
| ./tools/infra.ps1 status | Docker Engine 就绪 | 只读服务状态 |
| ./tools/infra.ps1 stop | 已有测试服务 | 停止本项目容器，保留卷 |
| ./tools/infra.ps1 check | Docker CLI 与配置所需文件 | 只校验 Compose 配置，不表示容器启动成功 |
| ./tools/check-infra.ps1 | 两个容器均已启动 | 真实 MySQL 认证查询、运行账号权限、Redis PING 及匿名拒绝检查 |
| ./tools/maven.ps1 -B -ntp verify | 构建工具和依赖源 | 编译、单元/架构测试、打包；此命令不运行 IT |
| ./tools/maven.ps1 -B -ntp -Pintegration verify | Docker Engine 就绪 | Failsafe 运行真实 MySQL/Redis 一次性容器；缺 Docker 报错 |
| ./tools/verify.ps1 | 构建工具和依赖源 | 构建并检查本次 Surefire XML，拒绝零发现/失败/跳过 |
| ./tools/verify.ps1 -Integration | Docker Engine 就绪 | 同时检查本次 Surefire 和 Failsafe XML |
| ./tools/start-test.ps1 | jar 已构建，测试 Compose 健康 | 前台 Java 服务；Ctrl+C 优雅停止，Flyway 首次初始化目标库 |
| ./tools/stop-test.ps1 | 本项目测试 Java 正在运行 | 仅终止命令行/JDK 路径均匹配本项目的进程；不用于生产或有在途业务的环境 |
| ./tools/bootstrap-admin.ps1 | 空测试库、构建完成、秘密文件已生成 | 一次性创建 admin，生成受保护初始密码文件；重复运行失败且不重置账号 |
| ./tools/pnpm.ps1 install --frozen-lockfile | Node 24、固定 pnpm、网络或已有缓存 | 按唯一锁文件安装前端和声明补丁 |
| ./tools/export-api.ps1 | 本机后端已启动 | 导出 OpenAPI 并重新生成 TS 类型；需要复核契约 diff |
| ./tools/verify-web.ps1 | 前端依赖已安装 | OpenAPI 漂移、lint、格式、单元、tsc strict、Vite 构建及非零发现门禁 |
| ./tools/start-web.ps1 | 前端依赖、API 已启动 | 前台 Vite，127.0.0.1:15173；同源代理 /api 到 18080，Ctrl+C 停止 |
| ./tools/verify-web.ps1 -Browser | 前后端已启动、Windows Edge、仍强制改密的测试账号 | 额外运行真实浏览器；只登录/刷新/注销，不修改密码或业务数据 |
| ./tools/verify-users-browser.ps1 | Docker、Node24、已安装前端依赖、Edge/Chromium | 启动一次性 MySQL/Redis、随机端口 Spring/Vite 和浏览器；实际增改启停/重置/改密，只修改一次性数据库；双报告非零发现门禁 |

健康检查地址：http://127.0.0.1:18080/actuator/health/readiness 。前端：http://127.0.0.1:15173 。本机 admin 已于 2026-09-29 15:48 完成首次改密，初始化密码文件中的旧值已失效，不要再次执行 bootstrap-admin。使用当前密码登录；自动化推荐独立账号运行器 tools/verify-users-browser.ps1。

浏览器 smoke 的默认前提是初始管理员尚未改密。若账号已正常使用，应设置 ADTEK_E2E_USERNAME / ADTEK_E2E_PASSWORD_FILE 指向另一个被要求首次改密的测试账号；不要为了测试重置既有管理员。浏览器依赖缺失或前提不满足会失败，不静默跳过。Linux 使用 Playwright Chromium，需自行安装对应测试浏览器；当前 CI 只执行前端静态与单元门禁，尚未运行浏览器。

启动脚本只读本项目 deploy/.secrets，加载 local profile、固定回环地址和 test schema，并设置 ADTEK_FILE_ROOT 为本项目 deploy/data/files；退出时恢复原进程环境。文件目录已忽略，须与数据库一并保留，不通过删目录处理下载失败。生产不能复用 local profile、HTTP Cookie 或关闭 TLS 的本机 JDBC 配置。

隔离浏览器验收通过 Maven browser profile 的 UsersBrowserE2E 启动，包含2项认证以及用户管理、配置管理、操作日志、持久导出、SN工厂、订单、规则、PI初始化、生成分配各1项完整流程，共11项，使用10个临时初始账号，不要求开发管理员仍为初始密码，不会读取其密码文件。运行器启用真实任务工作器，验证响应丢失后的原号查询、刷新与重复下载。测试结束关闭自己创建的 Node 子进程，Testcontainers 回收临时设施；查看 frontend/test-results/browser-users.json 和 tools/.runtime/users-browser-verify.log。Vite 的 ADTEK_API_TARGET 仅用于把临时前端代理到本机随机测试端口。构建前先停止本工程开发后端，完成后再启动。

V4 首次升级新增字典权限，V6 新增导出权限，均会递增既有平台角色账号的授权版本，使用当前密码重新登录即可；不需要重新初始化账号。V5 增加审计快照和入口失败字段/索引，不回填猜测历史。V1—V8 已应用并冻结，后续使用 V9+。用户、配置、操作日志和任务继续使用现有 MySQL/Redis；文件根目录、配额、工作器预算和恢复操作见[部署与运维](07-部署与运维.md)。

前一S2任务阶段联合回归使用 `./tools/maven.ps1 -B -ntp -Pintegration '-Dit.test=*IT,*E2E' '-Dfailsafe.failIfNoSpecifiedTests=false' verify`：明确选入49项IT及1项浏览器JUnit运行器。各模块可能没有匹配的IT，因此允许该模块无匹配；交付证据另严格检查整体48项单元、49项IT、1项运行器和6项浏览器，无零发现/失败/跳过。日常使用上表封装入口。

Maven 参数带点号时在 PowerShell 中整体加单引号，例如 `'-Dmaven=3.9.16'`，避免拆分为生命周期参数。常规构建无需重新生成 Wrapper。生产服务、数据导入和前端构建命令在对应实现完成后再登记。

## S3 联合验证

```powershell
./tools/maven.ps1 -B -ntp '-Pintegration,browser' '-Dit.test=*IT,*E2E' '-Dfailsafe.failIfNoSpecifiedTests=false' verify
./tools/verify-web.ps1
./tools/verify-users-browser.ps1
```

指定测试选项只让父POM/无测试模块不因未匹配而失败；交付仍核验全部预期XML、实际发现数和零跳过。浏览器脚本现严格要求11个流程，含SN工厂/订单/规则及S4初始化/生成分配；运行器启动独立HTTP ERP协议夹具，不读取开发admin密码或真实ERP。修改后端时先stop-test释放Windows jar，再构建、start-test、export-api；V1—V8已冻结，不可改写。

## S4 延续入口

沿用上述联合回归命令，当前套件包含48单元/架构、84真实IT、1个浏览器JUnit运行器；运行器执行11条Edge流程，使用10个临时初始账号。缺依赖或发现数不符均失败，不回退mock。前端门禁包含24单元及API漂移/lint/格式/strict/build；最终结果以S4报告为准。启动命令不变，新增S4资源/预演参数见[部署与运维](07-部署与运维.md#s4-测试启动配置)。

## S5 领取、打印和 MES

后端专项：`./tools/maven.ps1 -B -ntp '-Pintegration' '-Dit.test=SnAcquireIT' '-Dfailsafe.failIfNoSpecifiedTests=false' verify`。父聚合模块没有测试，实际S5测试必须发现15项且零跳过；此参数不免除报告计数检查。联合回归使用`'-Pintegration,browser' '-Dit.test=*IT,*E2E'`并检查各模块报告。

前端继续`./tools/verify-web.ps1`，隔离浏览器`./tools/verify-users-browser.ps1`现要求12条真实流程。MES工具`./tools/invoke-mes.ps1`的Items/Acquire/BatchId/TaskId/CallbackFile参数及稳定操作号示例见[12-MES契约](12-MES领取与打印契约.md)。工具不输出凭据，不自动换写意图。

## S6 回归与入口

既有`./tools/verify.ps1 -Integration`运行全部真实数据库回归；`./tools/verify-web.ps1`验证生成契约、lint、格式、前端单元和构建；`./tools/verify-users-browser.ps1`运行隔离真实浏览器并检查16个流程及最终数据库事实。缺Docker/浏览器不跳过。浏览器账号及随机密码仅在临时容器，真实管理员不重置。

新页面`/transfer`、`/query`、`/audit`、`/dashboard`按当前菜单权限显示；人员接口见[完整契约](13-转厂查询与痕迹契约.md)。本机重启仍使用stop-test/start-test、start-web；打包前停止本工程API以释放Windows JAR，不终止其他Java进程。

## S7 隔离容器、维护和恢复

以下均在工程根目录执行，PowerShell 7、Docker Engine、已构建的后端JAR和frontend/dist为前提。18443是独立测试HTTPS，18444是恢复演练；原开发18080/15173及数据卷不共用。

```powershell
./tools/container-test.ps1 build
./tools/container-test.ps1 start
./tools/container-test.ps1 status
# 只在独立容器空用户库首次执行；已有container_admin不得重置。
./tools/container-test.ps1 bootstrap
./tools/verify-backup-support.ps1
```

`container-test.ps1 stop`保留卷。自签证书只测试localhost，不安装系统信任根。账号初始/已改密秘密仅在deploy/.secrets/container-test；不要复制到报告。详细环境见[部署与运维](07-部署与运维.md)。

独立维护先显式注入ADTEK_MAINT_DB_URL/USER/PASSWORD/ALLOWED_SCHEMA，再运行`./tools/maintain.ps1 -Action PARTITIONS -Month 2026-09`查看计划。加`-RunId <UUID> -Apply`才执行；动作包含PARTITIONS、CLEAN_PREVIEWS、ARCHIVE_COPY、ARCHIVE_VERIFY、ARCHIVE_FINALIZE。最后一项还需ADTEK_MAINT_PROOF_ROOT及-ProofDirectory，见[维护契约](14-维护迁移与恢复契约.md)。不读取旧.env或借用Web运行密码。

```powershell
# 保存这些UUID，用同一号识别备份、恢复和终结操作；备份/恢复目标必须全新。
$backupRun=[Guid]::NewGuid().ToString()
$restoreRun=[Guid]::NewGuid().ToString()
./tools/backup-container.ps1 -RunId $backupRun
./tools/restore-container.ps1 -BackupRunId $backupRun -RestoreRunId $restoreRun
# 默认只核验；月必须已经结束且实际恢复证明包含该月在线/归档的相同内容。
./tools/finalize-container-archive.ps1 -BackupRunId $backupRun -RestoreRunId $restoreRun -Month 2026-08
```

备份会短暂停止独立测试Web/API，恢复创建新卷并占用18444；已存在目标或端口冲突会失败，不能删除卷解决。终结时显式`-RunId <UUID> -Apply`；永久归档保留。`verify-container-operations.ps1`仅核验报告对应的已完成合成夹具及运维权限，不作为任意生产库通用入口。

启用定时进程：`docker compose -f deploy/compose.container-test.yml --profile scheduled-maintenance up -d scheduler`；查看`logs scheduler`和`ps -a scheduler`，停止用`stop scheduler`。服务有专用维护密码，默认分区/预演清理、有限失败重试。配置变更先用`run --rm --no-deps scheduler --maintenance-scheduler --once`只读检查，再启用apply；不能把进程退出/日志当作外部告警已经送达。

## S7 旧库工具与专项回归

旧来源只读快照、暂存、主数据及有限 IMPORT 库存的参数、运行顺序和范围见[数据迁移契约](16-旧库快照暂存与主数据迁移.md)。四个 `legacy-*` 入口使用显式源/目标连接、固定快照 UUID 和迁移 UUID，后三个默认 dry-run。只操作独立目标；账号始终停用，结果不构成切换许可。

```powershell
./tools/maven.ps1 -B -ntp verify -Pintegration '-Dit.test=LegacySnapshotIT,LegacyStageIT,LegacyMasterIT,LegacyInventoryIT,LegacyCliIT' '-Dfailsafe.failIfNoSpecifiedTests=false'
./tools/maven.ps1 -B -ntp verify -Pintegration '-Dit.test=ProcessTaskRecoveryIT' '-Dfailsafe.failIfNoSpecifiedTests=false'
./tools/maven.ps1 -B -ntp verify -Pintegration '-Dit.test=SnWorkIT#capacityProfileAtOneTenAndOneHundredThousandPreservesAllLedgers' '-Dfailsafe.failIfNoSpecifiedTests=false'
```

强杀测试只启动并终止自己创建的两个打包应用进程，在一次性数据库用测试门闩固定提交前窗口；不强杀开发服务、不修改生产逻辑。容量测试以合成稳定来源执行 1000、10000、100000 三档生成、整单分配、查询和核对；耗时在运行通过后写入 `backend/adtek-server/target/sn-capacity-profile.json`。这两个 JSON 及库存容量 JSON 只有结合本次新鲜成功 XML 才能作为本次证据，旧文件不能证明重跑通过。

完整回归继续使用 `verify.ps1 -Integration`、`verify-web.ps1` 和 `verify-users-browser.ps1`，不同时启动两个 Maven；容量测量期间避免并行构建。上文各阶段发现数属于历史记录，当前结果以最新报告为准。
