## 统一格式化与检查

工作目录为`adtek-platform-sn`，使用PowerShell 7；先安装现有JDK21/Maven/pnpm和前端锁定依赖。首次PowerShell格式化还需网络访问PSGallery；模块仅下载到`.tools/powershell`。

```powershell
./tools/bootstrap-format.ps1
./tools/format.ps1
./tools/format.ps1 -Check
# 只处理后端Java和POM
./tools/format.ps1 -Scope Backend
# 仅检查PowerShell工具，不执行这些运维脚本
./tools/format.ps1 -Check -Scope PowerShell
```

`format.ps1`修改声明范围内的代码排版；`-Check`只检查，发现不一致返回失败。`-Scope`支持`All`、`Backend`、`Frontend`、`PowerShell`和`Configuration`，默认`All`。后端可直接运行`./tools/maven.ps1 -B -ntp spotless:apply checkstyle:check`或`spotless:check checkstyle:check`；Linux/macOS在`backend`中执行`sh ./mvnw spotless:check checkstyle:check`，在`frontend`中执行`pnpm format:check`。Maven普通编译/verify也会在validate阶段检查Java与POM格式，以及Mapper每行最多100字符。SQL长字符串需按字段/子句显式拆成常量拼接，格式器保留拆分，行宽检查发现超限会返回失败。工具版本和保护范围见[开发规范](../development/README.md)。

格式检查通过只代表排版符合规则。常规 Maven 默认打包会覆盖默认 JAR，运行中的开发 JVM 可能锁定它；先按维护安排正常停止该实例再构建。`verify.ps1` 和浏览器门禁使用独立 acceptance JAR，日常验收不覆盖正在使用的默认 JAR。

## 生产订单全量同步配置

先按[接入说明](K3订单同步.md)在受保护文件中准备K3五字段，勿在命令行填写密钥。

```powershell
./tools/configure-k3.ps1 -JsonPath ./deploy/.secrets/k3-input.json
./tools/configure-k3.ps1
./tools/stop-test.ps1
./tools/start-test.ps1
# 容器已使用当前Compose配置时，单独重新加载API配置
./tools/container-test.ps1 restart-api
# 隔离合成配置测试，不连接ERP
./tools/verify-k3-configuration.ps1
```

配置工具不自动发起同步；重启后到“生产订单快照”点击“全量同步”。`configure-k3.ps1 -Disable`仅关闭下次启动的连接，原快照和凭据文件保留。

浏览器 smoke 的默认前提是初始管理员尚未改密。若账号已正常使用，应设置 ADTEK_E2E_USERNAME / ADTEK_E2E_PASSWORD_FILE 指向另一个被要求首次改密的测试账号；不要为了测试重置既有管理员。浏览器依赖缺失或前提不满足会失败，不静默跳过。Linux 使用 Playwright Chromium，需自行安装对应测试浏览器；当前 CI 只执行前端静态与单元门禁，尚未运行浏览器。

## 当前联合验证

```powershell
./tools/verify.ps1 -Integration
./tools/verify-web.ps1
./tools/verify-users-browser.ps1
./tools/verify-k3-configuration.ps1
node ./tools/check-docs.mjs
```

隔离浏览器由 UsersBrowserE2E 启动一次性 MySQL/Redis、随机端口 Spring/Vite 和随机账号，当前严格要求 17 项 Edge 流程，覆盖认证、用户/系统配置、审计/导出及 SN 全链路。它启用真实工作器与回环合成 ERP，测试结束关闭自己的 Node 与临时容器，不读取已有管理员密码，不连接真实 ERP。结果见 frontend/test-results/browser-users.json。

verify 与浏览器脚本使用独立 acceptance JAR。默认 Maven JAR 用于日常开发启动，更新前需按维护安排正常停止对应实例；不要为验收停止相邻工程或既有容器。本轮常驻开发/HTTPS 库 V17 未变，当前源码 V19，升级说明见[部署与运维](部署与运维.md)。

Maven 带点号或逗号的参数在 PowerShell 中整体加单引号，例如 `'-Pintegration,acceptance'`。专项测试允许父聚合模块没有匹配用例，但交付仍必须核验整体发现数、当前时间、零失败和零跳过。不能把历史 XML 当作本次结果。

后端当前功能验收为 71 单元/架构、193 IT 最终覆盖，前端 46 项，浏览器 17 项；失败修复过程和最终受检版本见[本地交付](../releases/2026-10-04本地交付.md)。CI 未在远程运行，不把本地结果称为流水线通过。

MES 工具 invoke-mes.ps1 的参数、凭据边界和稳定操作号见[MES契约](../business/MES领取与打印契约.md)。工具不自动更换写意图；真实 MES 联调仍待完成。

## 隔离容器、维护和恢复

以下均在工程根目录执行，PowerShell 7、Docker Engine、已构建的后端JAR和frontend/dist为前提。18443是独立测试HTTPS，18444是恢复演练；原开发18080/15173及数据卷不共用。

```powershell
./tools/container-test.ps1 build
./tools/container-test.ps1 start
./tools/container-test.ps1 status
# 只在独立容器空用户库首次执行；已有container_admin不得重置。
./tools/container-test.ps1 bootstrap
./tools/verify-backup-support.ps1
```

`container-test.ps1 stop`保留卷。自签证书只测试localhost，不安装系统信任根。账号初始/已改密秘密仅在deploy/.secrets/container-test；不要复制到报告。详细环境见[部署与运维](部署与运维.md)。

独立维护先显式注入ADTEK_MAINT_DB_URL/USER/PASSWORD/ALLOWED_SCHEMA，再运行`./tools/maintain.ps1 -Action PARTITIONS -Month 2026-09`查看计划。加`-RunId <UUID> -Apply`才执行；动作包含PARTITIONS、CLEAN_PREVIEWS、ARCHIVE_COPY、ARCHIVE_VERIFY、ARCHIVE_FINALIZE。最后一项还需ADTEK_MAINT_PROOF_ROOT及-ProofDirectory，见[维护契约](维护与恢复.md)。不读取旧.env或借用Web运行密码。

```powershell
# 保存这些UUID，用同一号识别备份、恢复和终结操作；备份/恢复目标必须全新。
$backupRun=[Guid]::NewGuid().ToString()
$restoreRun=[Guid]::NewGuid().ToString()
./tools/backup-container.ps1 -RunId $backupRun
./tools/restore-container.ps1 -BackupRunId $backupRun -RestoreRunId $restoreRun
# 默认只核验；月必须已经结束且实际恢复证明包含该月在线/归档的相同内容。
./tools/finalize-container-archive.ps1 -BackupRunId $backupRun -RestoreRunId $restoreRun -Month 2026-08
```

备份会短暂停止独立测试Web/API，恢复创建新卷并占用18444；已存在目标或端口冲突会失败，不能删除卷解决。终结时显式`-RunId <UUID> -Apply`；永久归档保留。`verify-container-operations.ps1`仅核验报告对应的已完成合成夹具及运维权限，不作为任意生产库通用入口。

启用定时进程：`docker compose -f deploy/compose.container-test.yml --profile scheduled-maintenance up -d scheduler`；查看`logs scheduler`和`ps -a scheduler`，停止用`stop scheduler`。服务有专用维护密码，默认分区/预演清理、有限失败重试。配置变更先用`run --rm --no-deps scheduler --maintenance-scheduler --once`只读检查，再启用apply；不能把进程退出/日志当作外部告警已经送达。

## 旧库工具与专项回归

旧来源只读快照、暂存、主数据及有限 IMPORT 库存的参数、运行顺序和范围见[数据迁移契约](../archive/python-migration/docs/16-旧库快照暂存与主数据迁移.md)。四个 `legacy-*` 入口使用显式源/目标连接、固定快照 UUID 和迁移 UUID，后三个默认 dry-run。只操作独立目标；账号始终停用，结果不构成切换许可。

```powershell
./tools/maven.ps1 -B -ntp verify '-Pintegration,acceptance' '-Dit.test=LegacySnapshotIT,LegacyStageIT,LegacyMasterIT,LegacyInventoryIT,LegacyCliIT' '-Dfailsafe.failIfNoSpecifiedTests=false'
./tools/maven.ps1 -B -ntp verify '-Pintegration,acceptance' '-Dit.test=ProcessTaskRecoveryIT' '-Dfailsafe.failIfNoSpecifiedTests=false'
./tools/maven.ps1 -B -ntp verify '-Pintegration,acceptance' '-Dit.test=SnWorkIT#capacityProfileAtOneTenAndOneHundredThousandPreservesAllLedgers' '-Dfailsafe.failIfNoSpecifiedTests=false'
```

强杀测试只启动并终止自己创建的两个打包应用进程，在一次性数据库用测试门闩固定提交前窗口；不强杀开发服务、不修改生产逻辑。容量测试以合成稳定来源执行 1000、10000、100000 三档生成、整单分配、查询和核对；耗时在运行通过后写入 `backend/adtek-server/target/sn-capacity-profile.json`。这两个 JSON 及库存容量 JSON 只有结合本次新鲜成功 XML 才能作为本次证据，旧文件不能证明重跑通过。

本轮四个 legacy 脚本支持 `-JarPath` 显式选择验收产物；旧源版本白名单不自动随原型变化。历史转换本轮不适用。

完整回归继续使用 `verify.ps1 -Integration`、`verify-web.ps1` 和 `verify-users-browser.ps1`，不同时启动两个 Maven；容量测量期间避免并行构建。实际结果以当前发布记录为准，历史各阶段数量不代表当前发现数。
