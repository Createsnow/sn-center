# SN 环境、升级与运行

此前已交付版本到 V19；当前工作区一致性改造新增 V20—V26，仅在 2026-10-08 隔离比较库应用，V26 保存生成分配的提交工号，见[本阶段记录](../testing/2026-10-08一致性第七阶段.md)。本轮未升级或重启既有开发库和独立 HTTPS 库，它们仍是 V17，恢复演练实例保留原受检版本。查看运行产物和数据库迁移记录后才能判断实际版本，不能从源码版本推定已经部署。

## 启动和升级

首次新环境按[命令手册](命令手册.md)安装锁定工具、冻结依赖、构建默认 JAR、启动设施和检查，再只对空用户库执行 bootstrap。已有管理员继续用当前密码，普通启动不重置账号。

`start-test.ps1` 启动默认 JAR，Flyway 校验并应用其中的完整迁移链。V18 默认关闭定时设置，V19 从最近成功生成记录回填 PI 规则选择；失败与待执行作业不参与。V17→V19 已在隔离测试验证，不代表常驻库已经执行。

更新已有运行环境前先记录当前版本与镜像，核对在途作业、数据库与文件备份及恢复依据，再安排停止对应 API、构建、迁移、启动、健康/业务检查。不得删卷、清库或修改 V1—V19 迎合升级。默认 Maven 打包可能被 Windows 中的运行 JAR 锁定；日常验收使用独立 acceptance JAR，部署产物另行构建。

独立 HTTPS 构建/启动用 `container-test.ps1 build/start`，结构迁移由独立 migrate 进程执行，API 不挂载 DDL 密码。API/Web 非 root、只读根目录，文件挂持久卷。该命令会改变对应测试环境，不能在只做源码验证时顺手更新常驻实例。

## 任务、文件与恢复

文件根目录包含 objects、parts、quarantine；SQL 状态、固定快照和文件须一致备份，不能删除被任务引用的文件。多实例需共享可靠持久文件目录。普通任务默认最多 3 次/300 秒、租约 30 秒、执行事务 30 秒；V30 的 PI_INIT 执行与总截止预算例外见下文；资源阈值详见配置与业务契约。

停止时先停止领取并等待在途事务；HTTP 中断或进度不证明业务回滚。未知结果先查原操作，同意图沿用原号。已成功业务的文件失败通过原任务恢复，不重做打印或生成。

备份/恢复/审计归档终结仍按[维护与恢复](维护与恢复.md)执行。现有工具只面向独立 container-test 环境；备份会短暂停 Web/API，恢复用新卷及备份绑定镜像，原始 SQL 和文件包保存在 ACL 保护目录，不进入报告。恢复后 Redis 会话不恢复，须重新登录。生产异地备份、RTO 和多主机故障尚未验收。

## K3、调度与故障定位

新启动只读取本工程受保护配置，不自动读取 Python 配置。K3 配置导入、禁用和重新加载见 [K3订单同步](K3订单同步.md)。没有配置时请求明确失败，不注入演示订单。定时全量开关默认关闭；保存者身份、权限及执行权每次重验。

健康入口 `/actuator/health/readiness` 的 UP 只代表应用/MySQL/Redis，不包含磁盘容量、ERP 可用性或业务验收。故障按 traceId、原操作号、持久状态和日志定位，不输出密码/token，不手改水位、额度、护栏或任务成功状态。生产告警、容量、TLS、备份与切换条件见[当前待办](../releases/待办与验收边界.md)。

## 本机比较环境的 V27 生成执行

2026-10-08 独立比较库已应用 V27，仅增加生成业务失败参数列；旧开发和 HTTPS 环境保持既有版本。`ADTEK_SN_INLINE_GENERATION_QUANTITY` 默认 5000，与原型小批量同步反馈一致。集成测试将其置 0 以手动注入队列故障，专门的同步测试会启用该值；不要将测试用 0 当作页面一致性环境的启动默认值。

同步生成也先登记持久任务再执行，失败任务须保留；不能因 HTTP 4xx 判断“没有作业”。预演使用/过期/自有流水变化的前置拒绝才不创建作业。重启前核对在途任务和实例 PID，停止对应 acceptance JAR 的 JVM 后再打包；未触碰其他常驻环境。

## V28 升级检查

V28 新增整单历史生成身份，不修改原有流水、SN、累计或任务。升级前核对在途生成/分配、保存数据库和文件备份、停止对应应用；升级后检查 `SELECT bill_id, first_pi FROM sn_bill_generation WHERE first_customer IS NULL`。结果非空表示首次客户缺少唯一可信成功审计，相关分配会拒绝，需先从可信历史资料核实，不能拿当前 ERP 客户批量填充。

回填同时读取在线与归档成功审计；相关审计和操作关联不能在升级前删除。旧库迁移工具仍遵守原来源/目标版本白名单，本次 V28 不表示已支持新的历史库存导入。仅独立比较环境按阶段记录升级，其他常驻库不随源码验证自动升级。

## V29 升级检查

V29 只重建 `sn_item.ix_sn_item_pending`，使相同流水按生成时间选取。升级前停止接受新的生成/分配，确认在途任务已经结束，再备份并停止对应应用；不要在旧排序下已固定成员的分配任务尚未完成时切换。表规模较大时应提前评估索引重建时间和磁盘余量。

升级后确认 Flyway 为 V29，索引列序为 `bill_id,status,seq_dec,created_at,id`，并核对原 SN、护栏、额度、历史分配和账号未变。验证改 PI 后重叠流水的首批与余量分配；无需重写已有业务行或重置账号。仅本机独立比较环境执行本次升级，原开发及 HTTPS 库保持原状。

## V30 初始化容量与升级检查

新增配置 `ADTEK_SN_MAX_IMPORT_QUANTITY=500000`（范围 1—1000000）和 `ADTEK_SN_IMPORT_EXECUTION_SECONDS=600`（范围 30—3540 秒）。原生成数量上限不变；旧的初始化 8 MiB 内联载荷限制被固定输入分块取代。任务登记事务仍为 30 秒，浏览器提交等待 60 秒；登记完成后执行事务默认 600 秒，总截止预算至少 660 秒，非初始化任务保持原预算。调大数量或时间前需要重新验证内存、磁盘、事务与并发容量。

升级前备份 SQL 与文件并等待在途任务结束，保留未结束任务引用的数据。V30 增加 `sn_import_chunk`，无需改写旧内联载荷；升级后核对 Flyway 版本、原业务与账号摘要，并验证大文件上传、超过数量上限、缺块/摘要不符的整批回滚及旧内联任务执行。输入块跟随所属 `sn_work` 生命周期，不得单独清理仍被引用的块。

同步部署新的 Nginx 配置：初始化精确路径的请求体上限为 160 MiB，发送超时 120 秒，读取超时 480 秒，其他 API 保留 16 MiB。代理需要足够的请求临时目录空间；HTTPS 大文件验证必须走真实代理，不能只以 Vite 直连结果代替。比较测试专属代理为 `https://127.0.0.1:18443`，使用独立短期测试证书，不能当作正式部署证书。

本次仅升级 MySQL 33308 的独立 Java 比较库，原开发/HTTPS 库和 Python 原型不变。V30 已应用后保持原字节，后续变更从 V31 起。
