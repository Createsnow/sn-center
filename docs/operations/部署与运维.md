# SN 环境、升级与运行

当前源码交付到 V19；本轮未升级或重启既有开发库和独立 HTTPS 库，它们仍是 V17，恢复演练实例保留原受检版本。查看运行产物和数据库迁移记录后才能判断实际版本，不能从源码版本推定已经部署。

## 本机隔离环境

| 环境 | 入口 | 数据与凭据 |
| --- | --- | --- |
| 开发 | Web 15173 / API 18080 / MySQL 33306 / Redis 36379，均回环 | compose.test.yml；本工程 deploy/.secrets 与 deploy/data/files |
| 独立 HTTPS | https://127.0.0.1:18443 | compose.container-test.yml；独立卷、自签测试证书和账号 |
| 恢复演练 | https://127.0.0.1:18444 | 独立恢复卷与备份绑定镜像，不自动跟随新构建 |
| 自动化验收 | Testcontainers 随机端口 | 一次性 MySQL/Redis、新账号、新合成业务，不读上述业务库 |

固定镜像 MySQL 8.4.11 / Redis 8.4.7-alpine，摘要见 [images.lock.json](../../deploy/images.lock.json)。运行账号仅 DML，Flyway 用迁移账号。秘密首次由 infra 生成，ACL 限当前 Windows 用户和 SYSTEM。已有卷必须保留匹配凭据，重新生成文件不会修改库内密码。`infra stop` 保留卷。

## 启动和升级

首次新环境按[命令手册](命令手册.md)安装锁定工具、冻结依赖、构建默认 JAR、启动设施和检查，再只对空用户库执行 bootstrap。已有管理员继续用当前密码，普通启动不重置账号。

`start-test.ps1` 启动默认 JAR，Flyway 校验并应用其中的完整迁移链。V18 默认关闭定时设置，V19 从最近成功生成记录回填 PI 规则选择；失败与待执行作业不参与。V17→V19 已在隔离测试验证，不代表常驻库已经执行。

更新已有运行环境前先记录当前版本与镜像，核对在途作业、数据库与文件备份及恢复依据，再安排停止对应 API、构建、迁移、启动、健康/业务检查。不得删卷、清库或修改 V1—V19 迎合升级。默认 Maven 打包可能被 Windows 中的运行 JAR 锁定；日常验收使用独立 acceptance JAR，部署产物另行构建。

独立 HTTPS 构建/启动用 `container-test.ps1 build/start`，结构迁移由独立 migrate 进程执行，API 不挂载 DDL 密码。API/Web 非 root、只读根目录，文件挂持久卷。该命令会改变对应测试环境，不能在只做源码验证时顺手更新常驻实例。

## 任务、文件与恢复

文件根目录包含 objects、parts、quarantine；SQL 状态、固定快照和文件须一致备份，不能删除被任务引用的文件。多实例需共享可靠持久文件目录。默认任务最多 3 次/300 秒、租约 30 秒、执行事务 30 秒；资源阈值详见配置与业务契约。

停止时先停止领取并等待在途事务；HTTP 中断或进度不证明业务回滚。未知结果先查原操作，同意图沿用原号。已成功业务的文件失败通过原任务恢复，不重做打印或生成。

备份/恢复/审计归档终结仍按[维护与恢复](维护与恢复.md)执行。现有工具只面向独立 container-test 环境；备份会短暂停 Web/API，恢复用新卷及备份绑定镜像，原始 SQL 和文件包保存在 ACL 保护目录，不进入报告。恢复后 Redis 会话不恢复，须重新登录。生产异地备份、RTO 和多主机故障尚未验收。

## K3、调度与故障定位

新启动只读取本工程受保护配置，不自动读取 Python 配置。K3 配置导入、禁用和重新加载见 [K3订单同步](K3订单同步.md)。没有配置时请求明确失败，不注入演示订单。定时全量开关默认关闭；保存者身份、权限及执行权每次重验。

健康入口 `/actuator/health/readiness` 的 UP 只代表应用/MySQL/Redis，不包含磁盘容量、ERP 可用性或业务验收。故障按 traceId、原操作号、持久状态和日志定位，不输出密码/token，不手改水位、额度、护栏或任务成功状态。生产告警、容量、TLS、备份与切换条件见[当前待办](../releases/待办与验收边界.md)。
