## 3. 按角色的阅读顺序

- **业务方 / 新成员**：业务流程说明 → 需求文档（PRD）。
- **评审**：需求文档（PRD）→ 系统技术方案。
- **开发**：README → 需求文档（PRD）→ 系统技术方案 → 建表脚本 `V1__init.sql` → MES 对接说明。
- **运维 / 实施**：运维手册 → 系统技术方案附录。
- **MES 对接方**：只需要 MES 对接说明。

## 4. 写作约定

- **术语**：统一用「生产组织」（不再用「工厂 / 厂区」）；写操作的记录统一叫「操作痕迹」（表 `sn_audit`）；角色为「系统管理员（总部）/ 生产组织操作员 / 查询员 / MES 接口账户」；号的六个状态为「待分配 / 待推送 / 已推送 / 待领取 / 已领取 / 转组织申请中」，另有「暂停交付」标记。
- **单一来源**：配置项、表字段、接口字段只在权威文档里写全，其他文档写一句话加链接，不复制表格。
- **以代码为准**：文中的参数、默认值、错误码都应能在代码里找到；改代码时按下表同步文档，并更新文首的更新日期。

## 5. 改代码时要同步的文档

| 改了什么 | 需要同步 |
| --- | --- |
| 建表脚本 / 新增迁移 | 运维手册 8.1–8.3 里的表数量（现为 33 张 `sn_` 表）；涉及 ER 时更新系统技术方案的图 |
| 新增 / 修改页面接口 | 路由的 `summary`（在线文档 `/docs` 随之更新）；涉及权限或流程时同步系统技术方案第三章 |
| 修改 MES 接口 | MES 对接说明（须与 MES 方书面确认） |
| 新增配置项 | `.env.example`；部署时必须填写的再加到运维手册 §2 |
| 新增错误码 | `frontend/scripts/error_messages.py` 后运行 `gen_locales.py`；MES 接口会返回的另见 MES 对接说明 |
| 新增页面词条 | `frontend/scripts/ui_messages.py`（公共）或 `frontend/scripts/ui/<页面>.py`，再运行 `gen_locales.py` |
| 痕迹动作 | 前端 `constants.ts` 的 `AUDIT_ACTIONS` 与 `actions.*` 词条 |
| 业务口径变化 | 需求文档（PRD）→ 业务流程说明 → 系统技术方案 |

`系统技术方案.md` 改动后重新生成 Word 版（仓库根目录）：

```bash
uv run --with pypandoc_binary --with python-docx --with pillow --with pymupdf python docs/build_tech_docx.py
```

装有 LibreOffice 时目录带页码，否则只有标题。图的源文件是 `images/系统技术方案/*.mmd`（Mermaid），改完后用 mermaid-cli 导出同名 PNG、SVG（白底，与现有图同样的宽度和倍率；无界面服务器上 mermaid-cli 用无头 Chromium）：

```bash
cd docs/images/系统技术方案
npx -y @mermaid-js/mermaid-cli@11.4.2 -i fig2-1-function.mmd -o fig2-1-function.png -s 2 -w 1600 -b white
npx -y @mermaid-js/mermaid-cli@11.4.2 -i fig2-1-function.mmd -o fig2-1-function.svg -w 1600 -b white
```
