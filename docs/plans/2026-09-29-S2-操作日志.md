# S2 操作日志与入口失败审计切片

承接用户“继续下一阶段”授权，在三份冻结 v1.1 基线下实施 F-23 的在线日志部分。仅修改新工程，复用既有 MySQL/Redis；旧工程、账号密码和历史来源文档保持不变。

## 实施内容

- V5 追加审计工号/部门快照和 HTTP 失败元数据、查询索引；不推测回填旧日志部门。
- 列表、详情、筛选元数据和分页 COUNT 都通过同一 system:audit:list SQL 数据范围规则；未知规则失败关闭。
- 成功审计继续同事务，失败独立事务；HTTP 鉴权/CSRF/限流/参数/防火墙拒绝补充留痕，以独立事务提交成功标记避免重复。
- 主体仅取可信 Actor，路由使用服务器白名单模板；不存凭据或请求内容。历史 diff 读取时再次白名单投影。
- OpenAPI 类型、运行时守卫、精确 ID、三语只读 React 页及移动布局。
- 真实隔离 HTTP/MySQL/Redis、前端单元和 Edge 浏览器回归，同时验证此前认证/用户/配置切片。

## 退出条件与接续

必须验证五类范围及空自定义范围、匿名/历史记录、越范围404、大 ID、过滤绑定、历史秘密省略、入口主体可信、失败去重、审计不可写保留原拒绝，以及真实页面查询与三语切换。结果分别记录发现/失败/错误/跳过数，不用编译代替运行。

列表默认7天，单次时间窗口31天、每页至多100、页号至多10000；元数据每类200项，超限明确拒绝。当前不包含导出、归档、SN 业务审计、应用外拒绝、防篡改或性能验收。数据库故障时不能保证失败日志落库；人工 Security/SQL/权限重点审查仍待执行。

接续 S2 持久操作号/幂等、任务租约与文件恢复，然后 S3 工厂/ERP 订单/规则。F-23 和全量迁移均不因本切片自动化通过而关闭。
