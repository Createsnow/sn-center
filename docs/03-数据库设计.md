# 当前数据库设计

目标为独立 MySQL 8.4 schema adtek_sn_test。默认 utf8mb4 / utf8mb4_0900_as_cs，连接与持久时间为 UTC，时间字段 DATETIME(6)。内部身份使用有符号 BIGINT，自增用户/角色/部门 ID；JSON 统一字符串。用户名 ASCII 工号、区分大小写，不规范化后再比较。

| 表 | 当前用途与约束 |
| --- | --- |
| sys_user | username 唯一；停用保留身份；password_hash、must_change_password、security_version、language |
| sys_role | role_code 唯一；data_scope=1—5 的 CHECK；factory_scope=1 指定工厂/2 全工厂 |
| sys_dept | parent_id 组织树；enabled；递归 CTE 在一致快照中展开已启用下级 |
| sys_menu | M/C/F CHECK；permission_code 唯一；route_path、component_key |
| sys_user_role / sys_role_menu / sys_role_dept | 关联复合主键，当前初始化与认证读取使用 |
| sys_user_factory | V2历史关系，V7复制到sn_user_factory；保留旧表但运行时不再读写 |
| sys_security_control | 固定控制行串行化初始化、用户与全局配置管理；id=1 不是用户超级权限判断 |
| sys_dict_type | code 唯一且创建后不可变；name/enabled/version；停用保留值与引用 |
| sys_dict_item | type_id/value 联合唯一且不可变；label_zh/label_en/label_vi、sort_order/enabled/version |
| sys_oper_log | 账号/管理/入口失败审计；主体及部门/工号快照、模块/类型/动作/对象/结果/JSON diff/traceId/UTC 时间；入口失败另存 HTTP 方法、路由模板、状态及受控错误码 |

DataScopeType 对应 1=全部、2=自定义部门、3=本部门、4=本部门及下级、5=仅本人。未知编码拒绝。部门与生产工厂独立，不加无隔离能力的 tenant_id。当前关联没有数据库外键；管理 Service 在协调事务中验证关系、拒绝循环与无效父节点并维护版本，不开放通用 BaseMapper 接口。部门祖先由 parent_id 递归推导，不另存易失配的 ancestors 字符串。自定义授权只装配启用部门；移动部门重算树范围。存在启用子节点或启用用户的部门不能停用，存在启用子节点的菜单不能停用。

V1__system_foundation.sql 创建基础表。V2__identity_authorization_and_audit.sql 新增语言、工厂范围、审计与初始化控制，种入角色/权限而不种账号。V3__user_management_audit.sql 新增 module_name/business_type 和用户部门分页索引。V4__system_configuration.sql 增加配置版本、菜单自增、字典及权限。V5__audit_query_and_request_failures.sql 增加审计快照、HTTP 元数据及索引。V6__durable_operations_tasks_and_files.sql 增加持久操作/任务/文件和审计导出快照，种入 system:audit:export 并递增既有平台角色账号 security_version。V7增加SN业务基础，详见下节。V1—V8已应用并冻结，后续增加V9+，禁止清库重跑冒充升级。

V5 的 actor_dept_id、actor_username 为追加时的身份快照；原有日志保持 NULL，不伪造历史部门。HTTP 方法/模板/状态/错误码同样可空，已有业务审计不补造 HTTP 字段。匿名或身份尚未验证的入口拒绝不记录来访者提供的账号、令牌或工号。应用仅开放查询接口，不开放审计编辑/删除；当前运行账号权限仍为既有 DML，不宣称数据库具备防篡改或归档完整性保证。

默认角色包括 PLATFORM_ADMIN、SN_HQ、FACTORY_OPERATOR、SN_QUERY_ALL、SN_QUERY_FACTORY。用户及独立角色/菜单/部门维护已实现；角色编码、菜单类型/权限标识及字典编码/值不允许原地改写。共享角色可编辑五类范围和自定义部门集合；授予权限需操作者拥有该权限的 ALL 部门范围，工厂范围另行比较。初始管理员通过受控命令关联角色，不依赖固定用户 ID 授权。工厂业务用例和资格端口已由S3实现；用户页通过资格端口校验显式绑定，不能接受越权工厂ID。

## V6 设施与首个消费者

| 表 / 归属 | 约束与恢复依据 |
| --- | --- |
| sys_operation_control / framework | 固定容量协调行；只串行提交/恢复准入，不与system身份控制行混用 |
| sys_operation / framework | USER主体+动作+operation_id复合唯一；规范化版本、输入/范围摘要；PENDING/SUCCEEDED/FAILED/CANCELLED，任务/原结果引用 |
| sys_task / framework | UUID任务ID；输入JSON/摘要、提交主体/授权版本、owner/代次/租约、尝试/期限、结果/错误；QUEUED/RUNNING/RETRY_WAIT/SUCCESS/FAILED/CANCELLED |
| sys_task_progress / framework | task_id唯一、代次/数量/阶段；独立事务，不建阻塞任务控制行的父外键；非最终提交事实 |
| sys_file / framework | 不可变UUID、唯一任务与服务器存储键、摘要/字节数/固定行数；PREPARING/READY/RECOVERING/FAILED；业务与范围经task引用固定快照 |
| sys_audit_export_row / system | task_id+ordinal主键；连续固定序号、事件主体/部门、已转义CSV行；无原始changes/凭据；禁止应用层修改成员 |

设施 UUID 用 ascii_bin 精确存储，HTTP 为字符串；账号仍为 BIGINT，数量和执行代次在 JSON 仍为精确字符串。框架不依赖 sys_user 的外键或查询。文件恢复不改 operation 的已提交成功结果；FAILED 初始操作保留终态，新业务意图使用新号，文件恢复仅对已成功操作开放有界新周期。字段数据来源与HTTP语义见接口契约。

SN 双唯一护栏/月分区明细由V8实现，稳定来源/额度由V7和V8实现；月分区审计、领取批次和转厂历史待后续。后续必须以迁移方案 INV/T 约束建模，不将已实现的通用任务设施当作完整 SN 业务模型。

## V17 ERP精确计划量

`sn_order_entry.qty`和`sn_order_bill.total_qty`无损扩展为DECIMAL(23,4)，保留非负和long上界约束。`sn_order_bill.quantity_ready`表示所有有效分录均为整数；小数分录即使合计为整数也为false。旧整数自动保持true。SN计数、来源历史额度、流水和固定成员均不改为小数；Java用BigDecimal解析/存取，输出普通十进制字符串，禁止隐式截断。超出4位有效小数在SQL前拒绝。暂存/主数据/有限库存工具增加对17的精确版本识别，转换范围不扩大。
