## S7 独立容器测试与恢复环境

`tools/container-test.ps1 build/start`构建启动独立HTTPS环境，入口https://127.0.0.1:18443。配置为deploy/compose.container-test.yml，仅Web端口绑定loopback；MySQL、Redis和API只在容器网络。原开发33306/36379/18080/15173及卷保持独立。初次启动生成本机测试秘密和90日自签TLS证书，浏览器需接受该测试证书，不安装系统信任根。独立账号container_admin已完成首次改密，其当前测试密码保存在受限deploy/.secrets/container-test/container-admin-current-password；原开发admin未变。

API与Web非root/只读根目录，文件有独立持久卷；DDL由migrate单次进程执行，API不挂载迁移密码。Maintenance和scheduler使用专用维护账号。stop保留卷，更新前完成备份与在途任务核对。scheduler通过scheduled-maintenance profile显式启用，失败最多重试3次；当前仅交付日志/退出状态，外部告警需环境接入。

备份与恢复工具只面向这个测试项目，命令见[命令手册](10-命令手册.md#s7-隔离容器维护和恢复)。恢复进入全新卷并固定备份对应镜像，入口https://127.0.0.1:18444；原始SQL、tar、证明位于deploy/data/backups并受ACL限制。恢复校验成功后保留新环境供检查，失败目标也保留诊断，不自动删卷。SQL与文件须一起保存，Redis会话不恢复。该本机目录不能代替生产异地备份或生产RTO验收。

## 设施与隔离

| 服务 | 固定镜像 | 宿主地址 | 用途 |
| --- | --- | --- | --- |
| MySQL | mysql:8.4.11 | 127.0.0.1:33306 | 独立 adtek_sn_test schema |
| Redis | redis:8.4.7-alpine | 127.0.0.1:36379 | 会话/缓存的测试设施 |
| Java | 本工程 JDK 21 | 127.0.0.1:18080 | 健康检查、认证 API；业务默认需 Bearer |
| React / Vite | frontend/pnpm-lock.yaml | 127.0.0.1:15173 | 登录、首次改密与本人设置；/api 同源代理 |

Compose 项目名 adtek-platform-sn-test，数据库和 Redis 各自使用命名卷。容器 restart 为 unless-stopped；Windows 登录后需 Docker 引擎运行才能启动容器。

密码由 tools/infra.ps1 start 首次生成，保存 deploy/.secrets；ACL 授权当前 Windows 用户和 SYSTEM。脚本不打印秘密。凭据文件和已有卷必须一起保留；删除凭据后重建文件不会自动修改已有数据库密码。

运行用户 adtek_app 只有该 schema 的 SELECT/INSERT/UPDATE/DELETE。Flyway 使用 adtek_migration 的 schema DDL 权限。root 只用于初始化与设施诊断。Redis 开启密码、AOF、noeviction，256 MB 上限。端口不暴露局域网。

MySQL 表默认 utf8mb4_0900_as_cs；SN 双护栏需要在业务迁移中按精确字节语义单独定义，不能用此默认替代设计审查。时间统一 UTC。当前测试 JDBC 关闭 TLS 仅限本机隔离端口；生产必须单独配置 TLS。

## 安装和恢复边界

tools/install-docker.ps1 从 Docker 官方下载 Windows x64 安装包，验证有效 Docker Authenticode 签名，然后申请 UAC 启用 WSL 虚拟机平台，安装当前用户 Docker Desktop。不安装额外 Ubuntu，不修改旧数据库，不触发重启。

如果 WSL 返回 restartNeeded，用户完成 Windows 重启后再启动 Docker Desktop，执行 tools/infra.ps1 start。安装事实记录在 tools/.runtime/docker-install-result.json；该记录可能仍保留首次安装时的重启标记，实际就绪以 docker info 为准。

stop 只停止容器，不删卷；不提供自动清空入口。升级固定镜像应另行备份、迁移演练并记录摘要，不能修改已有 Flyway 脚本。

已实际拉取的镜像摘要记录在 [deploy/images.lock.json](../deploy/images.lock.json)，Compose 使用固定补丁标签；重新拉取或升级后需对照摘要，不能将标签不变当作镜像未变。

V1 已于 2026-09-29 14:10 应用，V2 于 14:51 应用，后续只能新增迁移。V2 初始化角色/菜单和控制行，不带默认账号；tools/bootstrap-admin.ps1 在独立事务中锁定控制行并创建初始账号/角色/审计，重复执行拒绝。普通启动不创建或重置管理员。

S2 配置升级 V4 新增字典权限；审计升级 V5 增加快照/HTTP字段；任务升级 V6 增加设施/固定导出快照及 system:audit:export。V4/V6 递增既有平台角色账号的授权版本，使用当前密码重新登录即可，不重置密码。现有用户/持久卷/历史日志保留；V1—V8冻结，后续使用V9+。角色/菜单/部门修改也可能使会话失效，这是版本撤销的预期行为。

操作日志使用既有 MySQL，无新增服务或密钥。入口审计数据库故障告警仅含服务器 traceId 和异常类型，保留原请求拒绝；告警发生意味着不能保证该次留痕已落库。尚未提供跨库缓冲重放、归档、防篡改、保留期清理或大数据量查询性能验收，不能据页面可用宣称这些运维能力已具备。

## 持久任务和文件运行

无需新增消息队列。测试脚本配置 ADTEK_FILE_ROOT 为本工程 deploy/data/files，已忽略Git；普通启动不清理产物。实际目录由文件设施按需创建，objects存不可变产物、parts存临时文件、quarantine保留损坏原件。不得手工删仍被任务/恢复引用的文件或数据库快照。生产部署必须显式指定持久目录、限制OS访问权限、纳入数据库与文件一致备份；多实例必须共享同一可靠文件目录，不能使用各容器临时层。

当前 adtek.tasks 参数：enabled=true、max-attempts=3、lease-seconds=30、budget-seconds=300、retry-seconds=3、per-user-limit=3、queue-limit=1000、export-rows=10000、file-bytes=16777216。路径通过file-root配置。调整边界应同时复核页面容量文案和前端下载上限；不能仅调后端导致前端静默失败。集成测试默认关闭自动工作器、独立target/task-files随机目录；浏览器运行器显式开启自动扫描。

启动即扫描可领取任务；执行持任务行锁，租约过期不会强行抢占正在提交的旧事务。关机时停止领取并等待在途任务20秒，之后中断并再等5秒；不能据中断标记“业务已撤销”。测试stop-test是进程停止工具，不作为生产任务安全关机保证。真实kill/断电、网络分区及多主机恢复仍待演练。

排查先查原操作/任务，不改号重放写命令。初始任务业务失败或预算耗尽保留FAILED；参数修正后创建新意图。已成功操作的文件丢失/损坏在下载前检测为RECOVERING，页面“恢复同一文件”从固定快照重建；如原摘要不一致，保护原产物并失败，需排查快照完整性。不要重做原业务操作。已发布但DB未READY可由原任务接管校验复用；同任务恢复清理其残留part，不提供全目录保留期删除。

当前只记录有限异常类型/traceId与持久错误码，未建立任务积压、磁盘容量、长期锁等待的监控阈值和告警；运维上线前须补齐这些指标、备份恢复及容量压测。没有磁盘健康探针，API readiness的UP只涵盖应用/MySQL/Redis。

jwt-signing-key 为本机单独的随机密钥；不是数据库密码或 Redis 密码。刷新 Cookie 的默认策略是 HttpOnly / Secure / SameSite=Strict。local profile 允许 HTTP，但启动校验要求 server.address 为回环地址；生产默认 Secure=true。修改 JWT 密钥使原 access token 失效，不等价于清理 Redis 刷新会话。

备份、生产 TLS/反向代理、镜像发布和灾难恢复尚未验收。本机命名卷持久化不能当作备份。Windows 终端 Ctrl+C 用于正常停止，tools/stop-test.ps1 是本机测试进程终止入口，不能把它描述成生产优雅关闭流程。

官方依据：[Docker Windows 安装](https://docs.docker.com/desktop/setup/install/windows-install/)、[Microsoft WSL 命令](https://learn.microsoft.com/en-us/windows/wsl/basic-commands)、[MySQL 官方镜像标签](https://github.com/docker-library/official-images/blob/master/library/mysql)、[Redis 官方镜像标签](https://github.com/docker-library/official-images/blob/master/library/redis)。

## K3只读测试连接

默认`ADTEK_K3_ENABLED=false`，未配置时同步明确返回503；开发库不注入演示订单。按环境提供ADTEK_K3_URL、ADTEK_K3_ACCOUNT、ADTEK_K3_APP_ID、ADTEK_K3_APP_SECRET、ADTEK_K3_USERNAME。LCID默认2052。凭据由部署环境注入，不写进仓库、命令历史或前端；本阶段没有读取旧.env或配置真实ERP。

本机持久接入现可使用`tools/configure-k3.ps1 -JsonPath <受保护JSON路径>`，字段与步骤见[全量同步接入](17-生产订单全量同步接入.md)。开发启动显式导入deploy/.secrets/k3，容器API只读挂载同目录；没有配置时仍禁用。更新配置后重启相应API，容器可用`tools/container-test.ps1 restart-api`并等待健康状态。原恢复实例不跟随配置变化。

adtek.k3默认连接10秒、登录30秒、单页/单据60秒、单次完整拉取180秒；page-size=2000、max-pages=100、max-rows=100000、单响应4MiB。超限整批拒绝而不是静默截取。订单与可选组织分别有预算，前端等待450秒；当前未做大批吞吐压测。确认实际K3版本的FID、FTreeEntity_FEntryId、FPrdOrgId.FOrgID/FNumber及View形状之后才能开启真实联调；还须确认跨页一致性方案。

V7复制用户工厂关系至SN归属表并增加菜单，保留旧关系表/数据卷和账号密码；已有SN角色会话需重新登录。V8已实施后只能新增V9+，不能改已应用迁移。同步进程崩溃遗留FETCHING需检查当前有效版本和数据库状态；没有后台自动恢复/任务接管功能，禁止把该状态直接改SUCCESS。

## S4 测试启动配置

既有 `tools/start-test.ps1` 自动运行 V8 并启用持久工作器，无需额外进程。可在启动终端设置 `ADTEK_SN_MAX_BATCH_QUANTITY`（默认100000）、`ADTEK_SN_MAX_IMPORT_BYTES`（默认8388608）、`ADTEK_SN_PREVIEW_SECONDS`（默认600）；分别映射 adtek.sn.work 的 max-batch-quantity/max-import-bytes/preview-seconds。默认前端上传8MiB，增大后端阈值不会自动增大前端上传准入。前端建议量10000与这些资源阈值及订单业务额度独立。

V1—V8冻结，后续V9+；原账号密码/卷保留。新SN菜单来自角色当前授权，重新登录刷新菜单。历史文件由浏览器先解析UTF-8 CSV/TXT首列，受控清单落业务固定输入；不创建可下载历史导入文件。生产不得清理被活跃任务引用的输入/预演/PI控制行。先查原操作的终态，再决定新意图；禁止手工清水位、删除护栏或解锁PI迎合失败任务。

当前使用全局授权/快照锁保证写用例一致性，默认执行事务30秒和任务总预算300秒。调整资源阈值须同步量测内存、SQL包、事务/锁等待和恢复，不以一次10001枚测试当生产容量。单机打包JVM强杀和独立卷SQL/文件恢复已在S7演练，多主机及生产恢复指标仍待验收。

## S5 测试启动与文件恢复

既有启动脚本自动应用V9，领取/回调及CSV/XLSX文件工作器与服务同进程运行。无额外MES默认账号或共享secret。V1—V9冻结，后续V10+。保留MySQL/Redis卷和原管理员密码，重新登录获取当前菜单。

打印CSV/XLSX使用同一受控file-root及16MiB单文件预算；XLSX流式窗口200行，临时压缩sheet在关闭时释放。文件恢复由原提交人以当前原厂打印+下载资格触发，保持原ID、固定快照和摘要；文件损坏/丢失进入RECOVERING，不能删打印事实或把SN退回待打印。临时文件与发布孤儿按任务/代次受控恢复，当前没有自动永久清理业务历史的作业。打印文件READY不表示当前标签归属有效。

本机MES调用工具及凭据生命周期见[契约](12-MES领取与打印契约.md)。真实MES保持未配置；隔离测试凭据不进入开发库，也不交给生产调用方。
