# 生产订单全量同步接入

订单页“全量同步”调用`POST /api/v1/sn/orders/sync`，不传billNo；按单据同步传入单号。交付配置默认禁用外部K3连接；本机已按用户明确指定的`sn-center-python/sn.env`安装五个K3连接字段。2026-09-30 16:53:31的FAILED/1005000001是接入前历史记录，不能据此判断当前配置状态。实际运行证据见[真实接入报告](reports/2026-09-30-K3真实全量同步.md)：18443测试环境发布3418张订单、26660条分录，开发环境已加载配置。

## 配置并启动

新工程启动只读取自己的受保护配置目录，不自动读取旧工程。已有旧配置时直接执行以下命令，只导入五个K3字段，不导入数据库、旧账号或其他环境设置，不执行源文件内容。支持旧解析器的`export`、成对引号、最后赋值有效及外层空白；键名大小写严格匹配，不与当前Shell环境混用。缺字段/非法值时不覆盖目标，不改源文件。

```powershell
./tools/configure-k3.ps1 -LegacyEnvPath ../sn-center-python/sn.env
```

也可将[空模板](../deploy/k3.example.json)复制到本工程`deploy/.secrets/k3-input.json`，填写以下五字段：

| 字段 | 内容 |
| --- | --- |
| url | 金蝶K3Cloud应用根地址，不能包含登录凭据、查询参数或片段 |
| account | 账套ID，也是订单的来源身份，不能随意换成其他账套 |
| appId | WebAPI应用ID |
| appSecret | 对应应用密钥，只保存在受保护文件中 |
| username | 具有生产订单/组织只读查询资格的金蝶用户 |

JSON仅作为数据解析。必填、字段白名单、长度、控制字符和占位符校验全部完成后才覆盖配置；不接受`${...}`插值，不执行脚本。工具限制目录ACL，只输出启用/完整状态及缺失字段名，不显示值，也不主动访问金蝶。

```powershell
./tools/configure-k3.ps1 -JsonPath ./deploy/.secrets/k3-input.json
./tools/configure-k3.ps1
```

安装结果为`deploy/.secrets/k3/adtek.k3.*`文件，已在Git和Docker构建上下文中排除。开发脚本通过`SPRING_CONFIG_IMPORT`指定该目录，容器API只读挂载到`/run/adtek-k3/`。不需要修改Java源码、镜像内文件、数据库密码或管理员账号。采用Spring Boot原生[配置目录导入](https://docs.spring.io/spring-boot/reference/features/external-config.html)，应用启动时加载；更新文件不会自动热加载。

开发环境重启入口：

```powershell
./tools/stop-test.ps1
./tools/start-test.ps1
```

容器已启动并使用当前Compose配置时，重新加载K3配置：

```powershell
./tools/container-test.ps1 restart-api
```

该动作只重启原API容器并等待健康状态，不重启数据库。首次应用新的Compose挂载配置仍先执行`./tools/container-test.ps1 start`。开发与独立容器测试环境共用这份本机K3配置；恢复演练的固定旧环境不自动接入。

随后使用有`sn:order:sync`和全部工厂资格的账号，进入“生产订单快照”，点击“全量同步”。同步中显示等待提示并锁定同步输入/按钮；成功后回到当前筛选条件第一页、刷新单据与统计，选中单据查看完整分录，再从“去生成”进入生成页。明确失败只显示实际错误；网络/协议导致结果未知时，先查看同步记录，不能把关闭页面视为取消。

如需停用连接，运行`./tools/configure-k3.ps1 -Disable`，再重启相应API。原字段保留在受限目录中，但开关为false；已同步的订单快照和生成额度不删除。

## 同步行为

登录使用LoginByAppSecret，全量分页使用PRD_MO/ExecuteBillQuery，按FID及分录内码排序，读取全部分页后统一发布。旧十个业务字段保持，新增稳定字段为FID、FTreeEntity_FEntryId、FPrdOrgId及FPrdOrgId.FNumber；目标账套不支持FPrdOrgId.FOrgID，组织内码直接取FPrdOrgId。登录会话使用无引号Version=0 Cookie；目标K3不识别Java默认Version=1带引号的值。请求时间采用旧部署的Asia/Shanghai及`yyyy-MM-dd HH:mm:ss`格式；支持二次JSON编码、多语言Name/Value和数组嵌套错误，错误原文不外传。

保留状态1/2，客户为空的单据继续保存在快照但不显示为可生成订单；空物料分录保留。稳定单据/分录/组织内码必须真实存在，不用显示行号猜造。V17按迁移基线保留ERP精确小数，计划量落DECIMAL(23,4)、通过普通十进制字符串传输，非负且不超过long上界；超过4位有效小数/非法值拒绝，不让数据库隐式舍入。含任意小数分录的订单quantityReady=false、整单SN额度为0，页面提示数量待确认；上下文返回NON_INTEGER_QUANTITY，预演和生成均拒绝。即使多个小数分录汇总为整数，也不自动转换成SN。历史已生成/分配额度保持；上游恢复整数后重新同步可恢复生成资格。

任一页、登录或数据校验失败，原有效快照与历史生成/分配额度保留；合法完整空结果可以发布空快照。发布再次检查当前权限与基准版本，竞争同步不能覆盖较新的发布。具有工厂同步资格时同时拉取组织；组织接口失败可发布订单并显示未映射警告，不猜测工厂关系。

默认分页2000，最多100页/100000行、单响应4MiB。超限明确拒绝，不截断后报成功。单次订单/组织读取各180秒总预算，发布60秒；前端450秒、Nginx480秒等待。同步仍为有限预算HTTP用例，不是后台可续跑任务；进程中断遗留FETCHING须核对已发布版本再操作。

## 验证与当前限制

`tools/verify-k3-configuration.ps1`在唯一临时工程执行正式配置入口，检查秘密原文保留、错误输入不覆盖、停用及输出脱敏。`K3ConfigurationTest`用实际Boot配置加载器和回环K3协议验证多页读取；`SnFoundationIT`验证真实MySQL发布、失败回滚、空结果、权限和并发。浏览器运行器验证等待态、单次提交、明确失败不显示旧成功或未知提示，保留原双栏及三语页面。

自动回归使用回环K3协议及独立MySQL/Redis，不连接真实金蝶。实际账套验证另外记录来源、时间、发布状态和计数，不能把回归夹具当成真实同步；跨页期间上游变更的一致性保证仍需金蝶侧契约。
