# 维护、迁移与恢复契约

本文件承接S7工作包。维护命令、定时进程、HTTPS容器及数据库/文件恢复已实现并完成隔离演练，见[S7恢复报告](reports/2026-09-30-S7-容器维护与恢复.md)。旧库ETL及生产切换尚未完成，不能把这次夹具演练作为生产数据迁移验收。

## 运维入口

DDL和数据维护使用独立命令进程、专用数据库账号、明确目标schema白名单与UUID运行号，不暴露页面维护接口，不借用管理员Cookie。默认dry-run，显式apply才写入。运行号绑定规范化输入摘要，成功重试返回原结果，异载荷拒绝；DDL自动提交意味着半途失败只能核对现状继续，不能声称回滚整组DDL。

互斥使用同一MySQL连接持有的命名锁，schema级锁区分独立数据库；运行中断释放连接后可重入。状态、计划/结果、失败类型写入运行记录，日志不输出SQL原始错误或数据库凭据。锁等待与语句时间有上限，超时以非零退出提示调度器告警。进程退出码不能因已写入部分分区而被伪装成成功。

月分区只操作sn_item、sn_audit和sn_audit_archive，固定RANGE COLUMNS列及合法月界限；拒绝任意表名/分区名/SQL。以当前月份为基准预建未来月份，验证兜底分区和已有边界；已存在的合法边界重复执行无变化。REORGANIZE处理兜底中的已有记录，不能先删除兜底。SN护栏和历史成员不参加清理。

预演只删除已过期且task_id为空、没有任何已提交任务依赖的记录。已绑定的失败、取消或成功预演仍保留，以支持历史与幂等证明。清理与生成提交遵循相同控制锁顺序，避免检查后绑定的竞态。

## 审计冷存储

保留策略为永久保留。冷存储移动不是删除保留期；不使用1095天替代三日历年，也不自动销毁归档。

归档以已结束的UTC月份为范围，月边界对应数据库存储分区；页面日期仍按Asia/Shanghai转换查询。只能复制原始列和(created_at,id)，不能更新内容、重新生成ID或丢弃重复错误。已有相同主键而内容不同立即拒绝；逐行长度分帧、NULL独立编码、稳定排序的SHA-256与精确行数用于比对，不使用简单SUM/COUNT冒充内容校验。

复制成功后允许在线与归档同时存在；查询ALL按原始键去重。没有在隔离目标验证过的备份证据时保留在线副本。移除在线数据之前重新验证范围、身份、内容、归档读取和备份绑定；失败保留可恢复副本，记录未完成阶段。不得通过整段DROP p_history误删其他月份。

ARCHIVE_FINALIZE要求受控备份根目录及`备份UUID/restore-恢复UUID`相对目录。验证实际SQL、完整规范SQL摘要、tar成员/字节、浏览器报告、证明时间和独立源/目标server_uuid；证明摘要参与运行号输入摘要。再核验当前源库身份并锁定两表整月范围，内容必须仍与恢复证明相等。在线DELETE及SUCCEEDED运行记录同事务提交；任一失败均回滚，永久归档不删。证明损坏/丢失时包括成功重放也拒绝，需要保留原证据。证明目录是受ACL保护的运维信任边界，不是供页面上传的可执行指令。

当前备份工具仅支持独立container-test环境；停止该环境Web/API，持MySQL全局读锁，同时导出SQL及固定文件，超时退出并恢复原容器，核对原镜像ID，不跟随本地同名新镜像隐式升级。恢复使用全新项目/卷与源镜像ID。完整SQL比较仅归一化MySQL重放后补写的同utf8mb4排序规则冗余CHARACTER SET，所有数据行、约束、分区和排序规则仍参与摘要。Redis会话不恢复，恢复后重新登录。原始SQL含密码哈希，保存在忽略且ACL受限的目录，报告不复制它。

## 独立调度

`--maintenance-scheduler`不启动Web、Redis或Flyway；显式要求ADTEK_MAINT_CRON与ADTEK_MAINT_ZONE，非法配置直接失败。缺省dry-run，`--apply`才写入，`--once`执行一次后退出。启动补执行当前UTC日，随后按指定时区cron唤醒；同UTC日/配置/动作生成固定运行号，重复启动返回原结果。每次只清理rowLimit条到期未绑定预演，积压分日继续或由运维使用新运行号分批处理。

Compose的scheduled-maintenance profile默认不启动；启用后按Asia/Shanghai每日02:15运行分区维护与预演清理，归档复制默认关闭。可选复制只针对已结束UTC月份，绝不自动ARCHIVE_FINALIZE。运行失败写记录/非零退出，Compose最多重试三次后保持退出，日志及退出状态是外部监控接入点；未配置邮件/短信/外部告警服务，不能声称已经通知值班人。

## 源数据与恢复

旧库只读，必须指定源schema、版本、时区与目标白名单，未知字段/时间语义不能猜测。19张旧表逐类盘点，保留来源ID到新ID的稳定映射、双唯一性、水位、来源额度、固定成员和不可变文件。旧schema缺少稳定ERP内码和部分历史快照：不足证据形成明确阻断或只读例外，不从当前SN重建曾经打印或领取的成员。

源数据摘要、映射版本和运行号共同绑定断点；来源变化不得直接续传。含密码哈希的原始快照和文件只进入受控备份目录，报告只写计数、摘要和问题类别。旧幂等命名空间独立，新领取不能吞掉无法还原的旧请求；映射与业务接受记录需可追溯。

备份必须共同覆盖数据库与固定文件，使用明确停写/一致性边界；仅有Docker卷或SQL导出成功不算恢复验证。恢复始终进入新隔离目标，验证迁移链、身份、SN/护栏、水位额度、历史引用、任务终态、文件字节和权限，再出具证据。生产切换还需要真实ERP/MES联调、业务UAT与单写封锁记录。
