# 需求与当前实施范围

用户要求依据三份 v1.1 基线，将 sn-center-python 全量迁入新的 adtek-platform-sn；先完成工程和测试启动配置，并在本机安装 Docker、MySQL 8.4、Redis。根目录三份原件、旧工程和旧库保持不变。有效来源快照在 references/baselines。

完整范围是迁移方案 F-01—F-30，包括账号/RBAC、工厂/ERP 订单、规则、PI 起号、生成/分配、领取/打印/MES 回调、转厂、查询/审计/导出、维护、历史 ETL 和运维验收；逐项状态集中在 [完整功能矩阵](11-完整功能迁移清单.md)，本文件不再维护第二份相互偏离的清单。

当前交付的工程切片：固定工具/依赖、六模块后端、严格 TS React、统一协议、认证会话、按权限合并的 Actor、SQL 数据范围、用户增改启停/重置/角色绑定、独立角色与数据范围/部门/菜单/三语字典配置、事务内权限复核与管理 diff、操作日志查询与入口失败审计、真实 MySQL/Redis/浏览器测试、本机启动流程和证据。浏览器发布认证、用户、系统配置、审计及SN工厂/订单/规则页面；未实现的SN状态命令仍不开放。

当前没有旧业务库、实际 ERP/MES 联调凭据或生产发布目标。可以继续实现适配端口、契约和隔离测试，不能将它们描述为外部系统联调通过。历史数据无法还原时的处置和业务差异必须按迁移方案明确记录，不凭生成数据声称已完成迁移。

S2 新增持久操作、任务领取/代次、进度、受控文件与恢复设施；在线操作日志 CSV 导出作为首个实际业务消费者。提交、重放、执行、查询、取消、恢复及下载复核当前权限；前端保留必要操作 UUID 以恢复未知结果。本切片不等于 SN 生成/打印任务、全量导出或历史文件已经迁移。

本机测试初始化使用空目标库和随机凭据。生产 TLS、备份恢复、压测、UAT、切换和回滚仍为后续阶段，不因 Docker 健康或编译成功而关闭。

S3新增工厂手工建档/组织同步/稳定映射、完整ERP订单快照发布与历史来源额度、持久编码规则，以及用户工厂资格绑定。保持旧三个独立页面路径和主要字段、操作、业务规则；基线要求修正的差异在[S3工作包](plans/2026-09-29-S3-工厂订单与规则.md)明确。订单“去生成”现由S4接通实际预演/生成用例；S3历史报告保留当时的未开放边界。

S4现已实现旧PiInit/Generate的起号、历史清单、预演、生成、分配与记录页面；整单分配按基线全部当前待分配成员执行。实现与运行验证不等于完整迁移验收，见[S4报告](reports/2026-09-29-S4-初始化生成与分配.md)。S5领取/打印/MES已接通，转厂/查询/存量ETL继续后续阶段。

## S5 领取、打印与 MES

当前新增旧 Acquire 页面对应的 PI 汇总、物料/状态连续段、同 PI 跨厂只读、整厂+PI领取、固定批次/逐项结果和打印历史。页面确认打印与文件生成分开，CSV/XLSX恢复不改原业务。MES使用独立服务身份进入相同SN用例，支持领取、固定批次、打印回调和只读拉取。契约见[接口说明](12-MES领取与打印契约.md)，验证记录见[S5报告](reports/2026-09-30-S5-领取打印与MES.md)。完整转厂/查询/首页和存量迁移仍按后续阶段推进。
