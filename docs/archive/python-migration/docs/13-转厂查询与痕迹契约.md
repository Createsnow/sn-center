# 转厂、查询、操作痕迹与首页

S6实现契约，承接三份v1.1来源及[S5 MES契约](12-MES领取与打印契约.md)。以下人员接口前缀均为`/api/v1/sn`，使用当前可撤销人员身份。SERVICE只能使用已定义的MES入口。业务ID、版本、数量和流水按精确字符串交换；错误码仍为整数。

## 转厂

| 接口 | 权限与输入 |
| --- | --- |
| GET /transfers/candidates | `sn:transfer:view`；factoryId/pi/scope，MATERIAL时material（空表示无物料），SINGLE时完整sn |
| GET /transfers/factories、/targets | `sn:transfer:targets`；最少交接目录，完整分页；不授予目标厂SN读取资格 |
| POST /transfers、/transfers/direct | 分别apply/direct；operationId、factoryId、pi、scope=PI/MATERIAL/SINGLE、material/sn、toFactoryId、toPi、toCustomer/toMaterial、targetSource=MANUAL/SNAPSHOT、reason |
| POST /transfers/{id}/withdraw、/reject、/approve | 对应withdraw/reject/approve；operationId、version、note |
| GET /transfers | view；factoryId/pi/status/page/size，历史原转出或转入工厂可见 |
| GET /transfers/{id}、/{id}/items | view；固定头/成员与独立当前投影；成员cursor/size完整读取 |
| GET /transfers/operations/{kind}/{operationId} | APPLY/DIRECT/APPROVE/REJECT/WITHDRAW；原主体与当前动作权限 |

整PI、PI+物料、单枚SN只选择来源厂+PI中TO_ACQUIRE/TO_PRINT/PRINTED且未被其他转厂冻结的成员。提交任务时按稳定顺序占用源、目标两个PI，原子执行时确定固定成员。APPLY冻结为APPLYING，状态PENDING；APPROVE或DIRECT整批转为目标厂PI的TO_ACQUIRE，清当前领取/打印/时间，写入精确SN+月份+目标厂PI领取例外。REJECT/WITHDRAW逐成员恢复申请前状态和原指针，保留固定历史。

APPROVE、REJECT、DIRECT须具有该动作的全部工厂范围；APPLY/WITHDRAW要求源厂资格，不能用目标厂只读范围写源厂。撤回不绑定原申请人，但要求当前源厂该动作资格。目标须启用，目标PI必填；空客户/物料逐成员沿用，不能误解为空字符串覆盖。快照目标必须仍精确匹配当前有效订单分录；不匹配按手工目标处理，并保留实际targetSource。

目标当前PI+完整SN冲突整批拒绝。护栏更新当前PI，不删除重建；seqPi/seqDec、来源身份、原领取/打印成员、水位和额度保持原事实。同厂同PI且全部字段无变化拒绝。新版错误：1004000023条件已变化、24无可转成员、25没有实际变化；碰撞复用1004000015，PI占用复用1004000014。软件不替工厂处理已经打印的实体标签。

## SN查询和固定导出

GET `/items`和`/items/count`使用`sn:query:view`。过滤包括factoryId/customer/pi、materialMode=ALL/EMPTY/VALUE及material、status、精确sn、billNo、当前batchId、piAll。列表使用签名游标而非偏移截断；数量是精确字符串。piAll必须指定PI，非全部范围人员必须在自己的当前工厂范围拥有该PI；排除未分配工厂的行。该只读例外不影响写权限。

POST `/exports`使用`sn:query:export`并要求view，输入`{operationId,format:"CSV"|"XLSX",filters}`。快照范围求两个动作的交集。GET `/exports`为本人历史，`/exports/operations/{format}/{operationId}`查询原操作。默认最多100000行，产物16MiB；超限明确失败，不静默截断。导出固定全部行，包含旧11列、流水归属、来源稳定身份、当前批次/打印/转厂和时间。

查询固定快照在授权协调/快照控制保护下分块读取。提交成功时operationState=SUCCEEDED表示固定快照已确认，文件可能仍PREPARING；不能因文件失败重新提交同业务。CSV保留业务编码原文；XLSX所有字段为文本。恢复使用原任务ID，校验既有摘要与字节数。下载及恢复复核原提交者、view/export和全部快照原范围，SN后来转到其他工厂不会转移文件权限。

## SN操作痕迹

`/audit`页面与平台`/system/audit`分开：前者按工厂呈现SN业务事实，后者保留认证、配置、入口安全和平台管理日志。V12开始由通用审计观察端口同事务追加SN事实；成功投影写入失败则回滚业务，失败事件独立记录且不覆盖原错误。来源事实来自服务已提交/同事务固定记录，不从HTTP请求体猜测。之前的开发日志没有自动伪造回填；旧生产历史由S7迁移流程处理。

GET `/audits`、`/audits/count`、`/audits/{id}?createdAt=`、`/audits/meta`使用`sn:audit:view`。保留原日期、action/operator/factoryId/pi/source/result/batchId/keyword筛选，新增storage=ALL/ONLINE/ARCHIVE。日期是上海自然日，默认结束日为今天、起始日为前30日，结束日包含当天；数据时间以UTC存储。关键词按原约定查起止SN、操作号、转厂号、来源订单和安全详情，`%/_`按文字搜索。

历史固定操作人工号/姓名/角色、来源、动作/结果、原工厂/目标厂/PI、客户/物料/订单、SN集合边界、数量、状态变化、批次/操作/转厂号、原因、错误码和traceId。混合客户/物料为null；起止SN是命令边界或固定集合最小/最大文本，不证明中间全部连续；取消任务不记录已完成的SN状态变化。详情为白名单JSON，不记录凭据、完整请求体、数据库异常或SQL。

当前工厂权限匹配原厂或转入厂；无工厂的全局事实仅全部工厂范围可读，不开放piAll例外。归档使用同一过滤/权限。ALL在在线与归档暂存重复时按时间+ID去重，详情仍按历史原键读取。当前永久保留；归档查询不意味着可以删除，归档写入/核对/备份与维护流程在S7交付。

POST `/audits/exports`同查询导出的格式/操作号模式，要求view/export，按每条事实分别满足两个动作的原厂或目标厂资格。使用单条INSERT SELECT的一致视图固定快照，避免独立失败审计并发追加造成跨页不一致。GET `/audits/exports`及`/audits/exports/operations/{format}/{operationId}`查询本人记录/原操作；下载使用通用文件接口。CSV对姓名、原因等自由文本防公式解释，业务编码不改；XLSX保存原始文本。固定快照不随在线归档搬迁或身份改名变化。

## 首页和会话

GET `/dashboard`使用`sn:dashboard:view`。在途状态限定当前工厂范围；生成/导入全局累计仅全部工厂范围返回，其他为null。待审批需同时具备转厂view，按其范围与首页范围求交。最近生成任务只开放给generation:view全部工厂范围，仍套用首页范围。今日作业来自成功业务事实、领取/打印/转厂固定记录，按Asia/Shanghai当天计算；当前SN状态变化不会改写过去的作业数量。页面30秒刷新，不显示全局后台任务内部数据。

V10—V12增加角色菜单并推进既有SN角色账号的security_version；用原密码重新登录获得新菜单。原管理员密码和持久卷不变。V1—V12已应用后冻结，后续只能新增迁移；此契约不表示真实ERP/MES、容量、人工UAT或生产切换已经验收。
