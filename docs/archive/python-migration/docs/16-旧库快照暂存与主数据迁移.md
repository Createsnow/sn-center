# 旧库快照、暂存与主数据迁移

目前支持仓库已知 `sn-python-repository-v1`：19 张表、254 个字段。源库只读快照、目标分块暂存、工厂/账号/角色范围/规则版本及有限 IMPORT 库存导入已实现；来源额度、生成 SN、领取/打印/转厂历史和文件的全量业务导入尚未完成。`STAGED`、`MASTER_STAGED`、`INVENTORY_STAGED` 都不能作为生产切换或账号启用凭据。

## 边界与来源

不读取旧工程 `.env`，不让新 Flyway 连接旧库，不覆盖旧 Flyway 历史。源库连接须显式注入 `ADTEK_LEGACY_SOURCE_URL/USER/PASSWORD`，使用只授予指定 schema SELECT 的账号。源 schema、源时区、schema 版本和 UUID 必须明确提供。时间没有偏移的旧 DATETIME 按显式源时区解释；夏令时重叠/空洞拒绝。源 `gen_month` 按原值保存，不随 UTC 转换重算。

原结构基准为 `backend/adtek-sn/src/main/resources/legacy/repository-v1.json`，原 SQL SHA256 为 `050f686bcd998e5ca2d9ffe939694dfae17c7d314b6ea6a2096218327c9f48e8`。未知列、类型、NULL、排序规则、主键/唯一键或分区布局拒绝，不尝试猜测版本。源 metadata 前后核对，导出期间使用同一 MySQL 一致性只读事务。旧生产停写及 DDL 冻结仍是正式切换的外部条件。

## 执行顺序

先构建最新 JAR，在全新独立目标执行新的 Flyway 链。源和目标必须是不同 MySQL 实例，不能仅改 schema 名。所有入口由 `tools/legacy-*.ps1` 或 JAR 的同名 `--legacy-*` 参数调用，不启动 Web 服务。

```powershell
./tools/legacy-snapshot.ps1 -RunId <snapshot-uuid> -SourceSchema <explicit_schema> -SourceZone Asia/Shanghai
./tools/legacy-stage.ps1 -SnapshotId <snapshot-uuid> -RunId <migration-uuid>
./tools/legacy-stage.ps1 -SnapshotId <snapshot-uuid> -RunId <migration-uuid> -Apply
./tools/legacy-master.ps1 -SnapshotId <snapshot-uuid> -RunId <migration-uuid>
./tools/legacy-master.ps1 -SnapshotId <snapshot-uuid> -RunId <migration-uuid> -Apply
./tools/legacy-inventory.ps1 -SnapshotId <snapshot-uuid> -RunId <migration-uuid>
./tools/legacy-inventory.ps1 -SnapshotId <snapshot-uuid> -RunId <migration-uuid> -Apply
```

上例时区仅说明参数格式，实际值必须来自旧部署证据。目标凭据由 `ADTEK_LEGACY_TARGET_URL/USER/PASSWORD/SCHEMA` 注入，目标 schema 名同时充当精确白名单。不要把密码放在命令行或报告中。JAR 直接调用还要求显式 `ADTEK_LEGACY_SNAPSHOT_ROOT`；脚本固定使用本工程 `deploy/data/legacy-snapshots`，先收紧 Windows ACL。快照包含旧口令哈希，不能提交、共享截图或作为普通日志打印。

快照默认总行数十万、字节数 1 GiB，可显式调节，最大总行数 1.5 亿是输入边界而非容量测试结论。文件逐行 NDJSON，所有源非空值均为字符串，SQL NULL 保持 JSON null；高位整数、小数和原始本地时间不经浮点转换。只有全部文件、结构和问题检查结束后才原子发布 `manifest.json`。失败残留无 manifest 的目录不能续用为完整来源，应保留排查并用新 snapshot UUID 重新取一致快照。

暂存默认 dry-run。apply 仅写 V14 的 `sn_legacy_*` 表，分块行和检查点同事务，块大小 1—1000。中断前提交的块保留；用原迁移 UUID、原 snapshot、原映射版本重试，先逐字段重算已提交内容，再继续。记录绑定源指纹、manifest 摘要、映射版本；修改源、检查点、旁存摘要或真实 JSON 内容都会拒绝。不会 INSERT IGNORE 掩盖差异。

暂存识别目标 V14/V15/V16/V17；主数据识别 V15/V16/V17，要求新的空业务目标和完整 STAGED 来源。导入前再次检查全部来源包/暂存行，按原始时间转换 UTC，并在一个事务中写入以下内容及主数据证明：

| 来源 | 目标与处理 |
| --- | --- |
| sn_factory | 新数字 ID 稳定绑定源包顺序，保留编码/名称/启停/来源；不虚构 K3 组织内码 |
| sn_user | 保留原高位 ID、工号、姓名、语言、待改密；新账号全部停用，原状态仍在原始档案 |
| admin | PLATFORM_ADMIN + SN_HQ |
| factory_operator | FACTORY_OPERATOR + 原工厂绑定 |
| query 有绑定 / 无绑定 | SN_QUERY_FACTORY / SN_QUERY_ALL，绑定关系不扩大 |
| sn_rule / sn_rule_version | 保留 ID、绑定、全部版本、当前版本、used、编码参数；重算与新编码器一致的摘要 |
| 旧创建者 | 能按工号解析则引用原用户 ID；缺失/未知为 NULL，原字符串在受控暂存档案，不能写成迁移执行者 |

主数据阶段合计上限两万行，超限明确拒绝。所有普通业务/任务目标必须为空；已经 bootstrap、存在业务数据、来源不一致或同号目标被改动时拒绝。成功时关闭 bootstrap，保留账号停用，禁止先开新写链路。主数据、身份、ID 映射及证明任一写入失败全部回滚；原 STAGED 数据保留。重放逐字段检查目标、身份状态、权限关系及映射，不覆盖任何后续修改。

旧 PBKDF2-SHA256 120000 次哈希只通过明确 `{pbkdf2-sha256-120k}` 前缀接入；裸哈希和未知算法不兜底。将来完成迁移并获准启用后，成功登录以同一密码升级到 600000 次编码，保留待改密标记和 security_version，条件更新防并发覆盖改密。

规则版本的创建者在接口中明确允许 NULL；前端校验与三语历史抽屉显示“创建者未记录”，不会因缺失旧主体使规则列表、有效规则或历史页整体报错。字段缺失、数字型ID和假造的0号主体仍拒绝。

## 有限 IMPORT 库存

库存入口要求目标 V16或V17、同一迁移 UUID 的已核验主数据和仍全部停用的账号。再次核对全部 19 表源快照与暂存实际内容、主数据、身份和映射。仅支持 source=IMPORT、status=PRINTED、订单号为空且没有旧作业、批次、打印、转厂、领取或分配引用的库存；出现其他类型或引用时整个阶段拒绝，不清空引用后导入。

SN、护栏、水位和映射在一个事务内写入，每 500 行使用参数化多值 INSERT，分批不形成独立提交。当前上限为 25000 枚 SN/护栏和 25000 个 PI 水位；不是通用大规模 ETL。超限先拒绝。最终证明写入失败也会回滚此前全部批次，原始暂存和主数据仍保留。用同一 UUID 重试会逐字段核对目标及映射，拒绝水位、身份、护栏或任何已导入字段变更，不覆盖。

保留源月份、原流水 PI 与当前 PI 的区别、高位流水、空流水和真实时间。可解析 SN 必须与原规则版本逐字相符；不可解析 SN 的 rule/seq 保持 NULL。无可靠历史创建者保留 NULL；不伪造 ERP 内码、历史成功任务或迁移执行人为原操作者。V16 约束使旧库存只能以 IMPORT + legacy_run_id + 空 task_id 表达，新业务仍要求真实 task_id。源旧键与新 UUID/月份、护栏、水位逐项登记。

这一阶段不会生成旧 PI 导入记录页、打印文件或其他历史投影，也不会自动启用用户。源原始历史已在受控暂存中保存，待相应转换和核对完成后才具备完整页面历史。结果 readyForPromotion/accountsEnabled 均为 false。

## 剩余数据与退出条件

快照预检给出孤儿、双唯一冲突、水位/计数/任务状态、编码和工厂排序规则冲突，以及缺 ERP 稳定来源、固定成员/文件、历史主体和在途绑定的计数。当前没有消除这些历史证据缺口的自动豁免开关。旧预演只保留事实，切换时作废，不恢复成可执行预演。

原始任务错误和审计错误不得改写为新成功状态；[102 项错误边界登记](15-旧错误码兼容登记.md)包含 97 枚举、额外字面量和无 code 的404。K3 错误使用 integration 号段且不返回原外部报文。真实来源分录/额度、幂等命名空间、领取/打印/转厂固定成员、原文件及授权、审计动作/主体尚待后续受证据约束的转换，不能用当前 SN 状态或订单显示行号倒推历史。

工程最新测试结果见[库存与整体验证报告](reports/2026-09-30-S7-库存迁移与整体验证.md)，前一检查点见[旧数据工具报告](reports/2026-09-30-S7-旧数据工具与错误兼容.md)。正式启用仍需真实源版本与时区、完整业务导入/逐类核对、旧侧单写封锁、ERP/MES联调、业务UAT和切换/回退记录；本地夹具通过不代替这些事实。
