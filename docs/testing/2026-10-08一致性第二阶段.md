# SN 一致性第二阶段：首页与角色视角

本阶段继续执行[完整验收清单](SN页面与功能一致性验收清单.md)，完成首页和角色视角的部分对齐。整体目标仍未完成；本报告不代表规则、生成、领取打印、转厂等页面已经全部验收。Python 原型源码保持不变，所有操作使用独立比较库和本机合成 K3。

## 已实现的对齐

- 首页采用原型的标题、统计范围说明、指标顺序和布局，累计生成与导入合并显示。数量按精确整数字符串计算，避免转换为 JavaScript 不精确数字。
- 在途统计仅包含待分配、待领取、待打印、申请中；今日作业量仅包含生成、分配、领取、页面打印和回调。初始化和转厂动作不再混入首页今日作业量。
- 快捷入口与左侧导航共用顺序，按当前权限显示；管理员前六项为订单、生成、起始号与导入、规则、领取、转厂。
- 最近生成任务补齐单据号、进度条和独立递增编号。订单名称来自提交时快照，执行进度只读取当前执行代次，成功数量以已提交业务结果为准。编号与任务提交同事务保存，重试沿用原编号，内部幂等关联仍使用 UUID。
- 新增当前 SN 业务身份接口，返回业务角色及授权工厂。顶部显示操作员、查询员身份和绑厂名称，不再从平台管理权限猜测业务角色。
- 查询角色补齐转厂只读权限；不授予申请、审批等写权限。工厂候选查询仍可用于授权业务页面，但非管理员不显示工厂管理入口，直接访问该页面返回首页。
- 首页对齐桌面和 760 像素布局、表格列宽、进度标识及折叠侧栏高度。截图等待过渡动画结束，避免把过渡状态当作最终布局。

## 实际浏览器操作

新增脚本为 `frontend/e2e/parity/dashboard-roles.spec.ts`，5 个场景在原型和新版分别执行，共 10 项。两阶段合并的 26 项场景全部通过；随后调整首页表格和折叠高度，再次执行全部 10 项首页/角色场景通过。脚本使用真实浏览器与 API，不伪造业务响应。

| 场景 | 已检查内容 |
| --- | --- |
| 管理员首页 | 六个指标的顺序和值；全部工厂范围；四种今日动作各 10 枚；最近订单、编号 1、100% 进度；六个快捷按钮逐一进入再返回；桌面及窄屏 |
| 工厂操作员 | 首次改密成功；四个指标；甲厂范围与顶部名称；五个菜单；没有最近任务；转厂入口、刷新、退出、旧密码失效、新密码重新登录 |
| 总部查询员 | 首次改密成功；五个指标；全部工厂范围；六个菜单；转厂只读入口；隐藏最近任务与工厂管理；直接访问工厂管理返回首页；刷新和重新登录 |
| 绑厂查询员 | 首次改密成功；甲厂范围；四个指标及六个菜单；转厂入口；顶部工厂名；工厂管理跳转限制；刷新和重新登录 |
| 首页三语 | 英文、越南文、中文的指标、今日作业量、快捷入口；保存用户偏好并刷新后继续正确显示 |

首轮通过 `tools/testing/parity-role-fixture.py` 在每个比较库各创建三个专用账号，随后通过页面完成首次改密。复跑沿用改密后的凭据，不重置账号。原有管理员账号及密码保持不变；账号建立仅作为本阶段测试准备，不能算作 P13 账户管理页面验收。

编号、创建时间和管理员显示名由各比较库独立生成。界面比较不要求两次独立提交具有同一时间，也不通过修改原型数据伪造一致。

## 环境与复跑

比较 Java 服务已经应用 V20（查询员转厂读取）和 V21（生成任务页面编号）。实测比较库最新版本为 21，现有一条生成任务完成编号回填；原开发库、HTTPS 库和公司配置均未使用或修改。现有 Flyway V1—V19 文件未改写。

访问继续使用新版页面 15173/API 18080、原型 8000、MySQL 33308、Redis 36380、合成 K3 19090。临时 101 行订单已移除，合成 K3 额外数据为空；两边定时同步均关闭、间隔恢复为 1440 分钟，管理员语言恢复中文。

从工程根目录，在确认当前运行的是比较实例之后执行：

```powershell
# 仅首次需要创建角色测试账号；已存在的账号不会被重置。
../sn-center-python/.venv/Scripts/python.exe tools/testing/parity-role-fixture.py
./tools/pnpm.ps1 exec playwright test --config=playwright.parity.config.ts

# 同一仓库一次只运行一个 Maven，且不可覆盖正在运行的 acceptance JAR。
./tools/maven.ps1 -B -ntp '-Pacceptance,integration' '-Dit.test=SnQueryIT,SnWorkIT' '-Dfailsafe.failIfNoSpecifiedTests=false' verify
```

构建前核对并停止本次比较 Java 进程，保留当前产物作为恢复依据；构建成功后使用比较环境启动脚本重新启动。不要停止无关 JVM，不要 bootstrap 已使用的账号。具体环境启动方式沿用[双项目记录](2026-10-08双项目启动与功能比较.md)。
