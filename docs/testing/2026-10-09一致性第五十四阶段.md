# SN 功能迁移验收结论（第五十四阶段）

2026-10-09。按照用户“外观等细节不纠结，尽快收敛问题，尽早完成任务”的要求，本轮本机功能比对收尾。主要页面、业务操作和完整 SN 流程已取得双端浏览器证据，不再扩展像素和无具体故障依据的组合矩阵。保留差异见下表，不能将结论理解为所有页面细节、历史数据和外部接口协议完全相同。

本阶段没有修改业务实现或数据库结构，新增 MES 和收尾验收脚本，修正隔离夹具的身份 ID 冲突。前阶段订单统计、定时设置返回缓存的修复保留。SN 后续开发与测试进入 `adtek-platform-sn`，相邻 Python 原型保持只读。

三个最终分组共 6 项浏览器测试，单 worker、零自动重试，58 张最终截图。这不是所有历史注册用例的一次全量重跑。后端 603 个基线文件、acceptance JAR、前端业务源码和 V1—V41 本阶段未改，未重复运行后端测试；前阶段后端结果仅作为继承证据。构建仍有分块体积提示，XLSX 读取器有默认样式提示，均未影响功能和内容核对。

MES 使用真实服务客户端。新版服务身份被人员接口拒绝，测试结束已停用。回调比较更新数、已打印数、阻止数及拒绝原因；原型只返回跳过项，新版保存完整逐项结果，未宣称响应 JSON 完全一样。

## 保留差异与边界

| 差异 | 处理及影响 |
| --- | --- |
| MES 协议 | 保留已确定的[独立身份、持久任务、UUID 幂等与游标契约](../business/MES领取与打印契约.md)。原型使用人员令牌、同步结果、数字页码。原调用方需要适配；零可领、固定历史成员、重放结果遵循新版契约。尚未接入真实 MES。 |
| 原型按物料转厂缺陷 | 原型丢弃空物料参数，首次候选加载报错、下拉无法选择；新版提供可用的物料候选。保留第 22 阶段证据，不故意复制故障；该分支不计作双端等价通过。 |
| 原型查询分页竞态 | 原型末页修改每页条数会发生响应覆盖；新版稳定回第一页。保留第 28 阶段差异，不复制竞态。 |
| 首页未来日期 | 原型“今日”仅限制今天零点以后，新版还限制小于明天零点。本次没有未来审计记录，正常页面操作写当前时间；人工未来数据不属于等价证明。 |
| 历史与容量 | 用户已决定不搬迁旧数据；V31 前无法重建的创建顺序、旧编号不宣称相同。50 万条导入已有功能证据，但新版约 384 秒、原型约 69 秒的已测差异保留，未作生产吞吐承诺。 |
| 恢复与外观 | 保留已批准的持久任务恢复能力。轻微样式、组件 DOM 和部分提示时序不再阻塞收尾，原始观察保留。 |

这些条目限定“本机核心功能验收完成”的含义，不是隐去差异后宣称完全等价。真实 K3/MES 联调、公司权限、生产容量与生产切换另走发布流程。本轮不访问公司网络、不更新 GitLab。

[当前清单](SN页面与功能一致性验收清单.md)汇总 P01—P16 的已验业务和证据。之前登录、规则、生成、初始化、打印、转厂审批、查询导出、审计、账户、工厂的分组证据继续保留。历史阶段的“下一步”表示当时状态，后续以明确需求或可复现缺陷进入正常开发，不再自动扩展外观一致性阶段。

诊断失败如实保留：MES 初版误用工厂列表接口；收尾脚本曾等待成功初始化后隐藏的表单、夹具 ID 与服务主体冲突、误将历史导入期望为待领取；第三次操作通过但标题读取早于页面切换。最终等待目标标题，导入明确断言 `PRINTED`，使用新夹具运行，双端观察比较通过。没有改写服务响应，也没有把中间失败改记通过。
