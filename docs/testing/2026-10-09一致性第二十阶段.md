2026-10-09，继续 P09，并通过两边页面执行单枚、整 PI 直接转厂。历史下载已改为读取打印单当前成员，转出后旧文件变少或为空；重新领取、打印归入新记录。完整功能与页面一致性目标仍未完成，P10 转厂页面整体布局、申请及审批流程未据此验收。比较库保持 V31，本轮没有 DDL，下一迁移 V32。

## 实现

人员 GET `/api/v1/sn/prints/{id}/file?format=xlsx|csv` 按原打印单工厂的当前 DOWNLOAD 权限授权。重复读事务按创建顺序、每批 500 行读取仍指向该打印单的 SN，输出当前状态、物料和领取批次。原打印头数量不变；没有当前成员时返回十一列表头。下载不创建业务或任务，不覆盖固定打印成员及已保存的追溯文件。

页面自动下载和历史 CSV/XLSX 使用新接口，不再依赖固定文件 READY，也不展示固定产物恢复按钮。固定 `/api/v1/files/{taskId}` 及原恢复协议继续用于追溯，原格式和摘要不改。无旧业务号的当前下载使用 UUID 文件名、SN 工作表；这不等于恢复了原型历史编号或原始创建顺序。

文件发送前完成有字节上限的生成，默认沿用 16 MiB。响应含 Content-Length、附件名和 no-store，发送块继续核对当前权限。格式、表头、公式防护和长整数保持上一阶段规则；固定文件默认 PRINTED，当前下载可以反映 APPLYING。服务边界、只读查询与权限规则分别落在既有分层中。

打印业务成功后即可自动下载，不等待后台固定产物。由此暴露的批量容量问题已修正：只对明确的任务容量拒绝 `409 / 1003000008`，以原操作号、原输入每秒等待，容量等待窗口一分钟。其他业务错误、权限拒绝和未知网络结果不自动重发，也不提高服务端任务上限。

空批次详情改用原型纯文字空状态，去掉默认插图；空内容区高度 60 像素。两边空详情位置为 x=700、y=128、宽720、高60。测试固定选项所属下拉框、等待历史加载，并在进入领取页后应用 PI 条件，避免页面切换时读取旧控件。

## 页面检查与下载证据

规则、初始生成和分配通过公开接口准备隔离合成数据。以下领取、打印、转厂、重新领取、打开详情及下载全部通过真实页面操作，不直接改 SN 指针：

1. 甲厂领取、打印 3 枚，下载原始文件并查看 3 枚详情。
2. 单枚转到乙厂，原批次与原文件均剩 2 枚，头数量仍为 3。
3. 乙厂重新领取、打印该枚，新文件 1 枚；甲厂旧文件仍为 2 枚。
4. 甲厂剩余整 PI 的 2 枚转到乙厂，甲厂旧详情为空、旧下载只有表头。
5. 乙厂整 PI 的 3 枚转回甲厂，再领取打印。甲厂旧记录和乙厂记录均为空；新记录按原创建顺序包含 3 枚。

每次下载前后核对业务投影不变；显示数量、业务单号和当前明细分别校验。CSV/XLSX 仅规范化两次独立操作生成的批次号，逐列比较原始行序，不按 SN 排序掩盖差异。下载标题和批次号另外核对实际界面记录，XLSX 单元格类型、冻结首行及 CSV BOM 均检查。ZIP 元数据和全部样式 XML 不声明逐字节一致。

## 诊断和边界

首次新场景两项失败分别是原型 radio 输入被可见标签覆盖、新版历史异步加载前读取批次号。第二次原型遇到两个工厂下拉框选项同时可见的定位歧义，新版已通过真实往返。限定下拉框 aria-controls 后，两项均通过；19 对下载文件核验通过。随后截图发现空状态图标及高度差异，已修正并加入几何断言。

第一次整组运行 10 通过、2 失败，失败为新版批量打印。增加仅记录 SN 操作路径、受控状态和任务状态的诊断后，确认后续 PI 被后台两个文件任务占用容量所拒绝。不是浏览器下载等待不足，也不是业务重复打印；修复后两项定向界面回归通过。失败报告保留，不将重复执行计为新用例。

第二次整组运行 8 通过、4 失败：第九项业务断言已通过，但当前下载提前完成后，后台固定产物仍在执行，原清理保护拒绝删除夹具；后三项因为夹具被保护保留而未能初始化。新增只读 active 查询，清理前等待真实工作器终态，原清理的活动任务、原数据摘要和所有权检查均保留。没有清空任务、修改租期或重置库来消除失败。
