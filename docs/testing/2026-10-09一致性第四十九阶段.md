# SN 一致性第四十九阶段 订单边界与三语页面

2026-10-09。本轮修复订单同步请求边界、定时责任人交接、订单查询缓存和三语页面差异。完整功能与页面一致性目标仍在执行，本轮有实际进展，无阻塞。

## 本轮修复

| 操作 | 当前行为及验证 |
| --- | --- |
| 缺省请求体、JSON null、空对象、null 单号 | 按原型执行全量同步；四种直接请求均实际对照。 |
| 显式空单号、普通或 Unicode 空白 | 返回“请输入单据编号”；拒绝发生在 ERP 查询和同步记录创建前。U+0085、U+001C 通过三语真实按钮检查，订单快照及 K3 查询次数不变。 |
| 定时间隔缺省或 null | 保留已有间隔；相同设置不重置下次执行时间。 |
| 定时间隔越界 | 作为业务拒绝返回并留痕；-1、0、9、10081、2147483647 均已对照，设置不变。10、10080 合法。 |
| 另一管理员保存相同启用状态和间隔 | 更新责任人，保持原下次执行时间；内部当前授权、控制版本和在途失效检查保留。双端界面实际执行交接。 |
| 失败操作痕迹 | 空白单号及间隔越界各独立记录一次；数量为空，记录真实请求路径及原型中文原因。页面查询、展开与直接 API 事实均有证据。 |
| 分页返回及相同条件再次查询 | 每次显式操作重新读取快照，修复 30 秒缓存导致返回已有页、重复查询不发起请求的问题。三语实际切换 100/20 条并连续查询两次。 |
| 中英越订单页面 | 修正同步/查询按钮字体、颜色、宽度，输入框及清除按钮，定时摘要标签和图标；表头恢复换行，表格固定 560 像素；对齐分页位置、尺寸、选项与选中标签。 |

控制器仅把缺失请求体规范化为全量命令，服务内部仍校验命令和当前权限。Unicode 空白使用既有 FactoryText 规则。错误码和 OpenAPI 已更新，生成类型通过工具重新生成。本轮没有数据库结构变更，V1—V41 原字节保持，下一版本仍为 V42。
