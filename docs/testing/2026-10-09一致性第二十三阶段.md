# SN 一致性第二十三阶段：转厂决策、固定明细与连续申请

2026-10-09。本阶段继续 P10，完成本轮申请、撤回、驳回、批准、固定明细分页和记录筛选的双端界面检查。**整体一致性目标尚未完成**；本轮没有把原型物料范围缺陷、剩余页面或未执行的边界视为通过。

## 实现与修正

- 转厂记录按原型提供状态即时筛选、PI 回车查询、绑定厂身份与方向、20/50/100 条设置，以及申请/处理工号、状态标签和固定操作列。源厂操作员可撤回；总部页面只显示审批/驳回，不显示源厂撤回。修正旧 UUID 撑宽列的问题，旧记录仍保留真实 UUID 兜底，不伪造历史业务号。
- 撤回仅确认，审批和驳回使用单行意见。取消不发起决策；审批弹窗打开前读取最新起号提示，成功反馈等待真实任务成功。修正起点后移但 `unused=0` 时隐藏提示的问题；本阶段为该判断补单元检查，跨 PI 的提示仍待专门界面验证。
- 新增 `GET /api/v1/sn/transfers/{id}/items/page`，默认 50 条，精确字符串总数，页码和数量受限。先验证整张转厂可见性，再读取固定成员与当前状态；同一个可重复读事务内取成员和总数。原游标接口保留，不需要 DDL。
- 780px 明细抽屉显示七列：完整 SN、进制流水、十进制流水、申请前状态、当前状态、当前挂靠、原领取批次号。按原流水归属、流水值和创建顺序排序。批准后单一源厂视角显示“已转出”，总部显示实际“待领取”；原批次号不因当前批次清空而丢失。
- 连续申请发现按钮残留透明加载图标，其辅助文本使按钮名称变成“loading 提交申请”。给按钮固定名称及忙碌状态，将加载图标标为装饰元素；真实连续三次申请验证通过。

## 界面实际操作

最终一次合并回归 **8/8 自动检查通过**，约 5.3 分钟，单工作器、零自动重试。由原型和新版各四项组成：既有直转往返/重领打印/历史下载、转厂表单、角色入口，以及新增申请决策闭环。物料表单检查仍明确记录原型缺陷，不能算作物料功能双端一致。

新增闭环在两端各使用独立的 51 枚待打印 SN 和同一个绑定厂操作员，通过实际页面完成：

1. 整 PI 申请 51 枚，全部变为申请中；查看 50＋1 条明细。
2. 撤回先取消再确认，取消保持申请中，确认后 51 枚恢复原厂、待打印及原领取批次；处理工号为操作员。
3. 对单枚 SN 再申请，总部驳回先取消再确认；恢复原状态，保存总部工号和输入意见。
4. 整 PI 再申请，总部输入意见并批准；51 枚归属目标厂、待领取，当前领取/打印指针清空。
5. 总部和源厂分别查看批准后的两页固定明细；验证总部待领取、源厂已转出，原批次号仍完整且一致。
6. 记录页选择 50/100 条，核对实际查询参数；状态选择即时过滤，PI 回车查询、空结果及恢复均检查。此处只有三张新记录，**没有证明超过 20 张转厂记录的实际跨页行为**。

管理员不能在页面撤回，源厂操作员不能审批或驳回；两种查询角色沿用本轮表单回归验证入口和只读约束。其他状态组合、目标厂查询员明细、并发决策与人员改名仍待界面验证。
