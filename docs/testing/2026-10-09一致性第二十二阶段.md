# SN 一致性第二十二阶段：转厂表单、展示身份与结果恢复

2026-10-09。本阶段继续完整一致性目标，推进 P10 转厂表单与直转流程。**转厂页及整体目标仍未全部完成**。本阶段界面检查包含一个已证实的原型缺陷，检查通过不等于该分支双端一致。

## 已实现

- 候选随来源厂、PI、范围、物料或单枚 SN 自动加载；MATERIAL 候选同时保留整张源 PI 的物料目录，切换选择不会把目录缩成当前物料。新增目标 PI 重号数量和最多五个按 SN 排序的样例；仅检查当前来源可见且可转的号，不开放目标库存枚举。计数与目录在可重复读事务中读取，正式提交仍重新校验并整批回滚冲突。
- 表单改为来源/目标双栏及卡片页签，范围为 PI/物料/单枚单选；工厂操作员显示绑定厂且不可修改。原因位于目标栏，必填条件、零可转或重复完整 SN 阻止提交；确认提示显示工厂名称。状态标签、提示背景、主要留白和窄屏单栏已调整；仍有几像素间距、字重及历史表格等外观差异，未声称全像素一致。
- V32 为转厂头增加可空业务单号、申请工号和处理工号快照。新单号为 `T + 上海时间十四位 + 四位随机尾号`，与共享业务单号表和业务写入同事务。请求/任务 UUID 不变；旧号缺失不伪造，只回填仍存在的可信账号工号。后来改名不会重写已记录的工号。
- 原任务成功并读取到转厂记录后显示单号/数量，清空原因并自动切到记录页。记录显示业务号、工厂名、申请/处理工号和上海时区时间。结果读取失败保留查询入口；页面刷新按持久操作号恢复原记录，不提交第二次转厂。

## 双端界面证据

最终一轮 **6/6 自动检查通过**，约 3.5 分钟，单工作器、零自动重试。包括两端三次真实直转（单枚 1 枚、整 PI 剩余 2 枚、整 PI 返回 3 枚）、转后重领打印/历史重下，表单候选、单枚不存在/存在、空 PI、确认取消、900px 窄屏，以及工厂操作员和两种查询员视角。工厂操作员在此仅验证绑定厂/候选/按钮资格，**尚未执行申请与撤回**。

新版另注入一次转厂结果 GET 的 HTTP 503：数据库已成功产生一条转厂记录，页面显示读取失败；刷新后恢复同一单号，仍只有一条记录。后续两次转厂与重领、打印继续完成。该项为新版异步协议恢复检查，原型同步接口没有伪造相同故障，不能据此声称未知 POST 响应和所有恢复时序均已验证。

证据包含 **53 张截图**、**25 对业务投影**（19 对原始相同，其余按同 PI 历史多重集合对照）、**7 对原顺序详情 DOM**，以及 **19 对完整下载文件**，其中 6 对为只有表头的空文件。文件逐列、单元格类型、原始行序和 CSV 编码比较；只对两系统独立产生的业务编号作明确归一化。

## 原型物料范围缺陷（未作为一致项通过）

原型首次选择“PI＋物料”时，`frontend/src/api/index.ts` 的通用 `clean()` 丢弃空字符串 `material_code`；`app/services/transfers.py` 又要求 MATERIAL 必须提供这个参数。界面得到 HTTP 400“按物料转移时物料编码必填”，清空候选后，物料下拉也没有选项，无法继续从列表选择。已通过真实页面与响应记录复现。

新版保留空物料参数并独立提供整源 PI 的物料目录，可选 `CMP-ACQ-MAT-1`，正确得到 1 枚候选。此行为有意保留可用性，但目前与原型缺陷行为不同；测试在两端分别验证并保存 `material-known-difference.json`，没有把它伪装成一致。原型源码未修改，物料实际转移的双端闭环仍未通过。
