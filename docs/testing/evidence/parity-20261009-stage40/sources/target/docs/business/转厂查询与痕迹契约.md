# 转厂、查询、操作痕迹与首页

维护日期：2026-10-09。本文为当前说明；本轮规则见[SN补迁契约](SN补迁契约.md)，验证和未完成项见[当前发布记录](../releases/2026-10-04本地交付.md)。历史阶段原文已另行冻结归档。

当前实现契约，承接三份v1.1来源及[S5 MES契约](MES领取与打印契约.md)。以下人员接口前缀均为`/api/v1/sn`，使用当前可撤销人员身份。SERVICE只能使用已定义的MES入口。业务ID、版本、数量和流水按精确字符串交换；错误码仍为整数。

## 转厂

| 接口 | 权限与输入 |
| --- | --- |
| GET /transfers/candidates | `sn:transfer:view`；factoryId/pi/scope，MATERIAL时material（空表示无物料），SINGLE时完整sn；可选toPi用于当前来源可转SN的重号预警 |
| GET /transfers/factories、/targets | `sn:transfer:targets`；最少交接目录，完整分页；不授予目标厂SN读取资格 |
| POST /transfers、/transfers/direct | 分别apply/direct；operationId、factoryId、pi、scope=PI/MATERIAL/SINGLE、material/sn、toFactoryId、toPi、toCustomer/toMaterial、targetSource=MANUAL/SNAPSHOT、reason |
| POST /transfers/{id}/withdraw、/reject、/approve | 对应withdraw/reject/approve；operationId、version、note |
| GET /transfers | view；factoryId/pi/status/page/size，历史原转出或转入工厂可见 |
| GET /transfers/{id}、/{id}/items | view；固定头/成员与独立当前投影；成员cursor/size完整读取 |
| GET /transfers/{id}/items/page | view；page 从 1 开始，size 默认 50、范围 1—1000；先验证整张转厂可见性，再返回固定成员总数及当前投影 |
| GET /transfers/operations/{kind}/{operationId} | APPLY/DIRECT/APPROVE/REJECT/WITHDRAW；原主体与当前动作权限 |

`/targets` 返回 `TransferSnapshotVO`：工厂 ID/编码/名称可共同为空，同时返回生产组织、客户、PI、物料编码和名称。仅列出当前有效且客户、PI 非空的订单分录，按组织/工厂、客户、PI、物料合并，物料名称取最大值；按 PI、物料排序。搜索匹配 PI、订单号、物料编码、客户，`%`、`_` 按字面值处理。组织使用 ERP 稳定映射，未映射组织保留候选；名称匹配不是授权依据。接口保留完整分页，默认每页 50、最大 100；页面遵循原型每次显示前 50 条，用搜索定位其余候选。

`/factories` 继续返回启用工厂的 `TransferTargetVO` 分页目录。快照行中未映射的工厂不会被伪造为可提交目标；页面可回填其它字段，待用户手工选择工厂后标为 `MANUAL`。点击快照行标为 `SNAPSHOT`，后续手工改目标字段改为 `MANUAL`。实际提交仍重新检查工厂资格和当前快照，目录读取本身不授予库存访问或转移权。

整PI、PI+物料、单枚SN只选择来源厂+PI中TO_ACQUIRE/TO_PRINT/PRINTED且未被其他转厂冻结的成员。提交任务时按稳定顺序占用源、目标两个PI，原子执行时确定固定成员。APPLY冻结为APPLYING，状态PENDING；APPROVE或DIRECT整批转为目标厂PI的TO_ACQUIRE，清当前领取/打印/时间，写入精确SN+月份+目标厂PI领取例外。REJECT/WITHDRAW逐成员恢复申请前状态和原指针，保留固定历史。

APPROVE、REJECT、DIRECT须具有该动作的全部工厂范围；APPLY/WITHDRAW要求源厂资格，不能用目标厂只读范围写源厂。撤回不绑定原申请人，但要求当前源厂该动作资格。目标须启用，目标PI必填；空客户/物料逐成员沿用，不能误解为空字符串覆盖。快照目标必须仍精确匹配当前有效订单分录；不匹配按手工目标处理，并保留实际targetSource。

目标当前PI+完整SN冲突整批拒绝。护栏更新当前PI，不删除重建；seqPi/seqDec、来源身份、原领取/打印成员、水位和额度保持原事实。同厂同PI且全部字段无变化拒绝。新版错误：1004000023条件已变化、24无可转成员、25没有实际变化；碰撞复用1004000015，PI占用复用1004000014。软件不替工厂处理已经打印的实体标签。

## SN查询和固定导出

GET `/items`、`/items/page`和`/items/count`使用`sn:query:view`。过滤包括factoryId/customer/pi、materialMode=ALL/EMPTY/VALUE及material、status、精确sn、billNo、当前batchId（内部UUID）、batchNo（业务批次号）、piAll。数量是精确字符串。piAll必须指定PI，非全部范围人员必须在自己的当前工厂范围拥有该PI；排除未分配工厂的行。该只读例外不影响写权限。

原`/items`保留签名游标协议。页面使用`/items/page`：page从1开始，size默认20、范围1—1000，返回items/total/page/size/totalCapped；计数最多读取100001条，total封顶100000，超限明确标记。无PI条件按SN创建顺序倒序；指定PI时按物料、原流水归属PI、十进制流水、创建顺序升序。行投影增加currentBatchNo，工厂显示名称，生成/打印时间按上海时区展示。V31以前已有记录的创建顺序仅为迁移时赋值，不能据此声称重建了原型历史生成顺序。

查询按钮和翻页按当时输入提交；导出独立使用点击时的筛选草稿。空白物料输入表示不限物料，API的EMPTY模式继续保留。页面每页20/50/100/500条，改变页大小回到第一页。原型在末页改大页大小时可能同时请求第一页和新的末页，最终结果取决于响应顺序，此竞态单独留在一致性验收待办；新版不复制并发覆盖竞态。业务批次号按本系统真实批次查询，不能混用另一套独立数据库生成的编号。

POST `/exports`使用`sn:query:export`并要求view，输入`{operationId,format:"CSV"|"XLSX",filters}`。快照范围求两个动作的交集。GET `/exports`为本人历史，`/exports/operations/{format}/{operationId}`查询原操作。默认最多100000行，产物16MiB；超限明确失败，不静默截断。新导出按创建顺序升序固定全部行，文件名为sn_export.csv/xlsx，使用原型11列：序号、完整SN、进制流水、十进制流水、PI、物料编码、客户编码、工厂、状态、领取批次、来源订单；Excel工作表名SN。

查询固定快照在授权协调/快照控制保护下分块读取。提交成功时operationState=SUCCEEDED表示固定快照已确认，文件可能仍PREPARING；页面等任务成功且文件READY后自动下载。CSV文本防公式解释；XLSX序号和不超过15位的十进制流水为数值，SN、进制流水等业务编码及更长流水保留文本精度。恢复使用原任务ID，校验既有摘要与字节数。下载及恢复复核原提交者、view/export和全部快照原范围，SN后来转到其他工厂不会转移文件权限。

V33增加sn_query_export.format_version：已有记录为1，继续按旧22列表头及文本Excel恢复原文件；新记录写2并使用上述11列。升级不会重写旧快照、旧文件或其摘要。完整异常恢复与角色界面验收按当前一致性清单继续执行，不能以本段接口说明代替全场景通过。

## SN操作痕迹

`/audit`页面与平台`/system/audit`分开：前者按工厂呈现SN业务事实，后者保留认证、配置、入口安全和平台管理日志。V12开始由通用审计观察端口同事务追加SN事实；成功投影写入失败则回滚业务，失败事件独立记录且不覆盖原错误。来源事实来自服务已提交/同事务固定记录，不从HTTP请求体猜测。之前的开发日志没有自动伪造回填；旧生产历史由S7迁移流程处理。

GET `/audits`、`/audits/page`、`/audits/count`、`/audits/{id}?createdAt=`、`/audits/meta`使用`sn:audit:view`。保留原日期、action/operator/factoryId/pi/source/result/batchId/keyword筛选，新增storage=ALL/ONLINE/ARCHIVE。日期是上海自然日，默认结束日为今天、起始日为前30日，结束日包含当天；数据时间以UTC存储。关键词按原约定查起止SN、操作号、转厂号、来源订单和安全详情，`%/_`按文字搜索。

页面使用 `/audits/page?page=1&size=20`，总数和当前页在同一可重复读事务及当前工厂权限下读取，按创建时间倒序，同时间按V34新增的写入序号倒序，再以记录ID兜底。总数以精确字符串返回；服务允许1—1000条，页面提供20/50/100条。查询及翻页提交当前筛选草稿，详情在原行下展开；顶部Excel按钮使用点击时草稿自动下载，不改变此前已查询列表。旧游标接口继续使用时间/ID排序。旧数据没有写入序号，不猜测其历史顺序。

批次筛选兼容内部ID和业务批次号；详情显示业务批次号与转厂单号，关键词可查询业务转厂单号。通过固定业务记录解析展示编号，保留内部指针；未能解析的编号为空。详情JSON只移除引号外空白，保留文本、转义和精确大数字，不改变原事实。完整动作事实、真实业务编号的双端界面验证及异常恢复仍按当前验收清单继续执行。

历史固定操作人工号/姓名/角色、来源、动作/结果、原工厂/目标厂/PI、客户/物料/订单、SN集合边界、数量、状态变化、批次/操作/转厂号、原因、错误码和traceId。混合客户/物料为null；起止SN是命令边界或固定集合最小/最大文本，不证明中间全部连续；取消任务不记录已完成的SN状态变化。详情使用白名单JSON或下述规则纯文本，不记录凭据、完整请求体、数据库异常或SQL。

V35起，成功规则操作按原型分别记录新增、未使用版本修改、已使用版本升版、改名。一次同时修改内容和名称产生两条SN痕迹；没有变化不追加SN痕迹，平台字段差异记录仍按原机制保留。规则详情固定为原型描述文本，保留空格；数量为null，不能补为0。新增时才记录PI/客户绑定，更新记录不继承该字段。记录、写入序号和业务修改同事务，第二条记录失败时全部回滚。旧审计事实不回填。V36补齐真实登录和改密事实；其他平台事件、其他业务失败原因仍按验收清单补齐。

当前工厂权限匹配原厂或转入厂；无工厂的全局事实仅全部工厂范围可读，不开放piAll例外。归档使用同一过滤/权限。ALL在在线与归档暂存重复时按时间+ID去重，详情仍按历史原键读取。当前永久保留；归档查询不意味着可以删除，归档写入/核对/备份见当前维护与恢复文档。

POST `/audits/exports`同查询导出的格式/操作号模式，要求view/export，按每条事实分别满足两个动作的原厂或目标厂资格。使用单条INSERT SELECT的一致视图固定快照，避免独立失败审计并发追加造成跨页不一致。新导出按写入序号倒序，缺少序号的旧记录以时间/ID兜底；这与页面优先按时间排序有意区分，对应原型导出自增ID倒序。GET `/audits/exports`及`/audits/exports/operations/{format}/{operationId}`查询本人记录/原操作；下载使用通用文件接口。固定快照不随在线归档搬迁或身份改名变化。

审计导出独立上限默认200000行，由`ADTEK_SN_MAX_AUDIT_EXPORT_QUANTITY`配置；不再借用生成批次数量上限。新文件固定原型24列、文件名`audit_export.csv/xlsx`、Excel工作表`audit`并冻结首行；上海时间文本、原型角色/动作/结果投影、业务编号在固定快照上生成，未知角色/动作不猜测。CSV文本防公式解释，数量列保持数值语义；XLSX数量在15位以内为数值，长整数为精确文本，其余文本即使以等号开头也不成为公式。

V34增加`sn_audit_export.format_version`和审计写入序号。已有导出为格式1，继续按原28列恢复；格式2保留最初24列写法，格式3增加空文本单元格语义，格式4再匹配本机Windows原型XLSX读回的CR换行语义（CR→LF，原CRLF读回两个LF）。CSV不作这项替换；数据库快照不改。V35起新建格式5，在固定快照末尾增加JSON/TEXT标记，输出仍为24列；纯文本详情保留空格，JSON沿用原压缩规则。已有1/2/3/4版本继续使用各自写法和原摘要，重放原操作不创建新版本；未知版本拒绝。此约定描述当前本机原型实际产物，并非跨平台原型运行时均有相同换行行为。完整容量、其他真实动作事实、角色与恢复界面验收仍未完成。

## 首页和会话

GET `/dashboard`使用`sn:dashboard:view`。在途状态限定当前工厂范围；生成/导入全局累计仅全部工厂范围返回，其他为null。待审批需同时具备转厂view，按其范围与首页范围求交。最近生成任务只开放给generation:view全部工厂范围，仍套用首页范围。今日作业来自成功业务事实、领取/打印/转厂固定记录，按Asia/Shanghai当天计算；当前SN状态变化不会改写过去的作业数量。页面30秒刷新，不显示全局后台任务内部数据。

V10—V12增加角色菜单并推进既有SN角色账号的security_version；用原密码重新登录获得新菜单。原管理员密码和持久卷不变。V1—V12已应用后冻结，后续只能新增迁移；此契约不表示真实ERP/MES、容量、人工UAT或生产切换已经验收。


## V32 转厂展示与候选补齐

`TransferVO` 增加可空 `transferNo`、`actorName`、`decidedName`。新单号为 T + 上海时间十四位 + 四位随机尾号，执行时与业务同事务固定；工号从可信身份查询，不接受前端传入。旧号缺失仍为 null，页面以 UUID 兜底，不宣称重建历史原号。

候选响应增加 `materials`（当前源厂和整张源 PI 的去重物料，包含空串）、`duplicateCount`（精确数字字符串）、`duplicateSamples`（按 SN 排序，最多五个）。物料目录不随选中的物料或单枚范围缩小。只有目标 PI 非空且不同于源 PI 时，才检查当前来源可转 SN 是否已占用目标 PI 的完整 SN 护栏。查询先检查来源权限，在同一个可重复读事务内取计数与目录；提示不预留号，提交时仍重新检查并整批回滚冲突。

页面根据来源自动加载候选，支持 PI/物料/单枚单选范围；必填、零可转或重号时不可提交。正常完成以原任务成功并读取转厂记录为准，然后显示业务单号/数量、清空原因并切换记录。未知响应保留原意图恢复入口，不重复创建业务。转厂记录显示新单号、工号及上海时区时间。原型首次切换物料范围会因空参数清洗报错，这一来源缺陷正单独留证，尚未作为双端一致项验收。

跨 PI 且当前主体具有目标目录权限时，页面等待独立起号提示请求完成后才允许提交；提示请求失败时显示错误并保留禁用，避免候选先返回造成漏确认。起号后移时，即使连续转入导致跳号数为 0，表单与确认仍显示前后起号。转入改变当前 PI，不推进原流水归属的计数器；目标后续生成根据实际转入号码避让。提示不是号段预留，提交仍重新检查当前事实。

快照搜索等待真实请求时保留上次候选，可关闭重开并保留输入；同一身份与授权版本内才可使用上次数据。身份或授权版本变化不复用旧目录。此行为不表示网络失败、乱序响应或权限变化的全部组合均已完成界面验收。

## 转厂决策与分页明细

记录页默认每页 20 条，可选 50/100；状态和工厂变化即时查询，PI 支持回车查询及清空。绑定工厂账号不显示工厂筛选，方向按其绑定厂判断，不借总部筛选条件伪造“转入/转出”身份。待处理单据的总部审批/驳回与源厂撤回分别受当前动作权限限制；总部页面不显示源厂撤回按钮。

审批和驳回使用单行意见输入，撤回仅确认；取消不发起决策。审批打开确认前重新读取目标起号提示，只有原任务成功才显示完成。起点后移即提示，不能因为连续转入导致 unused=0 而省略提示。

明细抽屉每页 50 条，显示完整 SN、进制流水、十进制流水、申请前状态、当前状态、当前挂靠工厂/PI、原领取批次号。按原流水归属、流水值及创建顺序稳定排列；总数来自转厂固定成员，批准后仍可查看全体原成员。单一源厂范围账号在批准后看到离开本厂的成员为 TRANSFERRED_OUT，总部看到实际当前状态；这只是授权视角的展示，不写回 SN 状态。原批次号通过固定成员保存的原批次指针解析，当前批次清空不丢失申请前的批次信息。读取处于可重复读事务，旧游标明细接口保留。

本次无需 DDL，V1—V32 保持原字节。完整界面验收仍须结合当前一致性清单，不能将这些接口说明等同于全页面、所有角色与所有边界均已通过。

V36增加在线与归档审计error_message，并允许匿名actor_id为空。登录成功、错误密码、未知工号、停用、达到锁阈值和已锁定的详情固定为原型语义；改密的成功及三种密码规则拒绝也入SN痕迹，数量保持null，改密不填写工厂。新建导出使用格式6，新增认证动作与匿名角色的展示映射，固定快照仍为25项、输出24列；旧1—5分别恢复原字节。改密直接取得新会话，页面不再额外登录。完整角色组合、请求校验/依赖异常、账号管理事件和其他真实动作继续按完整验收清单处理。
