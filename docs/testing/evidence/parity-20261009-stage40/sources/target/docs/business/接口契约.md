## 协议与错误号段

统一 JSON：`{code,message,data,params,traceId}`。code 是 int32，0 为成功；失败 data=null。message 是稳定消息键，客户端使用 code+params 本地化，不用 message 文本判断业务。traceId 由服务器生成，不接受来访者指定的可信追踪号。业务 ID 和部门 ID 为精确字符串，deptId 可以为 null；不能先转成 JavaScript number。

| common | 1000000000—1000999999 |
| system | 1002000000—1002999999 |
| framework | 1003000000—1003999999 |
| sn | 1004000000—1004999999 |

ErrorCodeCatalogTest 检查当前装配模块的重号、越界、HTTP 状态和消息命名。旧 97 枚举及额外边界的逐项映射已登记，原文见归档的旧错误码兼容登记；业务新错误继续使用独占号段。

## 人员认证

前缀 `/api/v1/system/auth`，JSON 编码 UTF-8。工号按 ASCII 字母/数字/下划线/短横线 2–32 位精确匹配，不自动 trim 或忽略大小写。所有返回资料来自当前 MySQL。

| 方法与路径 | 输入 | 成功 data | 认证/副作用 |
| --- | --- | --- | --- |
| GET /csrf | 无查询参数 | headerName、token | 公共同源入口，设置 HttpOnly CSRF Cookie；无 HttpSession |
| POST /login | username、password | accessToken、tokenType=Bearer、expiresAt、profile | CSRF；核验哈希/账号状态，创建 Redis 会话，成功审计 |
| POST /refresh | ADTEK-REFRESH Cookie | 同登录 | CSRF；原子轮换，旧凭据重放撤销整个会话，禁止自动重试 |
| GET /me | Bearer | id、username、displayName、deptId、language、mustChangePassword、permissions、authorizationVersion | 授权版本为字符串，用于前端缓存隔离；不返回 Entity 或 passwordHash |
| POST /password | oldPassword、newPassword | accessToken、tokenType、expiresAt、profile | Bearer；锁本人行，核验旧密码并增加 securityVersion，同事务审计，签发当前版本新会话及刷新 Cookie；不追加登录动作 |
| POST /language | language=zh-CN/en/vi | null | Bearer；锁本人行，按实际前后值保存白名单 diff |
| POST /logout | 无业务字段 | null | Bearer；撤销当前 Redis 会话，成功审计，清除刷新 Cookie |

新密码为 8–64 个 Unicode code point，至少有一个 ASCII 字母和数字，不接受控制字符，新旧密码不能相同。PBKDF2-HMAC-SHA256 600000 次、随机 16 字节盐，通过 Spring PasswordEncoder 保存算法标识；没有明文密码或通用默认密码。明确标记的旧 PBKDF2-120k 哈希支持成功登录后升级；旧库导入身份始终停用，本轮不搬旧账号。裸哈希和未知算法拒绝。

access token 有效期 15 分钟，HS256，固定 issuer/audience，校验 nbf/exp/签名/主体/版本/sid。每个 Bearer 请求另外核验 Redis 会话和 MySQL 当前账号、版本、角色；JWT 不携带可独立授权的权限快照。刷新会话寿命为最后成功轮换起 8 小时。修改密码后所有旧版本 access/refresh 都会被拒绝，不能仅依赖 Cookie 删除来宣称撤销完成。

刷新 Cookie 路径 `/api/v1/system/auth`；HttpOnly、SameSite=Strict，生产默认 Secure。只有显式 local/integration-test 且绑定回环地址时允许 HTTP。标准 Bearer 请求不依赖 Cookie 授权，浏览器客户端仍在每次写入前获取新的 CSRF token；标准认证策略可能使旧 CSRF Cookie 失效。前端只在内存保存 access token，不自动重试业务写入或刷新请求，多标签页通过 Web Locks 串行刷新，通过 BroadcastChannel 通知注销。

首次改密账号可以读取本人资料、改密、语言设置和注销；用户管理、SN用例和当前菜单拒绝尚未改密账号。已实现SN接口见本文S3/S4节，仍按各自权限和范围授权。

## 用户管理

前缀 `/api/v1/system`。所有接口需要有效 Bearer，管理操作还需要对应权限。用户 ID、部门 ID、角色 ID、version 和 total 全为十进制字符串；工号创建后不可编辑，没有删除接口。

| 方法与路径 | 输入 | data / 语义 |
| --- | --- | --- |
| GET /users | page=1、size=20（1—100）、keyword（最多64字符）、enabled（可省略） | PageResult：items/total/page/size；system:user:list，按此权限的部门/本人范围过滤 |
| GET /users/options | operation=add 或 update | 对应权限可选部门及角色；security:administer 才返回角色目录，提交仍须反提权复核 |
| GET /menus/current | 无 | 当前授权页面菜单；客户端只注册已实现页面 |
| POST /users | username、displayName、deptId、roleIds、password | ManagedUserVO；add 权限，非空角色绑定另需 security:administer；新账号启用且强制改密 |
| POST /users/{id}/update | displayName、deptId、roleIds、version | null；update 权限，修改角色另需 security:administer；成功递增安全版本 |
| POST /users/{id}/status | enabled、version | null；status 权限，禁止本人停用及最后管理员失效 |
| POST /users/{id}/password | password、version | null；reset 权限，禁止本人重置；目标旧会话失效并强制改密 |

ManagedUserVO 包含 id/username/displayName/deptId/deptName/enabled/mustChangePassword/version/roleIds，deptId/deptName 可为空。越范围目标返回404；逐权限比较目标现有及变更后的部门/工厂范围，超出操作者授权返回403。未提交当前版本返回409；前端不得无提示自动重试写操作。

新增错误：1002000007 工号重复（409）；1002000008 页面版本冲突（409）；1002000009 本人保护（409）；1002000010 最后管理员保护（409）；1002000011 超出授予/管理范围（403）。角色/部门不存在或停用返回400。MyBatis 缺失范围规则/上下文或解析失败为1003000006（403）。

用户管理成功审计随业务事务提交；UPDATE 只存注解白名单实际变更，密码及哈希不进入 diff。用例内部失败独立记录受控错误码；HTTP 入口拒绝统一记录未被用例审计覆盖的失败，事务提交成功后才标记已记录。事务提交或审计存储故障保留请求 traceId，不能宣称失败审计必定成功。

## 系统配置

前缀仍为 `/api/v1/system`。以下目录提供 GET 列表、POST 新建及 POST `/{id}/update` 修改/启停。新建不传 version，修改必须传原 version；ID/版本和关系 ID 全部为字符串。返回 ConfigurationChangeVO：id、reauthenticate；后者为 true 时当前会话已经失效，客户端结束会话并提示重新登录。

| 目录 | 所需权限 | 配置字段 |
| --- | --- | --- |
| /roles | system:role:list / update | code/name/enabled/dataScope(1—5)/factoryScope(1—2)/menuIds/deptIds |
| /departments | system:dept:list / update | name/parentId（空为根）/enabled |
| /menus | system:menu:list / update | name/parentId/menuType(M/C/F)/permission/path/component/sortOrder/enabled |
| /dictionary-types | system:dict:list / update | code/name/enabled |
| /dictionary-items | system:dict:list / update | typeId/value/labelZh/labelEn/labelVi/sortOrder/enabled；GET 另需 typeId |

还必须拥有 system:security:administer，且对应操作和安全管理两项权限均为 ALL 部门范围。配置是全局数据，无所属部门，不能以局部用户管理权限访问。每目录最多 1000 项，值按所属字典限制；达到创建上限或读取发现超限返回409，绝不返回截断结果。关系集合最多100项，服务去重并按 ID 排序。

角色编码、菜单类型/权限标识、字典类型编码、字典值及所属类型不可修改；没有物理删除接口。自定义部门允许空集合，其他部门范围必须提交空 deptIds。角色所选权限必须在操作者当前授权内且该权限具有 ALL 部门范围，工厂范围另受授权上限约束。关联账号的现有及变更后权限也必须在操作者范围内。

部门/菜单拒绝循环、失效父节点及非法节点类型，停用存在启用下级的节点返回409；部门存在启用用户时也不能停用。M 无权限/组件/路径，C 的权限、组件和路径须匹配本地注册表，F 无组件/路径。审计组件 system.audit 对应 /system/audit 和 system:audit:list。字典类型停用后值保留可读，值的写操作返回409。

新增错误：1002000012 配置版本冲突、1002000013 唯一值重复、1002000014 树/引用冲突、1002000015 配置容量限制，均为409。越权403、缺对象404、无效字段400、依赖故障503；审计失败不提交配置变更。创建审计为 INSERT，编辑为 UPDATE；实际关系 ID 集合与字段 diff 随业务事务提交。

## 操作日志查询

前缀 `/api/v1/system/audits`，有效 Bearer、已完成首次改密且拥有 system:audit:list。按此权限的五类数据范围查询，不额外要求 security:administer。没有编辑/删除接口；独立导出命令见下节。

| 方法与路径 | 参数 | data / 语义 |
| --- | --- | --- |
| GET / | page=1（1—10000）、size=20（1—100）、from/to、action、module、actorUsername、userId、traceId、success | PageResult；所有筛选精确匹配、参数绑定，列表不返回原始 changes |
| GET /options | from/to | 同一范围和时间窗的 actions/modules 去重选项；各最多200，超限返回409/1002000016 |
| GET /{id} | 正数十进制字符串 ID | event、changes、reason、failureCode、redacted；不存在或越范围均404 |

from/to 同时省略默认最近7天；显式传入须为带时区的 ISO Instant、from < to 且间隔不超过31天，采用 [from,to) 半开区间。可以查询任意历史31天窗口；详情按 ID 查询不限制时间。traceId 须为 UUID；userId 保持字符串并校验有符号 BIGINT 上限。非法参数返回400。元数据只使用时间窗，其余列表过滤不改变选项集。

AuditLogVO 的 id/userId/actorDeptId 以及分页 total 为精确十进制字符串；旧记录或匿名主体相关字段可空。包含追加时工号与部门快照、模块、业务类型、动作、对象、结果、服务器 traceId、UTC createTime，以及可空 requestMethod/requestRoute/httpStatus/errorCode。HTTP 状态和错误码为整数。部门范围按历史快照过滤，SELF 按 user_id；NULL 部门不会自动归入用户当前部门。

详情 changes 为 `{field,before,after}` 数组，前后值是安全文本或 null。服务端只投影已知白名单字段的合法结构，布尔改密标志与关系 ID 集合分别校验；不直接返回原始 JSON。未知/畸形/超限内容被省略并设置 redacted=true，原始数据库记录不改写。reason 只允许 credentialsRejected，failureCode 只允许受控数字码或 internal。

| 方法与路径（/api/v1 前缀） | 语义 |
| --- | --- |

| GET /tasks/{id} | 本人任务且当前完整业务范围满足；不是任意任务/输入查询，不返回存储路径或输入JSON |
| POST /tasks/{id}/cancel | 只允许尚未领取的QUEUED，200 + TaskVO，其余409；停止浏览器轮询不取消任务 |
| POST /tasks/{id}/recover | 仅已SUCCEEDED操作的文件恢复，原任务/文件/结果引用不变；重新授权与准入，200 + TaskVO；在途恢复同任务返回当前状态 |
| GET /files/{id} | 当前本人+完整快照范围，READY及完整摘要/长度校验；成功为UTF8 CSV附件，禁止缓存；失败输出前统一Result |

导出须同时具备 system:audit:list 与 system:audit:export，快照为两者部门/本人范围交集。每次重放、工作器、任务查询、恢复及下载均重新检查当前两项权限和整个固定成员集合，不能以文件创建者身份永久放行。跨主体任务/文件404，当前范围不满足403。首次改密账号不能提交或读取任务。首期只支持USER主体和登记的 SYSTEM_AUDIT_CSV 类型，不开放通用HTTP任意任务提交或管理员跨主体排障。

操作号与服务器 traceId 分开；列表筛选中的traceId是被导出日志的业务筛选，因此纳入载荷，HTTP追踪头不纳入。v1规范化将时间转UTC Instant、字段按键排序、空字符串归为null、UUID小写，保留布尔false；分页参数不存在于命令。相同主体+动作+operationId同摘要返回原任务/终态，异摘要409/1003000007。重放不能改变筛选或因源日志变化重新捕获数据。

一次提交最多10000行、16MiB，超出返回409/1003000014且登记/快照整体回滚，不截断。默认最多3个本人在途任务、全局1000；包含文件恢复准入。执行尝试至多3次/总预算300秒，暂时IO/数据库错误在同任务下等待3秒重试。业务拒绝或预算耗尽终态FAILED，调用方修改条件后使用明确的新意图/新操作号；不能删除失败号重用。

TaskVO 中 taskId/operationId/fileId/resultRef 是UUID字符串；attempt/executionEpoch/processed/byteSize/rowCount 是十进制字符串，errorCode为可空int32，createdAt为UTC时间。操作、执行、文件状态分别返回；processed只表示当前代进度。文件恢复时 operationState=SUCCEEDED 仍保持原成功，state可重新QUEUED/RUNNING，fileState=RECOVERING；不重复提交业务成功审计。

文件发布后READY尚未提交的故障可核对已发布对象重用；READY但丢失/损坏时下载返回409/1003000013并标RECOVERING，由显式恢复命令重建同一快照。恢复前先校验原摘要，异常快照不能替换原文件。下载成功使用 Content-Disposition 附件名和Content-Length；每个64KiB块重新授权，已输出后拒绝关闭流并日志追踪，不能再返回JSON或撤回已发字节。前端完整接收、检查类型/长度后才保存，JSON错误不作为CSV下载。

CSV固定英文字段：id/created_at/user_id/actor_username/actor_dept_id/module/action/success/object_id/trace_id，不包含原始JSON或密码。UTF8、CRLF、双引号转义；自由文本危险公式前缀加单引号，ID原字符保持不变。CSV是程序交换格式，电子表格需按文本导入ID，当前没有XLSX。

新增framework错误均为409：1003000007操作号冲突、1003000008任务容量、1003000009不可取消、1003000010尝试/时间预算、1003000011代次失效、1003000012文件未就绪、1003000013文件需恢复、1003000014行/文件资源上限。权限403、跨主体/缺对象404、非法输入400、依赖故障503。

## 入口失败审计

当前同步 /api/ 请求的认证、CSRF、限流、方法权限、参数/JSON、业务和未处理异常拒绝，如果尚无已提交的独立失败审计，追加 http:REJECT（4xx）或 http:FAILURE（5xx）。安全防火墙链外拒绝另以匿名主体和 /api/** 记录。只取完成认证的 Actor；不将未验证令牌、提交工号或伪造请求头当主体。

只保存白名单 HTTP 方法、服务器路由模板、状态、受控错误码和服务器 traceId；不保存原始路径、查询参数、请求体、响应体或凭据。入口失败 changes={}，已有业务失败保留其白名单语义，不再额外产生同请求入口记录。审计库不可写时保留原拒绝并发出仅含 traceId/异常类型的告警。容器/网络在应用外拒绝和未来异步流程未覆盖；响应失败不证明业务事务回滚。

## 限流和失败语义

| 策略 | 每主体 / 60 秒 | 每来源 / 60 秒 | 主体 |
| --- | --- | --- | --- |
| auth-login | 8 | 100 | 精确工号 |
| auth-refresh | 30 | 100 | 验证格式后的会话 ID，不使用刷新秘密 |

来源仅取 socket remoteAddr；server.forward-headers-strategy=none，不信任用户自带 X-Forwarded-For。Redis Lua 使用服务器时间和滑动窗口原子计数。来源预算在 CSRF/JSON 解析前执行，主体预算由 Service 的 @RateLimiter 执行；不使用共享“匿名用户”键。429 带 Retry-After 秒数与 params.retryAfter。

401：凭据/会话/账号版本无效；403：权限或 CSRF 拒绝；400：无效参数/密码策略；409：重复初始化；503：会话/限流/数据库连接依赖不可用，不能降级为信任旧权限。未知异常返回通用 500 与 traceId。

Redis 与 MySQL 没有分布式事务。登录在返回前失败可能留下不可见的短期会话，依靠 TTL 回收；刷新已轮换但响应丢失时，不得重放旧凭据，需要重新登录。注销时 Redis 已撤销而审计失败可能返回失败，不能据失败响应假定原令牌仍有效。失败登录审计使用独立事务；审计本身失败时保留认证拒绝，受控日志记录原因，不宣称已持久留痕。

## 页面领取与文件

## V26 当前工作区：按数量分配和生成历史

`AllocationDTO.quantity` 是可选精确正整数字符串。省略时保持旧整单行为与 v1 幂等摘要；显式传入时使用包含 quantity 的 v2 摘要，相同 operationId 不可换数量。`expectedQuantity` 始终是页面看到的全部待分配数，提交时必须与库中当前总数一致。quantity 超过 expectedQuantity 返回 `1004000029`；待分配总数或固定成员变化继续返回 `1004000019`。

资源准入按本次 quantity 检查，不再用全部待分配总数阻止小批分配。固定集合按流水升序取前 quantity 枚，余下成员保留待分配；分配成功只增加相应稳定来源台账。执行失败整批回滚，重复提交返回原任务，不再次分配。

`SnWorkVO` 新增必返字段：`actorName`（可空可信工号快照）、`generationNumber`（可空精确数字字符串，仅生成任务有编号）、`processed`（当前执行代次的精确数量字符串；成功时为已提交 quantity）。历史进度通过 framework 的受控只读端口装配，生成/分配仅全部工厂的 `sn:generation:view` 可读；不因此开放他人的任务输入、操作重放或任务取消。

`OrderPiVO.customer` 返回原型聚合候选的客户编码，采用可见活动单据的 MAX(customer)。生成页规则候选连续加载、优先默认通用；分配记录连续读取完整历史，生成任务仍展示最近 20 条。后端仍保留分页接口与精确数量。

## V27 当前工作区：生成拒绝与失败历史

生成前置校验区分 `params.reason=GEN_PREVIEW_USED / GEN_PREVIEW_EXPIRED / GEN_PREVIEW_STALE`。流水变化参数 `pi/expected/actual` 均为字符串。这些拒绝不创建新任务；订单、规则、物料和额度的执行阶段校验失败则保存 FAILED 作业，预演保持已消费，重新预演才能提交新意图。同 operationId 重放仍返回原持久结果。

默认 `ADTEK_SN_INLINE_GENERATION_QUANTITY=5000`，不超过阈值的生成请求在登记事务内领取自己的新任务，登记提交后执行业务事务；业务失败先独立提交失败记录，再返回原受控业务错误。大批量与需要恢复的任务继续由框架工作器处理。HTTP 断开或服务端未知响应须按原 operationId 查询，不另建意图。已接受任务不因排队后预演到期而失败；任务自身预算与租约仍适用。

`SnWorkVO.errorParams` 必返字符串映射，无可公开原因时为 `{}`；失败 `processed` 为 `"0"`。生成任务在执行前及失败时仍能展示原计划 `firstSn/lastSn`、数量、编号和操作工号。已发布数字码与 HTTP 类别保持稳定，因此预演过期/额度不足在新版仍是 409，Python 对应为 400；页面按同一业务原因显示原型文案。当前提示随语言翻译，失败历史沿用原型服务端中文语义，异步失败提示保留 8 秒。

## V28 当前工作区：ERP 归属变化与分配

`POST /allocations` 增加可选 `factoryCode`：页面提交确认时所见工厂，非空时必须与最近成功生成的工厂一致。省略时兼容原客户端，使用当前订单映射工厂；显式空串表示未指定。带此字段的命令使用 v3 规范化指纹，旧 v1/v2 重放不变。拒绝原因 `ALLOC_FACTORY_MISMATCH` 使用原数字码 1004000019，并返回字符串参数 `factory`；另支持 `ALLOC_NOTHING(bill_no)` 与 `ALLOC_QTY_EXCEEDED(qty,pending)` 的受控文案。

ERP 改生产组织后，在新组织成功生成之前，页面分配被拒绝；成功生成后，历史待分配成员与新成员可按流水固定数量分配到新工厂。成员实际 PI、客户、来源不被重写。分配任务/审计取首次生成 PI/客户和最近生成工厂，不要求每个成员来源与今天的 ERP 相同。提交仍检测 expectedQuantity，执行仍校验固定成员与历史工厂；并发不能扩大或偷换成员。

`piSummary` 按当前 PI/组织和历史首次 PI/最近生成工厂合并，顺序为当前订单升序，再追加历史订单升序。历史行 `inSnapshot=false,totalQty="0",quota="0"`，生成/分配累计保留。未生成的非活动订单不显示；未映射组织仍可查看当前同组织同 PI 的快照汇总。

ERP 改 PI 后若重新从 1 起号，按数量分配先按流水升序，相同流水先取早生成的 SN。分配首尾取本次实际成员顺序；例如先生成 A1/A2/A3，再在新 PI 生成 B1/B2，分配 3 枚为 A1/B1/A2，余量分配为 B2/A3。任务继续保存首次 PI/客户，成员保留各自实际 PI/客户。V29 为此更新查询索引，HTTP 和字段契约不变。

## V29 当前工作区：初始化拒绝参数

初始化接口补充下列 `params.reason` 和字符串参数；已发布数字码和 HTTP 类别不变。空输入、清单校验、容量及提交时已锁定的拒绝不产生新任务或 SN。行号按请求 `sns` 原数组从 1 计数，忽略空项时不重排行号；页面已经解析 CSV/文本后的数组以实际发送内容为准。

| 原因 | 数字码 | 参数 |
| --- | --- | --- |
| PI_INIT_EMPTY | 1000000001 | 无 |
| PI_IMPORT_SN_INVALID | 1000000001 | line：超过 64 个 Unicode code point 的项所在行 |
| PI_IMPORT_DUP_IN_LIST | 1004000015 | sn：去除首尾空白后的重复号码 |
| PI_IMPORT_DUP_EXISTING | 1004000015 | sn、pi：目标 PI 已有的完整号码 |
| PI_IMPORT_SEQ_DUP | 1004000015 | seq、pi：来源 PI 已占用的流水，允许精确字符串 `"0"` |
| PI_INIT_LOCKED | 1004000013 | pi：已设置起号或生成过的 PI |
| GEN_START_INVALID | 1004000002 | max：当前规则容量，精确十进制字符串 |

上述初始化执行阶段失败参数也可进入已有 `SnWorkVO.errorParams`，与生成/分配分别按白名单装配。缺少必填参数、数字码与原因不匹配、控制字符和未知字段均不会作为历史公开参数返回。页面读取失败结果后保留输入并释放终态意图，新提交使用新的操作号；同操作号重放仍返回原结果。历史列表继续只展示成功的初始化记录。

初始化执行时每 1000 条先检查目标 PI 的完整号码、再检查来源 PI 的已占用流水，与原型批次顺序一致；MySQL 唯一索引仍作为最终约束。后续批次冲突会回滚整个业务事务，包括此前批次的 SN/查重键、计数器、规则使用状态和成功历史。失败任务、已观察的进度及失败审计保留；进度不是已提交数量。受控冲突参数写入失败历史，页面隐藏失败历史行并显示三语提示，保留表单以供修正后重新提交。

当前前后端工程约束仍保留精确字符串、持久任务和幂等保护。原型容量/已锁定/清单重复的 HTTP 类别与新版有部分不同，页面按同一业务原因翻译；多个同时冲突、并发写入、字符范围、数量/字节上限和完整一致性验收继续见[一致性清单](../testing/SN页面与功能一致性验收清单.md)，本节不宣称这些范围已经全部对齐。

## V30 当前工作区：初始化导入容量

初始化数量与生成批量上限分开：`ADTEK_SN_MAX_IMPORT_QUANTITY` 默认 500000，沿用每个 SN 最多 64 个 Unicode 码点的校验。规范化清单超过上限时返回数字码 `1004000011`、`params.reason=PI_IMPORT_TOO_LARGE` 和精确字符串 `params.max`，拒绝发生在登记新任务之前；页面保留表单并显示原型三语文案。生成数量仍由原有 `ADTEK_SN_MAX_BATCH_QUANTITY` 控制，默认 100000。

HTTP 字段与异步任务协议不变。前端初始化提交等待 60 秒，等待的是登记完成；实际导入由持久任务执行并通过原页面轮询结果。只有 PI_INIT 的执行事务采用 `ADTEK_SN_IMPORT_EXECUTION_SECONDS`（默认 600 秒），对应总截止预算至少为执行预算加 60 秒，其他任务保持原预算。失败和超时仍须整批回滚，不把进度当成成功数量。

部署代理对 `/api/v1/sn/pi-initializations` 单独开放 160 MiB 请求体，其他接口保持 16 MiB。该容量覆盖正常页面 JSON 序列化后的 50 万条、每条 64 码点；不承诺任意冗余转义的手工 JSON 或任意并发负载。量测边界与真实页面证据按一致性阶段报告记录。

## V35 当前工作区：规则操作痕迹

`SnAuditVO.quantity`保持必返，类型为精确非负整数字符串或null；成功规则操作没有数量含义，返回null。`detail`仍为字符串，可能是白名单JSON或原型规则描述纯文本，前端不得假定可解析为JSON或删除纯文本空格。新增规则、未使用版本修改分别使用`sn:rule:create`和`sn:rule:update`，展示及导出为RULE_CREATE/RULE_UPDATE；已使用版本升版和改名分别为RULE_VERSION/RULE_RENAME。

一次编辑同时升版/改内容和改名会产生两条记录，均与规则修改同事务；未变化不新增SN痕迹。创建记录保留对应PI/客户绑定，后续修改记录按原型保持这些字段为空。关键词、在线/归档查询和导出均包含纯文本详情；旧快照及旧文件版本不变。其他平台动作、失败信息和完整权限/恢复验收继续按当前一致性清单执行。

2026-10-09认证痕迹补齐：system经framework的AuthenticationEventObserver发布类型化事实，由SN自己的Mapper固定历史身份、工厂和详情。登录失败的平台安全日志仍是匿名拒绝；SN痕迹记录格式已校验的尝试工号，数据库中存在的人员才具有actorId。未知工号及锁定提前拒绝为null身份，不伪造已认证用户。仅在密码匹配后明确返回停用码1002000018；错误密码仍统一1002000001。失败痕迹独立事务且不替换原业务错误，成功痕迹失败会回滚业务。登录地址使用可信连接remoteAddr，不接受任意转发头。密码、哈希、token、Cookie、原始请求体和异常文本均不进入该事实端口。

## 账户目录筛选与展示（V37）

`GET /api/v1/system/users`仍要求当前`system:user:list`及其部门/本人范围，分页默认20、上限100。keyword按工号前缀或姓名包含匹配，工号升序。同组roleCodes取并集，excludedRoleCodes排除候选；两者与enabled、factoryId取交集后分页，禁止页后筛选。工厂过滤还校验当前工厂list范围；系统模块通过FactoryMembershipPort读取候选和标签。

### SN 三角色账户表单

`POST /api/v1/sn/users`接收username、displayName、role、可选factoryId及只写password，返回精确字符串id。`POST /api/v1/sn/users/{id}/update`接收displayName、role、可选factoryId和当前version，不能更改工号或密码。两者要求对应的system:user:add/update权限及system:security:administer，最终写入仍受部门、工厂、角色授权、乐观锁和最后管理员约束。

role为admin/factory_operator/query：总部对应PLATFORM_ADMIN+SN_HQ且不绑厂；操作员对应FACTORY_OPERATOR且单厂必填；查询员按是否绑厂对应SN_QUERY_FACTORY/SN_QUERY_ALL。SN通过framework的AccountAdministrationPort调用system管理用例，不跨模块引用Mapper或实现类。新建部门由当前授权内的操作人部门或首个可选部门确定；编辑保留已有部门。自定义角色、多厂或不完整角色组合不能经简化接口改写，返回409/1004000031，页面保留通用编辑入口。

提交时依次校验工号、姓名、角色/工厂、密码和唯一性。业务拒绝使用400/1004000030及白名单params.reason，重复工号返回409/1004000032并增加emp_no参数。通用管理安全检查仍使用既有错误码；密码不进入VO、日志或审计。会话撤销、Unicode密码边界及SN管理痕迹仍按一致性清单继续对齐，不将本表单交付视为P13全部完成。
