# 第九阶段：生成失败历史与预演拒绝

继续 P07，核对“没有发号”背后的任务记录与页面反馈。本阶段只使用本机独立比较库和合成 K3；Python 原型、原账号、既有开发库不改，不访问 GitLab 或公司 ERP。整体 P01—P16 目标仍未完成。

## 行为依据与修正

原型 `app/services/generate.py::generate` 在提交前检查预演归属、已用、到期及自有水位；这些拒绝不新建作业。通过前置检查后登记任务，再在 `_generate_in_tx` 内校验额度、物料/名称、分段、规则和当前订单。执行阶段失败会保留任务编号、预演号段、数量、操作者、时间和原因，已处理数量归零，SN 与水位不提交。原型默认不超过 5000 枚同步返回结果，接受后的任务不再按预演到期时间拒绝。

新版据此将执行校验放回已登记任务的执行事务。小批量在提交事务中领取自己的新任务，提交成功后才执行，避免后台工作器抢先领取造成反馈时序变化；业务失败先独立保存终态，再返回受控业务错误。同 operationId 重放不重新执行，也不增加编号。大批量及恢复仍使用原持久任务框架，不绕过权限、代次、租约、整批事务与唯一性保护。

V27 只新增 `sn_work.error_params`。只保存与受控数字码对应的公开原因及允许字段，数量和流水保持字符串；多余字段和异常原文不写入历史。`SnWorkVO.errorParams` 必返，旧记录投影为 `{}`。未完成/失败任务用可信计划补足展示号段，失败进度为 0。当前提示使用页面语言；历史原因沿用原型服务端中文语义，异步失败提示保留 8 秒。

数字错误码与 HTTP 类别保留已发布契约：新版预演过期/额度不足仍为 409，原型对应为 400；按钮操作展示相同业务原因。此处没有把两套内部 API 宣称为逐字节相同。

## 本次界面范围

双端通过页面按钮进行预演、确认生成、另页签同步、刷新和重新预演；API/数据库读取仅辅助核对实际状态。到期场景只把本用例独占 PI、admin 的唯一未用预演设为过期，不改系统时间。

| 场景 | 检查内容 |
| --- | --- |
| 名称、编码、分段、行序变化 | 旧预演执行失败，有一条带计划号段、数量和工号的失败记录，进度 0；刷新保留，重新预演生成后同时保留失败与成功记录 |
| 预演过期 | 显示到期原因，无新增任务/成员；重新预演成功 |
| 另一页签先生成 | 原页显示自有流水从 0 到 2 的变化，保留已有成功记录，不增加失败任务；下一次从 3 继续 |
| 额度缩减 | 预演 3 枚后同步为 2 枚，显示数量与剩余量，保留原 1—3 计划号段的失败任务且无发号；刷新后重新预演 2 枚成功 |
| 既有生成回归 | 相同重同步、无关元数据变化、整单额度、21 行分录、选单、数量确认及部分分配 |

一次 26 项生成相关双端界面回归通过（7.4 分钟，无自动重试）。截图复核发现确认框关闭动画及下方历史行定位影响可读性，测试增加等待关闭并滚动到记录行后，相关 6 项与 2 项复核也通过；这些是重复验证，不计为新场景。当前共 82 项界面用例，本阶段没有宣称全量复跑。[阶段证据](evidence/parity-20261008-stage09/summary.json)保存三轮结果、26 个不同场景、100 张截图、源码与 JAR 摘要。后端 73 项单元/架构和 97 项集成已通过（SnFoundationIT 28、SnWorkIT 41、SnQueryIT 9、SnAuditIT 10、DurableTaskIT 9）；前端 57 项单元、TypeScript、ESLint、构建、API 生成类型核对、全工程格式/Mapper 行宽与 Python 静态检查通过。

后端新增检查覆盖同步失败先留历史再返回、原意图重放、重新生成、精确领取本任务不抢其他队列任务、不接管已有租约、预演使用/到期/水位前置拒绝、接受后到期仍可执行，以及回滚进度和错误参数过滤。完整 SN 冲突与额度回滚的既有用例继续运行。

## 过程与数据保护

第一轮新过期场景的测试错误地统一断言 HTTP 409，清理又遇到确认框关闭动画，后续场景由夹具保护拒绝启动。已按原型实际类别修正断言，并改为完整导航到订单页后用同步按钮恢复，保护性清理核对原成员/护栏/规则/累计摘要。没有降低断言或自动重试。原型前 10 项生成场景已实际执行的审计全部保留，不能删记录或制造操作来让全天累计相等；最终配对运行按测试前后的真实审计增量核对。

V1—V26 保持原始字节，V27 仅在隔离比较库应用。业务测试成员清理而真实审计保留。清理后两边均恢复 3 张订单、4 条分录、10 枚基线 SN 和 3 个 v1 规则，定时关闭、间隔 1440 分钟，临时 K3 控制和订单为空。三轮配对验证各新增生成 96 枚、分配 13 枚，领取/打印未增加。全天实际累计为新版生成 508、分配 88，原型生成 582、分配 101；两边领取/打印均为 10。差额来自前述第一轮实际执行，原始审计完整保留。当前浏览入口仍是新版 15173、原型 8000；服务账号未重置。
