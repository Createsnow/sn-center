# SN 一致性第四十七阶段 全量订单同步独立事务

2026-10-09。本轮将全量同步的工厂更新与订单更新拆为两个独立事务，按 Python 原型保留各自的成功结果，并对齐同步反馈、跨页提示和同步按钮。完整功能与页面一致性目标仍在执行。

## 提交与回滚行为

| 操作 | 双端页面及数据库结果 |
| --- | --- |
| 全量正常同步 | 先提交工厂，再提交订单；显示单据数及行数。 |
| 工厂第二笔写入失败 | 该次工厂事务全部回滚，包括已写入的第一笔；订单仍更新并显示正常同步结果及未建档组织。 |
| 工厂成功审计写入失败 | 工厂事务回滚，订单继续；没有额外的组织失败横幅。 |
| 订单写入失败 | 先前提交的工厂保留；原订单、分录保持原值，页面显示固定的 `Internal Server Error`。 |
| 订单成功审计写入失败 | 同样保留工厂、回滚订单；故障解除后可正常同步。 |
| 按单据同步 | 仅更新指定单据；即使外部目录变化，也不会更新工厂。 |
| 同步后立即切换工厂页面 | 成功提示继续显示至自身计时结束，不因订单页面卸载提前消失。 |

V41增加内部字段`sn_order_sync.factory_version`，保留原始`base_version`。工厂目录、映射、订单名称关联投影、成功审计和本次工厂提交版本在同一工厂事务中提交；订单事务仅接受原始基准或本次工厂提交版本。其他并发发布仍触发版本冲突。

两个事务分别复核当前主体、授权、同步状态和定时租约。集成检查验证了工厂提交后发生外部发布时订单拒绝、工厂提交后租约过期时订单拒绝，以及过期执行者不能写入工厂。原有历史额度及SN保持不变。字段只作为内部持久依据，没有新增开放导入接口。
