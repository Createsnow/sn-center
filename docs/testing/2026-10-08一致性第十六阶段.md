# 第十六阶段 初始化导入容量

本阶段将初始化导入从共用生成上限、8 MiB 内联输入，改为独立的 500000 条上限及固定输入分块。原型和新版均已通过真实页面导入 50 万条、每条 64 个 Unicode 码点的文件；新版经过独立 HTTPS 代理。超量拒绝场景也分别取得双方实际页面证据。既有 34 项初始化回归也已一次全部通过。本阶段共验证 38 项不同界面场景，分组执行；完整 P01—P16 目标保持未完成。

## 实现与约束

V30 新增 `sn_import_chunk`，每行最多 1000 条，保存原清单顺序。任务、业务元数据和全部输入块在同一次登记事务内提交；工作器逐块读取，检查序号、数量和整份清单摘要。摘要仍采用原 v1 完整 JSON 数组语义，旧内联任务可执行，同操作号幂等指纹不变。缺块、篡改或后续冲突会回滚全部业务写入，分块不代表分批提交 SN。

初始化默认上限为 `ADTEK_SN_MAX_IMPORT_QUANTITY=500000`，生成批量默认上限仍为 100000。超量请求在新任务登记前返回 `PI_IMPORT_TOO_LARGE` 及精确字符串上限。只有 PI_INIT 使用 `ADTEK_SN_IMPORT_EXECUTION_SECONDS=600` 的执行事务预算，总截止预算至少为执行时间加 60 秒；普通任务仍保持原预算。登记事务仍为 30 秒，页面登记请求等待 60 秒，随后由持久任务执行并轮询结果。

Nginx 只对初始化精确路径开放 160 MiB 请求体，其他 API 保持 16 MiB。比较测试使用独立 HTTPS 18443，挂载实际部署配置和前端构建产物。页面解析清单改为随文本变化计算，避免任务轮询时重复解析大清单。配置、升级和边界详见[运维](../operations/部署与运维.md)、[数据库设计](../architecture/数据库设计.md)和[接口契约](../business/接口契约.md)。

## 测试进程失败与提示观察

这些失败如实保留，不计为通过：初次大文件测试的 Node 工作进程耗尽堆内存；实际 Java 任务后来成功，另开浏览器查询、刷新、核对数据并清理，属于恢复证据。随后减少巨型文本页面的自动化诊断开销，两边最大数量用例取得完整通过结果。

超量用例曾多次因跨进程轮询没有捕获短提示而失败，改用外层容器和原生 DOM 查询仍未解决。一次网络诊断还遇到浏览器调试缓存淘汰响应正文，导致测试异常。只读 DOM 观察记录过正确提示节点约 5.3 秒后移除；最终新版用例在浏览器绘制帧内等待实际文案和非零几何区域，通过了拒绝、保留输入和无数据写入检查。没有改写页面、延长消息持续时间或替换服务响应。跨进程读取为什么错过提示尚未完全定位，不把推测写成根因。

新版超量截图记录的是提示已消失后的保留表单；错误文案证据来自浏览器帧内断言。完整提示时序、截图外观及其他页面视觉差异仍属于后续待验范围。最大数量的两项通过结果、原型超量通过结果与新版最终超量通过结果来自不同运行，合计 4 项不同场景，不宣称一次 4 项全部通过；原始失败报告同时保留。

最终恢复 3 张订单、4 条分录、10 个基线 SN、3 个规则；原业务摘要和账号安全字段未变，生成/分配/领取/打印审计累计未变，真实初始化审计保留。所有测试夹具和输入块清理，定时关闭且间隔 1440 分钟，API readiness 为 UP，两边页面 HTTP 200，实时 OpenAPI 与保存契约语义相同。
