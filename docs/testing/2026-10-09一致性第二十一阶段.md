# SN 一致性第二十一阶段：下载失败、三语与窄屏详情

2026-10-09。本阶段继续 P09 领取打印：对齐自动下载与历史下载失败的提示和后续操作，检查中文、英文、越南语及 900×900 窄屏详情。完整一致性目标仍未完成，剩余范围见[验收清单](SN页面与功能一致性验收清单.md)。

## 改动与实际行为

- 自动下载和历史下载失败均显示约三秒、无关闭按钮的错误提示。历史记录不再因下载失败留下持久错误横幅或重新查询列表。打印业务已成功时，下载失败不会回滚打印，也不会阻断批量队列中的下一张 PI。
- 非 JSON 的 HTTP 下载拒绝显示本地化状态码，例如 `Download failed (HTTP 503)`。新增独立错误类型区分传输响应与有效业务错误；已有业务错误码、网络错误和 HTTP 200 非法文件仍保留原有校验及提示，不将 JSON 错误内容保存成文件。
- 从打印历史重新下载 CSV/XLSX 不重新提交打印命令。本阶段逐端确认每次批量只产生两次成功打印、两条打印记录，六枚 SN 保持 PRINTED，下载重试前后的完整业务投影相同。
- P09 中文确认按钮改为原型实际显示的“确定”；英文 `OK/Cancel`、越南语 `OK/Hủy` 与原型 MessageBox 一致。未修改其他页面的确认用语。
- 批次详情的状态标签背景被组件默认样式覆盖，现已修正已打印/待打印标签的样式优先级。详情遮罩改为黑色 50%，关闭按钮颜色及 32×22 尺寸与原型对齐。样式仅作用于当前批次详情。

## 双端界面验证

一次完整 P09 回归 **18/18 通过**，约 8.9 分钟，单工作器、零自动重试。包括既有领取/打印、历史 10 条分页与详情 50+1 条分页、批量部分失败、工厂跨 PI 只读和查询角色、真实转厂往返重领、空文件及三语下载故障。

对三语场景分别通过页面选择两张 PI、取消确认、批量领取，再批量打印。只在文件 GET 上注入一次非 JSON HTTP 503，实际领取与打印命令、工作器和后续下载均走本机服务。首张文件失败后第二张正常下载，仍显示两张 PI、六枚 SN 完成；打印历史再注入一次 CSV 503，提示消失后重下 CSV 和 XLSX，确认业务状态未变。该检查证明下载失败后的恢复行为，**不代表实际撤权或所有网络故障已验收**。

截图复核发现整组中的瞬时提示截图抓到了淡入前一帧。增加可见性、动画完成和祖先透明度检查后，追加 **6/6 三语双端复查通过**，约 2.8 分钟。它们是同一组场景的证据补强，不另计新增用例；112 张验收截图使用补强后的三语截图。整组原始截图另存，未覆盖或删除。

## 失败和修正记录

第一次新增六项运行为 1 通过、5 失败。误将 Element Plus 的 Popconfirm 本地化文字用于 MessageBox 断言，英文实际页面是 `OK/Cancel`，并非 `Yes/No`。清理还遇到未关闭的弹窗及“中文/简体中文”精确定位问题，来源夹具被保护保留，后续四项被初始化保护拒绝。修正定位和关闭顺序后，通过正常页面恢复中文和三单四行 K3 快照，再执行原有带摘要、所有权校验的夹具清理；未重置库或放宽保护条件。随后新增六项全部通过。

只读样式诊断最初还因登录后立即跳转而超时；增加登录完成等待后取得实际样式。诊断确认新版标签背景原为 `rgb(177,189,180)`，原型为 `rgb(240,249,235)`。修正后纳入整组和补拍断言。最后一次补拍核对了可见提示，避免将 DOM 中存在文字误当成截图已显示。
