# 第八阶段：重同步后的预演有效性

继续 P07，修复“订单未变但重新同步后不能确认生成”的迁移差异，并检查有意义的变化仍会阻止发号。完整 P01—P16 目标仍未完成。仅操作本机独立比较服务和合成 K3；原型源码、既有账号与业务库不改，不连接 GitLab 或公司 ERP。本阶段没有新增数据库迁移，比较库仍为 V26。

## 修正依据与实现

原型 `app/services/generate.py::_generate_in_tx` 比较 PI、工厂、规则版本、水位以及实际 `segments_json`。此前新版直接比较整个 Plan 的 JSON，连同步时间、订单/分录快照版本都要求一致，造成相同订单重同步后旧预演被误拒绝；同时原计划没有保存物料名称，漏掉了原型对该字段的检查。

新版显式比较预演承诺的单据号、PI、工厂、规则版本身份、自有水位、指定起号及每段的行序、物料编码/名称、数量、流水和完整 SN。规则、容量、额度、起号和当前资格仍通过锁内重算检查。同步时间、内部版本、分录内码、未改变本次号段的后续行变化不单独使预演失效。不能仅删除版本校验后继续使用旧来源：提交和工作器均使用通过校验的当前计划写入，来源累计归属当前分录，成员客户及成功审计归属本次实际客户；原预演和任务输入仍保留用于追溯。

截图复核进一步发现，原型在拒绝后按当前额度恢复数量建议并展示新分录，新版只清除预演，仍保留旧输入/分录。现已在生成成功、失败及明确拒绝后刷新分录，在失败/拒绝后重新计算数量建议；界面检查明确断言恢复到 13 枚以及新的物料编码/名称、行序和数量。最近一次成功生成的数量继续用于本页分配建议。

预演内部段落新增物料名称；历史已完成作业不受影响，缺少该字段的旧预演不能证明名称一致，会提示重新预演。比较环境升级前没有未完成生成任务。HTTP 预演/命令结构与生成类型未变化。

## 实际界面检查

新增 5 个场景，分别在原型与新版执行。第一页通过按钮预演并保留结果，第二个同会话页签通过订单页按钮同步；回到第一页确认生成，未调用 API 替代预演、同步或生成按钮。

| 场景 | 核对结果 |
| --- | --- |
| 无变化同步与无关元数据变化 | 13 枚订单预演 3 枚，同内容重同步后继续生成；再次预演 3 枚，将来源分录内码、客户、PO、状态、需求单号及未使用的后续额度改变，确认本次相同号段仍可生成。前 3 枚保留原客户，后 3 枚使用新客户 |
| 物料名称变化 | 编码、数量、流水不变，名称变化必须拒绝旧预演；没有生成 SN，重新预演后成功 |
| 物料编码变化 | 旧预演被拒绝；重新预演后只写新物料 |
| 分段变化 | 首行从 8 缩到 2，第二行补到 11，总量仍 13；原单段预演被拒绝，重新预演后按 2+1 两段发号 |
| 行序变化 | 总量和物料未变，仅调换两行顺序；旧预演被拒绝，重新预演采用新的第一行 |

最终修改后单次运行全部 20 项生成相关界面场景通过（双端各 10 项，5.1 分钟，无自动重试），包括本阶段新增 10 项及此前 10 项生成/选单回归。[阶段证据](evidence/parity-20261008-stage08/summary.json)保存该次完整结果、72 张截图、测试报告与源码/运行 JAR 摘要。前面调试复跑不重复累计为新场景。本阶段没有复跑全部 76 项现有界面用例；上一轮完整 66 项回归证据保存在第七阶段，不能把两轮结果称为一次 76 项全量通过。

最终前端 55 项单元、TypeScript、ESLint、生产构建、生成类型一致性、全工程格式/Mapper 行宽和 Python 静态检查通过。清理后两边均恢复 3 张订单、4 条分录、10 枚 SN 和 3 个 v1 规则；定时关闭、间隔 1440 分钟，K3 临时控制及订单为空。当天成功审计均为生成 412、分配 75、领取 10、打印 10；这是含多次真实测试的累计，未删除或编造审计来匹配数量。

## 后端与数据保护

新增集成检查覆盖提交前和工作器执行前的相同重同步、两次来源内码与客户变化后的实际成员/累计/审计，以及物料名称变化在提交和排队执行两个位置的拒绝。原有“排队后重同步即失败”的测试改为真实物料变化，保留不发号、不推进水位、释放占用及预演不能重复消费的断言。73 项单元/架构与 84 项集成通过（SnFoundationIT 28、SnWorkIT 37、SnQueryIT 9、SnAuditIT 10）。调试期间新增审计断言曾误用任务表字段导致混入别的测试历史，已改为 sys_operation 的本次操作号精确筛选后复跑通过。

界面测试只使用独占 CMP-UI-GEN-PI / CMP-UI-GEN-MO、G06 号段和最多 30 个受控成员；测试完成先通过页面恢复原 3 张订单，再由受控清理器删除专属成员。原有成员、护栏、计数器、规则版本和累计逐字段摘要核对，保留所有真实审计与框架任务。

## 尚未完成

ERP 的 PI/生产组织变化后原型按历史生成台账分配、新版按当前来源校验，仍需继续对齐；离开当前快照的 PI 汇总数量、后台资源上限、跨订单首次规则保留、长任务/断网/多账号/并发和更多页面外观仍待核对。拒绝截图已确认：原型同步生成失败会留下任务历史，新版在部分错误提交前拒绝，没有该行；原型区分预演错误原因，新版仍使用合并错误文案。后续须对齐任务失败记录与细分提示，不能因两边都未发号而认定整个失败流程一致。其他 P01—P16 缺口保持在[总清单](SN页面与功能一致性验收清单.md)，本阶段不宣称完整页面一致或整体完成。
