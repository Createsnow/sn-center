# 第三十五阶段：真实认证操作、审计事实与改密会话

本阶段补齐真实登录、停用、锁定及改密操作在 SN 操作痕迹中的事实，修正页面提示和改密后多出一次登录记录的问题。最终16项双端界面流程250.0秒通过。**全项目功能与页面完全一致仍未完成；登录表单外观、平台管理及其他真实业务事件继续待对齐。**

## 已修复

| 原差异 | 当前行为 |
| --- | --- |
| 原型有登录失败记录，新版只写平台日志 | 通过 framework 认证观察端口投影至 SN 审计；system/sn 不跨模块引用 Mapper，实际认证成功与失败均产生对应事实 |
| 未知工号、已知账号、停用及锁定混为一种错误 | 保留原型对应提示、主体快照、角色、单一绑定工厂、失败原因及 client/locked 详情；未知工号和已锁定请求允许匿名主体 |
| 改密错误未出现在 SN 痕迹中 | 错误旧密码、相同新密码、弱密码分别记录；失败独立事务，审计失败不替换原始业务错误 |
| 改密成功后前端再次登录，额外产生 LOGIN | 改密直接返回新会话并更新刷新 Cookie，前端直接进入首页；旧访问与刷新凭据失效，不再额外登录 |
| 错误提示位置/文案不同，长工号溢出相邻列 | 登录与改密接入已有顶部提示；保留旧全局错误映射，认证页使用原型三语文案；审计工号按原型换行 |

V36 增加审计失败消息并允许匿名主体，在线与归档表同时支持；原历史消息保持空值。归档摘要对两个可选扩展采用有值才追加的规则，旧记录摘要保持兼容。新审计导出格式6将改密动作和匿名角色显示对齐原型；旧格式1—5继续按原版本恢复并通过摘要回归。V1—V35原字节未修改，下一迁移V37。

认证事件仅携带明确枚举、可信身份快照和必要上下文，不携带密码、令牌、请求体或异常内容。客户端地址使用服务器实际连接地址，不信任任意转发头。成功留痕参与业务事务；失败独立事务。上述语义由认证与归档集成测试检查。
