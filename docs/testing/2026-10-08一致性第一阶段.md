# SN 一致性第一阶段：公共框架与订单页面

本阶段继续执行 [完整验收清单](SN页面与功能一致性验收清单.md)，目标没有缩小。结果为部分功能已对齐，整体一致性尚未验收。Python 原型源码未修改；所有写操作使用 2026-10-08 独立比较库及合成 K3，没有连接公司环境或 GitLab。

## 本阶段修改

- 公共框架采用原型的五组菜单、顺序、静态图标、220/64 像素侧栏、面包屑、语言选择和用户菜单。保留后端菜单及权限检查；非管理员身份和工厂标识仍待补齐。
- 登录页面采用原型布局和三语文案，首次访问按浏览器语言选择中文、英文或越南文；页面标题跟随语言。修改密码使用独立页面，主动修改入口和取消返回已检查。
- 订单页保留左单据、右分录布局；定时设置改为弹窗，支持分钟、小时、天换算，关闭弹窗放弃未保存编辑。
- 订单分录连续展示全部行，后台仍按 100 行一页读取，取消选单后停止后续请求。工厂候选文案、空状态插图、时间格式、表格行高也已向原型对齐。
- 开发期间发现 Vite 曾缓存空的页面模块，导致订单路由报错。已为 Windows 文件监听启用等待写入稳定，重启前端并增加浏览器未处理异常检查。

静态图标与空状态 SVG 来源于原型使用的 Element Plus 软件包，许可文件保存在 `frontend/src/components/prototype/`；目标工程不增加 Vue 运行时依赖。

## 已执行的界面操作

脚本为 `frontend/e2e/parity/shell-orders.spec.ts`。每个场景在 Python 原型和 React 新版各执行一次，共 16 项，无重试；使用真实浏览器、真实应用 API 和独立 MySQL，不拦截业务响应伪造通过结果。

| 场景 | 实际检查 |
| --- | --- |
| 登录三语与窄屏 | 点击三种语言；核对标题、说明和登录按钮；保存桌面、390 像素宽度截图及几何数据 |
| 菜单与退出 | 核对 11 个入口和五组顺序；进入订单；展开收起到 220/64；打开用户菜单；退出并刷新 |
| 主动改密入口 | 从订单进入修改密码；提交空表单检查必填提示；点击取消返回订单；未修改管理员密码 |
| 同步和选单 | 点击全量同步，核对 3 单 4 行成功提示；按单同步，核对 1 行提示；搜索、清空、选单、查看两个物料、去生成、浏览器返回 |
| 定时设置 | 打开默认 1 天；改成 2 小时并保存；重开核对；编辑后取消；重开确认未保存；恢复关闭状态及 1 天间隔 |
| 语言持久化与导航窄屏 | 登录后依次保存英文、越南文、中文；每次刷新核对菜单及标题；760 像素下自动收起，手动展开并进入订单 |
| 浏览器语言 | 新浏览器上下文分别使用 en-US、vi-VN、zh-TW，核对首次登录页语言和标题 |
| 101 行分录和快照删除 | 通过按单同步导入临时 101 行订单；选单后核对全部行并滚动至第 101 行；K3 移除临时订单后再次按单同步，检查提示及列表移除 |

临时 K3 大单在测试后清空，恢复基础 3 单 4 行。测试不恢复或覆盖用户密码，不重新 bootstrap。
