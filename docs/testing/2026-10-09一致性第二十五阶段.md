# SN 一致性第二十五阶段：跨 PI 起号、重号与搜索等待

2026-10-09。本阶段继续 P10 转厂页面对齐。新增 6 项双端检查通过后，最终一次 **16/16 合并界面回归通过**，约 7.2 分钟，单工作器、零自动重试。**完整一致性目标尚未完成**，不以本阶段部分场景替代全部页面、角色、状态与边界验收。

## 修改内容

- 新版候选与起号提示使用两个请求；现在跨 PI 且有目标目录权限时，等待起号提示请求完成后才允许提交。请求失败时显示错误并继续阻止提交，避免候选先返回、用户跳过重要起号提示。
- 订单快照搜索等待时保留上次显示的候选，移除遮挡表格的加载层，与原型等待行为相同。保留只限同一账号和授权版本，身份边界变化不沿用旧目录。
- 扩展专用合成夹具，支持目标 PI 尚未生成 SN、相同编码跨 PI 的重号验证；清理只接受精确声明的单号、原因、方向、成员和终态，继续核对原业务与账号摘要。
- 修复新界面测试的工厂下拉定位：按控件的 `aria-controls` 选择所属弹层，不通过任取首个同名选项绕过歧义。准备步骤进入保护清理范围，请求等待有明确超时，避免准备失败后遗留夹具。

## 双端页面操作

全部核心转厂操作通过真实页面完成。两套项目仍使用独立本机比较库和合成订单；规则、生成及分配通过既有夹具 API 准备，不将这些准备步骤计为完整页面闭环。

| 场景 | 验证内容 |
| --- | --- |
| 请求尚未返回 | 延迟真实候选/起号提示请求，确认提交按钮禁用；放行原请求后读取真实返回，不伪造业务响应 |
| 连续号转入 | 三枚连续 SN 转入前显示 `A17A00001 → A17A00004`，跳号数为 0 仍有提示；确认框也包含相同内容，取消后业务状态不变 |
| 单号带空档转入 | 选择 `A17A00003`，显示跳过 2 个号码；确认后实际转入乙厂和目标 PI |
| 继续转入剩余号 | 目标 PI 已有较大转入号，剩余两枚转入不再推动下一起号，不显示虚假的再次跳号提示；实际转移成功 |
| 原流水归属 | 三枚最终均归目标工厂/PI，状态为待领取，原流水 PI 不变；计数器投影保持来源 3、目标 0 |
| 完整 SN 重复 | 目标 PI 已有同名 6 枚 SN，准确显示 6 个重复与前 5 个样本；单枚第 6 号显示 1 个重复并阻止提交 |
| 返回同 PI | 改回源 PI 后重号提示消失，可向另一工厂提交；仅检查按钮与状态，没有实际执行这次转移 |
| 快照搜索等待 | 搜索第 50 条之后的物料时保留原 50 行；关闭重开仍保留搜索和原结果；真实响应完成后显示目标一行，点击回填正确 |

计数器断言是明确的业务投影：目标不存在的计数器行按 0 处理，不宣称两种存储模型的实体行完全相同。SN 当前归属和原流水归属分别核对，没有通过改写原计数器制造一致。

## 诊断与剩余范围

第一次新增检查中，原型三项通过，新版在选择目标工厂时遇到两个同名的可见下拉选项，尚未提交转厂。通过真实页面恢复三单四行，再按原严格夹具规则清理；诊断失败和恢复证据保留。修正定位后新增六项全部通过，零自动重试。

归档核对首次在重号夹具的 `items` 数据库投影处停止。检查确认是 `ORDER BY sn` 下不同 PI 的同名 SN 并列顺序未规定；固定原始输出，并仅比较这些明确的并列项。页面前五个重号样本及所有表格、下载顺序断言没有放宽。最终汇总分别标记原始相同、历史多重集合和同 SN 数据库并列顺序三种情况。

当前截图仍存在表单行距、成功提示图标位置、输入清除按钮、快照组织文字颜色和关闭图标的视觉差异，不能称整页像素一致。原型首次选择物料的空参数缺陷仍单独记录，未计为一致通过。P10 其它角色/状态、跨 PI 审批提示、20 条以上历史、并发与恢复、快照错误/乱序响应/身份变化/改名、三语窄屏继续待验。P09 权限、未知提交响应和队列恢复、旧记录/文件容量，以及 P01—P08/P11—P16 和 50 万条导入性能差异继续保留，见[完整清单](SN页面与功能一致性验收清单.md)。
