2026-10-09。本轮对齐工厂编码、组织内码和名称变化后的订单归属，并修复订单未建档提示及其引起的页面偏移。完整目标仍在执行，不能据此认定全部功能和页面完全一致。

## 已对齐的业务行为

原型按工厂编码维护目录，按订单快照中的生产组织名称寻找工厂。新版原来优先按组织内码关联，导致改编码或换内码时结果不同。自动同步现按原型规则维护目录，并在建厂、同步和订单发布时更新当前订单的名称关联。

| 界面检查点 | 双端结果 |
| --- | --- |
| 手工工厂名称与订单组织名称相同，编码与 ERP 不同 | 按单同步后订单关联该手工工厂。 |
| ERP 同名异码触发目录冲突 | 同步报告冲突，已有名称匹配仍有效，不把订单误判为未建档。 |
| 工厂编码和名称不变，ERP 组织换内码 | 不新建、不计更新、不报冲突，旧订单归属不变。 |
| 相同内码改为新编码和新名称 | 新建工厂，旧工厂保留；旧快照仍归旧名称工厂。 |
| 当前工厂改名，订单仍保存旧组织名称 | 订单变为未建档，显示相应提示，分录归属同步清空。 |
| 新建另一个编码、名称与旧快照相同的手工工厂 | 已有订单立即恢复关联，无须重新同步订单。 |
| 重复名称、禁用组织、空编码、缺有效内码 | 名称保留首项；禁用和空编码跳过；合法目录编码/名称可在缺内码时建厂。 |

组织请求按 FNumber 排序，启用标记接受大小写 A，目录按名称去重。自动来源记录允许多个内码对应同编码工厂；内码变化本身不计工厂更新。工厂来源 MANUAL/K3、未变化的版本和更新时间保持。

新增 V40 将来源记录分为 AUTO 和 EXPLICIT。成功绑定日志恢复既有显式绑定，新增显式绑定记录来源和组织身份；普通同步不覆盖显式绑定。旧日志只有工厂 ID 时保守保护该工厂的全部既有来源映射。历史日志若已缺失，旧映射的来源不能被本方案自动证明；生产升级仍需核对这类映射。本机原有两条映射经原始日志核对均为 AUTO，旧字段逐项保持。

名称重算只作用于当前有效订单及分录，不搬动历史 SN、生成台账、领取、打印、转厂或已消耗额度。只有实际归属改变的订单/分录抬快照版本；迁移需要改变归属时才推进全局修订。真实 V39→V40 升级测试验证显式绑定保护、自动关联修复、未变化快照保持、额度不变和重复迁移不再执行。
