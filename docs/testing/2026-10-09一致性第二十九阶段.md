# 第二十九阶段：SN 查询角色、跨厂范围与拒绝提示

本阶段完成一组 P11 角色与组合筛选的双端界面检查，并修复实际发现的行为和外观差异。**全项目功能与页面完全一致的目标尚未完成。** 当前注册 172 项界面用例，本轮最终只运行查询相关 4 项长流程，workers=1、retries=0，全部通过，约 2.1 分钟。

## 界面逐项结果

| 场景 | 实际操作及结果 |
| --- | --- |
| 本厂操作员 | 默认只见甲厂两枚 SN；无 PI 时跨厂开关禁用；输入本厂拥有的 PI 并开启后，显示甲厂两枚、乙厂一枚，保持只读 |
| 无权跨厂查询 | 输入本厂不拥有的另一 PI，双端均返回 403；提示说明本厂没有该 PI 的号；保留上次成功的三行结果；提示可手动关闭 |
| 清空 PI | 开关复位并禁用，跨厂说明消失；再次查询回到本厂两枚 SN |
| 全厂查询员 | 可见两厂六枚 SN；查询乙厂独有 PI 得到三枚；没有操作员专用跨厂开关 |
| 本厂查询员 | 只见甲厂两枚 SN；另一厂独有 PI 返回空列表和空导出；没有跨厂开关 |
| 工厂及组合筛选 | 全厂查询员选择乙厂得到四枚；已打印状态为空，待领取状态得到四枚；完整 SN 定位一枚；来源订单与物料组合定位两枚；清空工厂和状态恢复六枚 |
| 实际下载 | 三角色各执行 CSV 和 Excel，共六对实际浏览器下载；逐列值、单元格类型与原始行序一致，验证两枚/三枚/六枚及空结果范围 |
| 管理员主流程回归 | 复跑第二十八阶段分页、默认/PI 排序、物料空白、当前草稿导出、业务批次、空结果、中英越及 1440/900px 检查；八对下载、十四对表格与主体矩形一致 |

本轮使用独立 `CMP-UI-QUERY-SCOPE-*` 夹具。六枚 SN 的生成/分配及一枚跨厂成员由公开业务 API 准备；订单同步、各角色登录、查询、筛选、错误关闭和下载均通过浏览器界面操作。这里不将 API 准备算作生成或转厂界面验收。

## 修复内容

1. 查询拒绝原先会清空新版列表，改为保留当前账号及授权版本最后成功的结果、总数与页码。切换账号或授权版本时丢弃旧范围数据。
2. 后端保留原数字错误码 `1003000004`/HTTP 403，为确实没有本厂 PI 成员的拒绝增加受控 `reason` 与用户输入的 `pi`，不泄露其他厂成员。前端使用中英越原型文案及五秒可关闭提示，普通 403 仍保持通用语义。
3. 工厂标签字体、圆角，跨厂开关尺寸与标签间距、颜色，以及只读说明背景和图标尺寸对齐原型。独立测量确认标签、开关、开关文字、说明框、图标、滑块、查询按钮七组矩形相同；没有宣称整页像素相同。
4. 五个状态选项关闭虚拟列表，使全部选项具有真实可访问节点。第二次诊断中，基于角色的定位无法找到虚拟列表中未暴露的“已打印”；最终通过实际选项点击验证。

初次诊断为原型通过、新版因清空三行结果与缺少具体提示失败；修复后再次诊断为三项通过、状态选项定位失败；最终四项一次通过。失败证据一并保留，没有用自动重试掩盖。
