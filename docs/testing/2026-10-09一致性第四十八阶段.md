## 已对齐的行为

| 实际操作 | 痕迹与页面结果 |
| --- | --- |
| 全量同步 3 单 4 行 | 数量为 3，来源订单为空，详情为 `mode=all rows=4`。 |
| 按 CMP-MO-001 同步 2 行 | 数量为 1，来源订单为该单号，详情为 `mode=one rows=2`。 |
| 同步不存在的 CMP-MISSING | 成功，数量为 0，保留单号及 `mode=one rows=0`；页面提示该单已从快照移除。 |
| 全量空快照 | 成功，数量为 0，详情为 `mode=all rows=0`。 |
| 人工 K3 查询、登录拒绝 | 每次一条失败痕迹；数量为空，保留按单单号，详情为 `POST /api/orders/sync`，失败原因与原型一致。 |
| 人工订单 SQL 写入失败 | 不新增 SN 业务失败痕迹；保留此前工厂成功痕迹及平台失败记录，订单事务回滚。页面显示 `Internal Server Error`。 |
| 保存、重复保存、关闭定时设置 | 每次成功保存均留痕；数量为空，记录 `enabled`、`interval_minutes` 及修改前值，布尔文本为 `True/False`。 |
| 定时成功、查询失败、恢复 | 操作人 `system`、姓名“系统”、角色 `admin`、来源 `SYSTEM`、请求号为空。成功详情为 `mode=all rows=4`；失败详情为 `mode=scheduled`，数量为空。 |

定时同步附带的工厂痕迹也显示系统身份。内部同步记录及平台日志仍保留实际责任人；执行时当前权限、全局范围、并发版本及租约检查保持。人工业务拒绝在用例事务外独立记录，结构校验和未处理 SQL 异常不误记成业务拒绝。成功审计写入失败仍回滚其业务事务，审计故障不替换原始业务错误。

不修改旧痕迹，V1—V41 和历史导出格式保持；本轮没有数据库结构变更。
