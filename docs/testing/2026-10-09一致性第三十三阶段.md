# 第三十三阶段：真实规则操作痕迹

本阶段修复规则页面真实操作产生的审计差异：新增、未使用版本修改、已使用版本升版、改名分别留痕；同时修改内容和名称产生两条记录，未变化不产生SN记录。规则详情保留原型纯文本和空格，数量为null。最终8项双端界面流程全部通过，**P12及全项目功能、页面完全一致目标仍未完成**。

## 实现及兼容性

规则服务在修改前固定描述快照，审计观察端口读取本模块的规则事实。平台仍保留字段差异记录；SN审计按原型规则分别追加。记录和写入序号与业务同事务。集成测试故意让第二条改名审计写入失败，已验证规则修改和第一条成功审计共同回滚。

V35在在线和归档审计中增加`detail_text`并允许数量为null，旧JSON列和旧事实不改写。接口的quantity仍必返，前后端类型及运行时校验均接受精确数量字符串或null。关键词分别匹配纯文本或旧JSON，避免二者合并表达式产生MySQL排序规则冲突。

新导出为格式5：固定快照额外保存JSON/TEXT标记，实际文件仍为24列。纯文本空格保留，JSON继续使用原压缩规则。旧格式1—4全部使用实际旧文件SHA-256重生成回归通过；旧任务重放不改格式。归档复制包含新文本；旧null文本行保持原摘要算法结果，新文本内容纳入摘要。归档后查询、CSV文本和篡改识别已通过集成测试。

V35已应用于独立比较库33308。V1—V35冻结，下一迁移V36。验收JAR已重建并启动，普通开发JAR不替代此比较服务。
