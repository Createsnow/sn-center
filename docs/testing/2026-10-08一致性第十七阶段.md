2026-10-08，本轮推进 P09，完整一致性目标仍未完成。原型保持不变；测试只使用本机比较库和合成 K3。Java 后端及数据库仍为 V30，下一迁移 V31，没有访问公司 ERP 或 GitLab。

## 已修改的页面行为

领取页按原型改为“待领取、待打印、领取批次、打印记录、号段”五个标签。工序列表只显示对应数量大于零的 PI；总部按工厂和 PI 查询，厂区绑定工厂，只有厂区显示“同 PI 各厂（只读）”开关。汇总读取完整分页结果，数量在浏览器内使用 BigInt 累计。

增加逐行确认、多选批量、已选数量、批量确认及结果汇总。每张 PI 创建独立持久操作，明确终态后再提交下一张；一张失败继续其余张。打印成功自动下载该 PI 的 XLSX。号段页保留状态、物料筛选，“号段”按钮聚焦当前工厂 + PI，聚焦也作用于批次和打印记录，“看全部”解除聚焦。物料筛选不会缩小领取或打印命令范围。

正常操作过程中隐藏内部任务面板；未知响应及结果读取失败仍提供原操作查询、重发或结果读取入口。领取成功数量使用 `eligible`，不会把被阻止成员计为成功；被阻止成员仍可查看逐项结果。原已批准的固定成员、来源资格及零可领结果契约继续保留，这些语义与最新原型的差异仍需逐项完成一致性审查，不能因为旧契约存在就自动豁免。

本轮还调整主工序表的字号、行高、列宽、颜色和确认弹窗。截图可证明布局接近原型，不能据此宣称像素或所有视口完全一致。

## 实际界面验证

最终一次执行 8 项双端场景，workers=1、retries=0，约 2.5 分钟，全部通过：

| 双端场景 | 实际验证 |
| --- | --- |
| 单张领取打印 | 默认工序、总部无跨厂开关、取消确认无写入、PI 聚焦、物料筛选、聚焦历史与看全部、整 PI 领取、自动 XLSX、打印后刷新无重复记录 |
| 两张 PI 批量 | 两张各 3 枚，确认合计 6 枚，两个领取批次、两个打印记录、依次下载两份文件 |
| 批量部分失败 | 先在另一浏览器页面打印其中一张，再确认原页面批量；重复打印被拒绝，剩余一张成功并下载，最终各 PI 只有一个打印记录 |
| 角色 | 厂区开关无 PI 时禁用，启用跨厂只读后隐藏工序标签；总部及绑厂查询员无领取按钮、无勾选列；原业务状态不变 |

准备步骤使用公开 API 创建两张合成订单对应的规则、生成和分配数据；本轮受验的领取、打印、筛选、确认及权限操作均由浏览器按钮执行。数据清理由独立夹具在校验原始行摘要和任务终态后完成，没有用直接改状态代替页面操作。

[阶段证据](evidence/parity-20261008-stage17/summary.json)包含 28 张界面截图、14 对原始业务投影及 5 对 XLSX。14 对业务投影完全一致。138 项已登记界面用例没有全量复跑；本轮通过不代表 P09 整页或整项目已经完成。

## 文件与历史的确切剩余差异

5 对 XLSX 的原始行序均不同。原型 11 列中文表头，含状态、领取批次和来源订单；新版 14 列英文表头，增加来源系统、账套及稳定来源 ID，但缺少原型所需的状态和领取批次列。原型按原数据 ID 输出，新版按月份和随机 UUID 扫描后固化 ordinal。本轮仅证明按 SN 对照、将相应数字转为字符串后，8 个共有业务字段一致，不把这种投影比较称为完整文件一致。原始文件和各自 SN 顺序均保留在证据中。

领取/打印历史仍显示 UUID、数字操作人 ID、不同时间格式及文件状态布局；原型使用业务编号、操作人工号及更紧凑的下载链接。批次抽屉的字段、宽度和分页也未全部对齐。这些差异与 CSV、文件内容及排序一起进入下一阶段，不能用本轮自动下载通过替代它们。
