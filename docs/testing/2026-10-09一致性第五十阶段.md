# SN 一致性第五十阶段 K3 响应与失败详情

2026-10-09。本轮对齐订单同步的 K3 登录、查询、单据查看响应，以及三语错误提示和失败操作痕迹。首轮实际页面记录有 33 处提示或结果差异，最终复测对应结果一致。完整功能与页面目标仍在执行，本轮有实际进展，无阻塞。

## 已修复行为

| 场景                                   | 对齐后的行为                                                                                                                     |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 登录状态缺失、布尔值、字符串或顶层标量 | 作为登录业务失败，显示 `LoginResultType != 1`；数字错误摘要转换为文本。                                                          |
| 数值登录状态、空会话                   | 正数状态按原型整数部分判断；1.0、1.25 的单元测试及 1.25 的实际页面操作通过。空会话不作为格式异常。                               |
| 查询返回对象、JSON null、数字或字符串  | 合法 JSON 但不是结果数组时显示查询失败 `unexpected response`；不误报 JSON 解析异常。部分类型通过单元测试，页面覆盖对象和字符串。 |
| 错误摘要                               | 按原型空白规则处理各片段，数字和布尔值转成文本，忽略 null；空摘要与没有摘要区分。空摘要保留查询失败前缀，三种语言均通过。        |
| 数组嵌套和二次编码                     | 正确提取业务失败摘要；顶层普通字符串不会被强行当作另一份 JSON 解析。                                                             |
| View 缺状态或无错误项                  | 分别显示 `View failed` 或“查询失败”；保持订单快照。                                                                              |
| View 缺单数字码、成功但无单据/分录     | 将指定单据移出有效订单快照；页面列表消失。再次全量同步后恢复。10.0 由单元测试验证，10.25 另经双端界面验证。                      |
| HTTP 503 和后续页失败                  | 保留对应查询失败摘要；先读到 2000 行、第二页再失败时，原订单及分录全部字段保持不变。                                             |
| 失败操作痕迹                           | 三语操作各产生 13 条订单失败记录，每端共 39 条；实际筛选、调整分页并逐条展开，核对中文原因、操作员、来源、请求路径和空数量。     |

K3 凭据脱敏、响应大小和超时限制、真实订单分录的稳定身份检查继续保留。数据库采用既有停用历史记录机制，公开列表及业务结果与原型删除快照的表现一致；并未删除历史记录来满足测试。没有数据库结构变更，V1—V41 原字节保持，下一结构版本仍是 V42。

后端 **94 项单元/架构测试、60 项集成测试**通过（SnAuditIT 23，SnFoundationIT 37）；前端 **84 项单元测试**、lint、构建、OpenAPI 类型检查、完整格式检查通过。构建保留既有大 chunk 提示。当前注册 **227 项 UI、40 个文件**，本轮未全量复跑。

上述证据覆盖管理员、1440×960、三种语言的列明场景。已复核错误提示、单据移除及失败详情截图；两端自动滚动位置和表格省略仍有后续核对项，不把本轮语义结果一致认定为整页像素一致或完整矩阵完成。
