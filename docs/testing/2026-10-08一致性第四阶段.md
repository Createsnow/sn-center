## 改动与实际结果

- 人工同步失败改为原型的浮动提示，可关闭，配置持续 5 秒；不再把固定错误块插入订单页面。查询失败、HTTP 503 与登录失败显示对应业务摘要，保留当前列表、摘要时间和选中单据的分录。成功重试刷新订单并清除选单。
- K3 适配器保留受控错误码，只放行经过秘密检查、控制字符清理和 500 字符限制的业务摘要。含凭据字段或当前连接秘密时整段回退，原始响应和异常堆栈不进入提示或定时结果。HTTP 拒绝按登录/查询阶段分类。
- 新增 V23，分开记录定时执行状态与上一轮成败。正在同步时继续展示上一轮结果；失败保留旧快照和上次成功数量；恢复后清空错误。租期、执行编号、发布事务和保存者授权检查保持。
- 定时失败内容沿用原型后台保存的中文摘要，外层标签随中文、英文、越南文切换。调整弹窗位置、字号、间距、颜色、输入和结果图标；在 1440×960 下中文失败弹窗两边均为 x=480、y=144、宽 480、高 453。
- 合成 K3 新增本地文件控制的查询拒绝、登录拒绝、HTTP 503、空订单和短暂挂起。仍只监听回环地址，HTTP 不提供更改控制文件的接口。

## 通过页面执行的检查

`frontend/e2e/parity/order-sync.spec.ts` 的三个场景分别在两个项目执行，新增 6 项双端界面检查通过。使用真实 Edge 的页面、输入、按钮、弹窗和语言菜单，没有用业务 API 请求替代操作。

| 场景 | 实际操作与断言 |
| --- | --- |
| 人工失败与恢复 | 选中 CMP-MO-001；全量查询拒绝、按单 HTTP 503、登录拒绝；检查可见错误和关闭；订单、摘要时间、两个物料分录保持；清除故障后全量同步恢复 3 单/4 行并清除选单 |
| 空快照 | 选单后全量同步空结果；显示 0 单/0 行、最近同步为 `—`、空列表和空明细；刷新保持；恢复合成 K3 后通过页面同步回 3 单/4 行 |
| 后台定时执行 | 页面开启 10 分钟；真实后台线程依次执行成功、查询失败、恢复；挂起请求时验证仍显示上一轮成功或失败；失败快照时间不变；三语检查失败弹窗；最终通过页面关闭并恢复 1 天 |

定时测试仅用 `tools/testing/parity-schedule-clock.py` 将独立比较库的 `next_run_at` 提前，避免每次等待 10 分钟。该工具固定回环端口与比较库、要求页面已开启 10 分钟，不调用同步用例或修改结果字段。之后由已运行的定时器自行领取并访问合成 K3。这证明实际 worker 路径，不是完整等待十分钟的时间精度测试。

最终合并回归 **44 项全部通过**，单 worker、无重试、无未处理 JavaScript 异常。本阶段保留 12 张截图及几何信息，原始结果、源码摘要、后端分项测试和前端检查日志见[summary.json](evidence/parity-20261008-stage04/summary.json)与[证据目录](evidence/parity-20261008-stage04/)。最终核对两边均为原 3 单/4 行、10 枚 SN、原始小数 2.5，定时关闭且间隔 1440 分钟，附加订单及故障控制为空。

调试时曾将原型开关定位到隐藏 input，并在取消弹窗尚未结束动画时再次点击取消；这些失败或中断未计为通过。脚本改为点击可见开关、等待弹窗关闭，并在截图前等待弹窗稳定。首次新版提示样式使用了过时的 AntD 类名，按当前组件结构修正后重新取证。
