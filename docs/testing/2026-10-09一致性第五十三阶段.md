# 第五十三阶段：返回刷新修复与完整界面业务闭环

本阶段完成生产订单返回时的缓存修复，并通过新旧两端的完整界面业务闭环。完整目标继续执行；下一步按功能缺口收尾，不再扩展外观矩阵。

## 本次收敛原则

用户于 2026-10-09 明确要求“外观等细节不纠结，尽快收敛问题，尽早完成任务”。字体、阴影、细微间距及组件内部 DOM 差异保留为观察，不作为完成阻塞；控件不能操作、数据错误、权限和业务缺失仍须处理。历史报告不改写。

## 已完成的功能

1. **返回订单页读取当前统计与定时设置。** 两个真实页面共享隔离账号，另一页同步新增订单并把定时间隔改为 2 小时。修复前新版列表已包含新订单，统计仍为 3 单/4 行，弹窗仍为 1 天；原型为 4 单/5 行、2 小时。新版两个查询改为进入页面即重新读取，双端相同操作通过。
2. **P15 完整界面业务闭环。** 从真实订单同步、新建 PI 绑定规则开始，通过预演生成 3 枚 SN、分配、甲厂领取打印、整 PI 转往乙厂、乙厂再次领取打印，再查询状态及操作痕迹。账号和合成 ERP 输入为测试前置；规则、SN、分配、领取、打印和转厂均由页面创建，没有用 API 或数据库预先生成号码。
3. **实际产物核对。** 两端 4 个状态检查点的完整 SN、状态、PI、工厂相同。4 份实际下载 XLSX 均为 3 条数据、11 列；除各自生成的领取批次编号，另 10 个业务列逐行相同。审计页面按 PI 筛选，均包含 1 次生成、1 次分配、2 次领取、2 次打印、1 次直转。此项证明动作与数量存在，不主张所有审计详情格式完全一致。

## 回归及诊断边界

最终完整业务闭环双端 2 项通过，耗时 39.1 秒，每端 11 个界面检查点。订单返回双端 2 项、三语订单长流程双端 2 项、滚动诊断双端 2 项、定时焦点/键盘/步进复核双端 2 项也有通过记录；这是分组验证，不是全部注册用例的一次全量回归。

订单长流程 77 对状态的已比较功能字段一致；焦点复核 27 对状态的滚动、高度、控件矩形及所检查焦点类型一致。12 组导航/同步滚动实验中，6 组直接鼠标点击两端均保持 0 滚动。原型的 60 像素跳动只在部分动画期间的测试工具自动定位点击中复现；保留诊断，不在产品中增加强制滚动来模仿该现象。

中间失败记录完整保留：一次快速切换单位后键盘步进未达到预期，后续确认单位控件生效、输入值已提交后双端复核通过；原型实际上限使用 `max`，其 `aria-valuemax` 仍可能保留旧值。完整闭环脚本修正了多行输入框定位、PI 专用筛选、初始请求和查询请求的区分，以及等待目标页面挂载；这些属于测试修正，没有改写业务响应。失败运行没有改记为通过。

84 项前端单元、ESLint、TypeScript/生产构建、API 类型及完整格式检查通过。后端 603 个基线文件、acceptance JAR 和 V1—V41 未改，未重复执行后端测试。文字及外观原始测量仍有差异，按用户最新要求不继续逐项调整。
