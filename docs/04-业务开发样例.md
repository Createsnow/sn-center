# Adtek 业务开发样例：设备台账 0.1.0

完整代码位于 `backend/adtek-equipment` 和 `frontend/src/features/equipment`，不是伪代码脚手架。数据库为 `equipment_asset`，新建表与菜单在 server 的 `V2__equipment_sample.sql`。

| 层 | 文件 | 作用 |
| --- | --- | --- |
| HTTP | EquipmentController.java | `/api/v1/equipment/assets` GET/POST，`/{id}` GET，`/{id}/update` POST |
| 参数 | EquipmentCreateDTO / EquipmentUpdateDTO / EquipmentQuery | 编码格式、名称长度、版本文本、有界分页 |
| 服务 | EquipmentService / impl/EquipmentServiceImpl | 权限、范围、可信身份、事务、唯一/版本冲突、审计 |
| SQL | EquipmentMapper.java / resources/mapper/EquipmentMapper.xml / EquipmentDataPermissionRules | 接口参数、更新版本条件、各用例准确范围 |
| 映射 | EquipmentEntity / EquipmentConvert / EquipmentVO | 持久数据与对外精确字符串分离 |
| 前端 | api/equipment.ts、EquipmentPage.tsx | 生成契约、运行时检查、查询状态、表单与详情 |
| 测试 | EquipmentIT、equipment.test.ts、equipment.spec.ts | 真数据库正确性、协议边界、浏览器操作 |

## 追踪一次新增

页面使用 `equipmentApi.create` 提交 `{code, name, enabled}`。公共 client 装配当前 access token 和 CSRF，DTO 拒绝非法格式。DataScope 切面先检查 create 权限，Service 进入 READ_COMMITTED 事务，AuthorizationMutationPort 锁当前身份，OrganizationMembershipPort 返回当前有效部门。

服务器设置 deptId/createBy/updateBy/version，不使用请求中的同名字段。MapStruct 只复制显式业务字段，编码由唯一索引保证；重复 409 / 1004000001。AuditContext 记录 code/name/enabled/deptId 的受控 diff，OperLog 成功与插入共同提交。返回 EquipmentVO 的 ID/版本是字符串；页面验证响应、刷新列表、关闭编辑框。

列表/详情/新增/编辑权限分别为 `equipment:asset:list/detail/create/update`。角色 2 全范围，角色 3 本人；平台管理员角色 1 本身不隐含业务权限，bootstrap 明确授予角色 1 和 2。新增必须具有有效部门；不存在部门时 409 / 1004000003。

## 追踪一次编辑与失败

编辑正文为 `{name, enabled, version}`；编码、所属部门和创建者不可编辑。对象按 update 权限读取，不可见 404。SQL 同时约束 id 和原 version，更新行数为 0 返回 409 / 1004000002。旧表单保留错误提示，用户关闭、刷新后重新编辑；客户端不自动覆盖服务端新值。

列表、详情和新增复用 MyBatis-Plus 基础方法；自定义编辑 SQL 位于 `adtek-equipment/src/main/resources/mapper/EquipmentMapper.xml` 的 `change`，Java 接口通过 `@Param` 绑定。XML namespace 与接口全名一致，权限登记继续使用 `com.adtek.equipment.mapper.EquipmentMapper.change`。新增自定义语句时同步维护这三处，不把 SQL 写回 Java 注解。

EquipmentIT 并发测试验证同一原版本只有一个成功，唯一编码竞争只有一条记录。审计故障场景在一次性库注入拒绝成功审计的 CHECK，确认新增与编辑回滚，再移除测试约束；不会修改开发/业务库。

## 扩展一个字段

以位置为例：追加迁移；Entity/DTO/VO 添加有界字段；MapStruct 显式映射；Mapper 更新列；Service 审计快照与 @OperLog.fields 增加 location；AuditChanges 投影和三语标签增加 location。追加后端正反测试、页面表单、运行时响应 guard 和浏览器断言，再用 RuntimeIT 导出契约，重新生成 TypeScript。不能只更改生成的 schema.d.ts。

外部 ERP 数据或资源资格不是此样板的隐含依赖。需要时新增端口/适配器及独立协议测试，仍由业务服务负责授权、幂等、事务和状态约束。
