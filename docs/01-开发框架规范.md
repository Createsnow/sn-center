# Adtek 开发框架规范 0.1.0

本规范以可运行模板为依据，约定分层、精确 ID、事务、注释和验证原则。模板包含与不包含的能力见[能力边界](06-能力边界与版本.md)。

## 版本与模块

Java 21、Spring Boot 4.1.1、MySQL 8.4.11、Redis 8.4.7；React 19.3.0、TypeScript 5.9.3、Vite 8.3.1、pnpm 10.34.6。完整依赖以 `backend/pom.xml`、`frontend/package.json`、`pnpm-lock.yaml`、`tools/build-tools.lock.json`、`deploy/images.lock.json` 为准。禁止在业务改动中顺便升级依赖；删除锁文件不会自动解析最新工具。

依赖方向：`server → system / equipment → framework → common`。server 装配模块；common 只含纯契约；framework 提供安全/范围/任务/审计设施；system 拥有身份与平台配置；equipment 是可替换业务。业务模块之间通过 framework 中的窄端口或专属业务 service.port 交互，不能读取对方 Mapper/Entity。新增外部适配器放独立 integration 模块，由 server 装配，不把具体协议混入 common。

业务包采用 `controller / service / service.impl / mapper / domain / dto / query / vo / convert / constant`。持久对象命名 Entity；DTO 是写入参数，Query 是过滤，VO 是返回。MapStruct 明确映射；不能直接返回 Entity 或接收持久实体作为 HTTP 正文。公开服务和端口说明权限、事务、输入来源、失败与返回含义。

## 请求、身份与范围

HTTP 使用 `/api/v1/{module}`，统一 `Result` 信封含整数 code、翻译键、参数、traceId。成功 code=0；不要用 HTTP 200 表示失败。业务 ID、数据库计数和版本使用十进制字符串；仅有界页码/页大小使用 number。新业务错误码分配独立百万号段；模板 equipment 使用 1004。同步 `ErrorCodeCatalogTest`、三语错误字典和生成契约。

请求主体只从 `CurrentActor` 读取，JWT 仍需 Redis 会话与 MySQL 当前授权。禁止接收客户端权限、操作者或所有者作为授权依据。Controller 按钮隐藏与注解不能代替服务用例检查。每个权限独立合并授权角色范围；全局读角色不能扩大局部写权限。

`@DataScope` 绑定准确 resource/permission，`DataPermissionRules` 登记准确 Mapper statement 与表/部门/所有者列。新语句默认拒绝。内部豁免必须写明调用路径和限制，不能将整个 Mapper 默认豁免。列表与 total 同范围，不可见详情与不存在同为 404。部门、指定部门、部门树、本人、全部部门均由服务可信数据决定。

可选资源维度通过 `ResourceMembershipPort` 扩展；默认返回空集合、拒绝非空绑定。新增资源资格须实现存储、存在性、委派上限及撤销测试。设备样板只使用部门/本人维度。`OrganizationMembershipPort` 由 system 提供当前有效部门，业务不可自行查账号表。

## 写入、并发与数据库

写用例开启 READ_COMMITTED 事务，先调用 `AuthorizationMutationPort.lockCurrent`，再取得业务锁。协调锁直到事务结束，安全配置修改与业务写遵守相同顺序。检查当前权限，随后检查对象范围与版本，成功审计共同提交。数据库唯一约束解决并发唯一性；编辑通过 `WHERE id=? AND version=?` 原子递增版本，冲突 409，不静默覆盖。

MySQL 是业务最终状态。Redis 不保存替代事务的额度、设备版本或任务成功标志。SQL 参数绑定，不拼接客户端列名/排序。Mapper 单行上限 100。数据库迁移发布后不可改写；新增 `V3__...sql`，升级已有模板库只追加版本。V1/V2 属于模板自己的新库历史，绝不能应用到其他产品的 Flyway 库。

基础单表 CRUD 优先使用 MyBatis-Plus 已有方法；自定义 SQL（含任务、审计和身份内部语句）统一放在所属模块的 `src/main/resources/mapper/*Mapper.xml`。Java Mapper 保留接口、参数、必要的结果类型与便利方法，不再使用 SQL/映射注解或 SQL 字符串常量。所有自定义语句参数显式标记 `@Param`；实体参数统一命名 `entity`，XML 使用 `#{entity.field}`，自增主键回填使用 `useGeneratedKeys="true" keyProperty="entity.id"`。

XML 的 `namespace` 必须等于接口全名，语句 `id` 必须等于方法名，并保持 `DataPermissionRules` 的准确登记。重复投影可用 `<sql>` / `<include>`，动态批量用 `<foreach>`；XML 中小于号写成 `&lt;`。迁移只调整存放方式和排版，不同时修改权限、锁、版本条件、排序或分页；即使原始 SQL 相同，不同权限用途的方法也不能合并（例如审计导出的 `count` 与 `visibleCount`）。Mapper XML 使用两空格层级缩进，SQL 按子句人工排版；`tools/format.ps1` 和 `-Check` 统一空白与换行，启动集成测试核对语句装配、参数名称和结果类型，架构测试禁止 SQL 注解回流。

## 前端、审计、任务与文件

React 函数组件、TypeScript strict。TanStack Query 保存服务端状态，query key 包含用户和授权版本；退出及身份变化清理缓存。Zustand 仅保存最小内存会话。所有 API 用生成类型并校验运行时 unknown；不从 number 恢复精确 ID。页面明确 pending、空、失败、冲突和成功；写失败不自动重试。

登录、刷新、个人偏好等共用会话、CSRF、统一错误边界。禁止把访问令牌写入 localStorage/sessionStorage。敏感输入不进入日志、URL、网络 trace 或测试截图。

`@OperLog` 声明允许审计字段，`AuditContext.record` 只传受控 before/after；成功日志失败应回滚业务。业务新增审计字段时更新投影白名单和三语标签，不能将整个 DTO 当日志。请求拒绝登记路径模板，不保存动态 ID、查询串或正文。

任务通过持久 operation/task 执行，记录执行权、租约、attempt、终态与恢复；后台重新检查当前主体和权限。文件先生成完整快照再发布，下载复核任务所有者与当前完整范围。业务必须自定义 TaskHandler 的权限和数据快照，不能认为任务框架自动证明业务正确。模板保留在线审计 CSV 导出，其余文件类型由项目显式添加并测试。

## 配置、格式与交付

无内置账号、默认密钥或相邻工程路径。秘密只由明确本地文件/部署 Secret 注入；开发账号 DML 与迁移 DDL 账号分开。HTTP 不安全 Cookie 仅 local/integration-test 且监听 loopback；部署使用 TLS 和安全 Cookie。

注释解释职责、约束、来源与风险，不复述语句，不虚构作者/时间/测试。生成代码和冻结证据不手工排版。提交前运行 `tools/format.ps1`、`-Check`、后端/前端/契约/受影响集成和浏览器验证。报告命令、版本、发现数、失败/跳过、数据范围、截图及未执行项。所有门禁在 `.gitlab-ci.yml`；远程执行结果单列。
