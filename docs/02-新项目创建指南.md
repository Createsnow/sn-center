# Adtek 新项目创建指南 0.1.0

## 环境与复制

使用 Windows PowerShell 7、Node 24、Git、Docker Desktop Linux 引擎和 Edge。工具脚本为 Windows 基线；Linux 部署镜像不意味着 Windows 工具可直接在 Linux 运行。至少保留可运行 MySQL/Redis 临时容器的内存及磁盘空间。

从本地模板已发布标签取得干净 checkout，不需要访问 GitLab。执行：

```powershell
./tools/new-project.ps1 -Destination ../adtek-equipment-training -ProjectName adtek-equipment-training
Set-Location ../adtek-equipment-training
./tools/bootstrap-build.ps1
./tools/bootstrap-format.ps1
./tools/pnpm.ps1 install --frozen-lockfile
```

Destination 必须不存在且位于模板 checkout 外；复制失败时保留结果供排查，不自动删除目录。默认新端口 MySQL 33326、Redis 36399、API 18100、Web 15193，可用对应参数改写。脚本只复制干净 Git 跟踪文件，并记录 template-origin.json；该记录用于接收后续公共修复。

脚本修改应用名、JWT issuer/audience、Compose 项目/数据库、前端包名、会话频道与端口。Java `com.adtek` 和 `adtek-common/framework/system/server` 是框架约定，保持稳定；替换设备业务模块时同步父 POM、server 依赖、MapperScan、组件注册表、错误码目录、菜单迁移、页面/API 和测试。品牌文本在三语字典及登录/布局页面独立修改。

## 验证后启动

```powershell
./tools/verify.ps1 -Integration
./tools/check-contract.ps1
./tools/verify-web.ps1
./tools/verify-browser.ps1
./tools/infra.ps1 start
./tools/check-infra.ps1
./tools/bootstrap-admin.ps1 -Username admin
./tools/start-test.ps1
```

另开 PowerShell，在同一新工程执行 `./tools/start-web.ps1`，访问新端口（默认 15193）。bootstrap 通过 Java 初始化服务只允许空库，一次性创建平台与业务管理角色账号；密码在新工程 `deploy/.secrets/bootstrap-admin-password`。登录、强制改密后进入设备台账，新建设备 `TRAIN-001`，查看详情，编辑名称及启用状态，再到操作日志核对前后值。

角色和范围在平台配置维护。普通登记员角色只有本人范围，管理员有全部设备范围；切换账号核对列表、详情、编辑边界。创建账号后必须改密，角色变更使原会话失效，需要重新登录。

`infra start` 新建独立随机秘密和 Compose 卷；账号 app 只有 DML，migration 负责 DDL。不要复制别的项目的 `.secrets`、`.env`、卷或数据库。改过秘密文件不会自动修改既有 MySQL 账号；排查时先核对项目/卷，不通过删库消除报错。

## 构建与部署

`verify.ps1` 生成 `backend/adtek-server/target/adtek-server-0.1.0.jar`；`verify-web.ps1` 生成 frontend/dist。`deploy/api/Dockerfile`、`deploy/web/Dockerfile` 只复制这两个产物。使用 `tools/build-images.ps1` 构建本地镜像，构建上下文由 `.dockerignore` 严格限制。

部署配置见 `deploy/compose.app.yml` 与 `deploy/app.env.example`，针对已经提供的独立 MySQL/Redis 和 TLS。先提供新 Secret 文件，再显式运行 migrate profile 的单次 DDL 容器，之后启动 API/Web；不要把开发库当生产库。API 不挂载 DDL 密码，关闭自动 Flyway；迁移用例验证允许的 schema。正式部署还需自己的备份恢复、容量、证书、日志保留与业务验收，不由模板自动完成。

新项目检查通过后 `git init`，审查忽略项，提交代码和 template-origin.json。不要提交 `.tools`、node_modules、运行日志、测试账号、数据库卷或秘密。GitLab 地址、runner 与推送由项目负责人按环境安排。
