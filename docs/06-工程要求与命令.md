# 工程要求与命令 0.1.0

本工程不使用 PowerShell 脚本。Windows 开发机使用 `tools\*.bat`；Linux 部署使用 Docker Compose；CI 使用 Linux Docker runner。

## Windows 本地开发

前提：JDK 21（`java` 在 PATH）、Maven 3.9.9+（`mvn` 在 PATH）、Node 24（自带 corepack，按 `package.json` 的 `packageManager` 使用 pnpm 10.34.6）、Git、Docker Desktop（Linux 引擎，用于本地 MySQL/Redis 与 Testcontainers）。在 `cmd` 中、工程根目录执行：

```bat
tools\setup.bat
tools\verify.bat
tools\infra.bat start
tools\migrate.bat
tools\start-api.bat
```

另开一个命令行窗口：

```bat
tools\start-web.bat
```

浏览器打开 `http://127.0.0.1:15183`，`/api` 由 Vite 代理到 `http://127.0.0.1:18090`。

| 命令 | 作用与成功判据 |
| --- | --- |
| `tools\setup.bat` | 检查 JDK/Maven/Node 版本，按锁文件安装前端依赖（`--frozen-lockfile`） |
| `tools\format.bat` / `tools\format.bat check` | 全仓格式化 / 只检查（Java、Mapper XML、POM、前端、配置与 `tools\*.mjs`） |
| `tools\verify.bat` | 后端编译、格式、架构测试、单测、打包；前端契约（存在 OpenAPI 时）、lint、格式、单测、严格 TS、构建；文档链接 |
| `tools\verify.bat integration` | 另外运行 `*IT` 集成测试（`PlatformIT`：Testcontainers 临时 MySQL/Redis，复用 `deploy/mysql`、`deploy/redis` 初始化脚本） |
| `tools\infra.bat start/stop/status` | 本地 MySQL `127.0.0.1:33316`、Redis `127.0.0.1:36389`；首次 start 在 `deploy\.secrets` 生成随机秘密；stop 保留数据卷 |
| `tools\migrate.bat` | 以 DDL 账号对本地库执行一次 Flyway 迁移后退出 |
| `tools\start-api.bat` | 前台运行 API（`local` profile，`127.0.0.1:18090`），Ctrl+C 停止 |
| `tools\start-web.bat` | 前台运行 Vite 开发服务器（`127.0.0.1:15183`） |
| `tools\new-project.bat` | 从模板复制新项目，见下文 |

所有脚本可在任意目录调用；失败时返回非 0 退出码并提示原因。

## Linux 部署（Docker Compose）

每个服务一个独立、无状态、单进程容器：

| 服务 | 镜像 | 职责 | K8s 对应 |
| --- | --- | --- | --- |
| `migrate` | API 镜像，`--spring.profiles.active=migrate` | 以 DDL 账号单次执行 Flyway 后退出；数据库未就绪时有限次重试 | Job 或 initContainer |
| `api` | `deploy/api/Dockerfile` | 业务接口；只在容器网络开放 18090；可多副本 | Deployment + Service |
| `web` | `deploy/web/Dockerfile` | 静态资源与 `/api` 反向代理，监听 8080 | Deployment + Service + Ingress |
| `mysql` / `redis` | `compose.infra.yml`（可选） | 单机部署的数据库与缓存；生产可换托管服务 | 托管服务或 StatefulSet |

部署步骤（在构建机或 CI 先执行 `tools\verify.bat` 或 CI 流水线，得到 JAR 与 `frontend/dist`）：

```bash
sh deploy/init-secrets.sh
```

```bash
cp deploy/app.env.example deploy/app.env
```

```bash
docker compose -f deploy/compose.infra.yml -f deploy/compose.yml up -d --build --wait
```

- 连接外部 MySQL/Redis 时只用 `-f deploy/compose.yml`，并在 `deploy/app.env` 中填写实际地址；外部库需预先创建 `adtek_app`（仅 DML）与 `adtek_migration`（DDL）账号。
- 水平扩展 API：追加 `--scale api=3`；之后执行 `docker compose ... restart web`，nginx 重新解析多个 API 地址。
- Web 默认只绑定 `127.0.0.1:18080`，由主机上的 TLS 反向代理或负载均衡对外提供 HTTPS；可用环境变量 `ADTEK_WEB_BIND`、`ADTEK_WEB_PORT` 调整。
- 停止：`docker compose -f deploy/compose.infra.yml -f deploy/compose.yml stop`（保留数据卷）。

### K8s 扩展基础

镜像与配置已按以下约定准备，迁移到 K8s 时只需编写清单：

- **无状态**：会话在 Redis，最终状态在 MySQL；容器内不写业务文件，根文件系统只读，只有 `/tmp` 可写（K8s 使用 `emptyDir`）。
- **配置**：全部来自环境变量（`deploy/app.env` → ConfigMap）。
- **秘密**：Spring `configtree` 读取 `/run/secrets/<变量名>` 文件（K8s Secret 卷挂载到 `/run/secrets`），也可直接注入同名环境变量。API 只持有 DML 账号密码，DDL 密码只给迁移 Job。
- **探针**：API 存活 `/actuator/health/liveness`、就绪 `/actuator/health/readiness`（含 MySQL 与 Redis），端口 18090；Web 存活 `/healthz`，端口 8080。
- **优雅停机**：收到 SIGTERM 后 Spring 等待进行中的请求最多 30s，`terminationGracePeriodSeconds` 应不小于 40。
- **安全**：非 root（UID 10001 / nginx 101）、`no-new-privileges`、丢弃全部 capabilities、资源上限（API 1Gi、Web 256Mi），JVM 按容器内存的 70% 分配堆。
- **日志**：只输出到 stdout/stderr，带 traceId，不含秘密。
- **启动顺序**：API 在迁移成功后启动（K8s 用 initContainer 或先执行 Job）；不依赖 MySQL/Redis 的启动顺序：迁移自行重试数据库连接，API 在依赖可用前就绪探针保持 DOWN。

## 创建新项目

```bat
tools\new-project.bat --destination ..\my-project --name my-project
```

- 目标目录必须不存在且位于模板之外；模板工作区必须干净。
- 只复制 Git 跟踪文件；在全部文本文件（含 README、docs、`.gitlab-ci.yml`）中替换项目名、数据库名与端口（默认 MySQL 33326、Redis 36399、API 18100、Vite 15193、部署 Web 18180，可用 `--mysql-port` 等参数改写）；镜像摘要与锁文件保持原样；生成 `template-origin.json` 记录来源版本与提交。
- 不复制账号、秘密、缓存、数据或 Git 历史。`com.adtek` 包名与 common/framework/system/server 模块名是框架约定，保持稳定。
- 新项目执行 `tools\setup.bat` 与 `tools\verify.bat` 后 `git init`，提交代码与 `template-origin.json`。

## 测试要求

- 后端单元测试 `*Test.java`（surefire），集成测试 `*IT.java`（`-Pintegration`，failsafe）。`adtek-server` 零发现测试即失败。
- 模块回归保护（`ModuleRegistrationTest` 强制）：有生产代码的模块必须有 `*Test.java`；有 Mapper XML 或迁移的模块必须有 `*IT.java`。CI 每次运行全部模块的测试，修改一个模块时其他模块的测试即为回归保护，因此每个已上线用例都应有覆盖其业务规则的测试。
- 集成测试只使用临时 Testcontainers 或本工程隔离设施，不退回 H2/模拟数据库，不连接业务库执行破坏性测试。
- 每个写用例至少覆盖：正常流程、超长/非法输入、大于 2^53 的 ID、重复与并发创建、旧版本编辑冲突、越权读写、权限撤销后拒绝、审计失败回滚。
- 浏览器测试（`pnpm test:e2e`）操作真实页面与独立 MySQL/Redis；禁止开启含凭据的 trace/storageState，截图不含秘密。
- 不得为了变绿而跳过、禁用或隔离测试。`ArchitectureTest`、`ErrorCodeCatalogTest`、`boundary/*Test` 与前端 `locales.test.ts` 是规范门禁，不得删除或放宽。
- `PlatformIT` 覆盖迁移（V1、DML/DDL 账号分离）、就绪探针依赖与安全链；新增迁移或基础设施时同步扩展。

## 提交与交付

- 提交前：`tools\format.bat`、`tools\format.bat check`、`tools\verify.bat`（涉及数据库时加 `integration`）。
- 迁移文件发布后不可改写；接口变更同步导出 OpenAPI 到 `frontend/openapi/adtek-template.json` 并执行 `pnpm api:generate`。
- 不提交秘密、`deploy/app.env`、`deploy/.secrets`、数据库卷、`.tools`、`node_modules`、`target`、`dist`、测试结果与运行日志。
- 报告实际执行的命令、版本、测试数与失败/跳过数，以及未执行的环境；远程 CI 结果单独说明，不以本地结果冒充。
- `.gitlab-ci.yml` 面向 Linux Docker runner：`backend`、`frontend` 执行与 `tools\verify.bat` 相同的门禁；存在 `*IT.java` 时运行 `integration`；`images` 构建镜像。后两者使用 `docker:dind`，需要 privileged runner。

## 常见问题

- `java`/`mvn`/`node` 版本错误：`tools\_env.bat` 会给出具体提示；检查 PATH 与 `JAVA_HOME`。
- Docker 不可达：确认 Docker Desktop 已启动且使用 Linux 引擎，`docker info` 正常；集成测试不会退回内存数据库。若容器已启动但连接被重置（`localhost` 解析为 IPv6 而 Docker 只转发 IPv4），设置环境变量 `TESTCONTAINERS_HOST_OVERRIDE=127.0.0.1`。
- 端口占用：`netstat -ano | findstr :18090` 定位进程，不终止未知进程；新项目使用新端口参数。
- MySQL Access denied：核对 `deploy\.secrets` 与首次创建数据卷时的凭据；改写秘密文件不会修改已有账号密码。不打印秘密、不自动删除卷。
- 迁移失败：查看 `tools\migrate.bat` 或 `migrate` 容器日志；Flyway checksum 错误时恢复已发布 SQL 原文，用新版本迁移修正。
- 格式检查失败：执行 `tools\format.bat` 后审查差异再提交。
