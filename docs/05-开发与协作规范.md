# 开发与协作规范

本工程遵循 [技术栈 v1.1](references/baselines/技术栈和工程结构（v1.1）.md) 和 [注释 v1.1](references/baselines/AI%20生成代码注释规范（v1.1）.md)，不引入第二套业务脚手架。

模块依赖为 server → system/sn/integration/framework，integration → sn/framework，system/sn → framework → common。framework 不访问 system/sn 的表或实现；system 和 sn 通过共同身份协议协作。service.port 的外部实现放 integration。

持久业务层采用 controller/service/service.impl/mapper/domain/dto/query/vo/convert。domain 是 Entity；MapStruct 负责 DTO→Entity/Entity→VO，业务计算在 Service 中。SequenceSpec 是非持久的规则值对象，位于 service/support，不冒充 Entity。

每个公开 Service/端口说明当前授权、作用范围、副作用、事务及幂等失败语义。实现只注释真实锁/约束/恢复机制，不把计划写成已保证。业务 IDs、流水及大计数的 JSON 类型是字符串，错误码是 int32。

真实 MySQL/Redis IT 必须显式执行并统计报告；缺 Docker 不自动跳过。认证、用户、系统配置、审计查询和持久任务/文件底座已实现，不等同 S2 全部完成。新增 Mapper 语句必须登记精确范围策略或内部豁免理由；禁止整个包绕过拦截。管理写操作共用权限协调行、事务内复核和 @OperLog；角色/菜单/部门授权写已使用相同锁顺序并撤销受影响账号版本，S3用户工厂资格写已通过同事务端口遵守，后续SN状态写继续遵守。

持久操作使用数据库模板服务；@Idempotent 是该契约的标记，不会使任意方法自动获得幂等能力。业务消费者通过 TaskHandler 端口接入，快照、范围和成功审计仍归属业务模块。新增消费者必须证明自身业务锁、最终状态和任务结果在同一事务，不能把租约、Redis 或进度当作业务互斥与提交凭据。文件路径仅允许服务器生成的受控键，当前授权检查须贯穿重放、执行、恢复和下载。

代码和报告在本工程中修改；旧工程和根目录来源文档保持只读。用户授权含本机 Docker、WSL 和隔离容器安装，并于2026-09-30明确授权将本工程代码与文档提交、推送至http://git.adt-net.cn/58671/adtek-platform-sn；生产部署、删卷或自动重启仍需对应授权。密钥、业务备份和本机运行目录不入Git。

S5扩展底座时仍按端口分层：服务主体类型装配在system，framework只消费Actor与AuthorizationPort；固定SN/打印成员在sn。公共CursorResult不依赖Swagger，装配层补齐必返与可空协议。打印的业务操作成功和产物执行状态必须分开，禁止文件恢复时再次更新SN。任何新文件消费者须显式声明共享文件读取范围，不能全局放宽任务所有权。

## S6 观察与导出规范

SN成功审计由同事务观察端口从固定业务事实组成；观察器禁止注入再次依赖ManagementAuditPort的引擎/服务，避免依赖环，禁止失败审计等待外层业务锁。领域成功投影失败必须使原业务失败，不静默遗漏。新导出同时检查读取和导出动作，工厂范围的交集按每条事实判断，不能误把“源厂或目标厂”替换成不等价的工厂ID集合交集。

所有新Mapper语句逐项登记理由，Archive只能用封闭服务器常量。不可从当前SN、当前姓名或当前规则重建过去的审计/文件。前端共享下载/恢复组件，业务数值保持文本，空和null分开。

## 统一代码格式

Java主代码和测试使用父POM锁定的Spotless 3.10.3 / google-java-format 1.36.1，采用AOSP四空格缩进；类与方法注解独立排版，构造器、方法体、连续声明和长参数列表由格式器统一展开。长字符串按常量拼接换行，保持运行时内容；关闭`reflowLongStrings`，避免重新合并已按SQL字段或子句拆分的片段。Mapper源码每行最多100字符（含缩进、注释和字符串），字段列表、VALUES和SET赋值按逗号或子句边界拆分，不改变SQL空格、换行、绑定参数或条件。七份POM使用SortPom 4.0.0、两空格缩进，保留依赖和模块列表顺序。`validate`阶段自动执行`spotless:check`和Mapper行宽检查，失败时显式修正并格式化后再构建，不在编译过程中自动改源码。

前端保持现有Prettier 3.9.9配置与生成物排除规则。部署/应用YAML、非敏感JSON模板及构建工具锁文件使用同一Prettier；PowerShell使用项目缓存中的PSScriptAnalyzer 1.25.0及`tools/format-settings.psd1`，四空格缩进并展开大括号。PowerShell入口在写入前比较去除排版/注释后的token，若字符串、运算符或命令发生变化则拒绝写入。编辑器遵循`.editorconfig`，Git文本统一LF，Windows `.cmd`保持CRLF。

统一命令见[命令手册](10-命令手册.md#统一格式化与检查)。格式范围明确排除Flyway历史SQL、三份来源基线、已冻结报告/证据、生成的OpenAPI/TS、第三方补丁、依赖和本机秘密。格式化不修改业务逻辑，也不代替功能测试。已有GitHub工作流加入格式门禁；实际CI执行情况按报告记录，不能因配置存在就宣称CI通过。
