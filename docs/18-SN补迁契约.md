# SN 补迁契约

日期：2026-10-04；状态：增量实现已落地、综合验证中。完整范围和剩余项见[差异清单](plans/SN原型更新差异清单.md)。本契约记录当前实现，不等同于六步计划全部完成。

## 登录失败锁定

登录入口保留 IP/工号请求速率限制，增加独立的工号连续失败策略。默认在十五分钟窗口内失败五次后锁定十五分钟；达到阈值的第五次仍返回原凭据错误，第六次起返回 `1002000017` / HTTP 429、`minutes` 和 `retryAfter`。锁定期间正确密码也被拒绝；成功登录清除该工号失败计数。未知账号使用相同策略，不泄漏账号是否存在。

状态由 Redis Lua 和 Redis TIME 原子维护，多实例共享，应用重启不清空；Redis 不可用时拒绝登录。数据库安全审计独立记录凭据拒绝、锁定请求和触发阈值标记，不记录匿名提交的工号、密码或 token。失败审计存储不可用时记录脱敏告警并仍拒绝登录。配置为 `adtek.security.login-guard.maximum-failures` 和 `lock-seconds`，不是修改已有请求速率预算。

## 订单定时全量同步

`GET /api/v1/sn/orders/sync-schedule` 要求 `sn:order:list` 的全部工厂资格；`PUT` 要求 `sn:order:sync` 全部工厂资格。请求是 `enabled` 布尔值和 `intervalMinutes` 整数（10—10080）；责任主体取当前认证人员，不接受客户端指定身份。

V18 新建 `sn_order_sync_schedule` 单行设置，默认关闭。返回开关、间隔、下一次时间、最近运行号/开始时间/状态/错误码、最近成功数量和保存时间；ID、数量均保持字符串。`workerEnabled` 表示当前服务是否运行扫描器。页面显示“最近成功量”，避免失败时残留的上次统计被误解为本次成功。

`ADTEK_ORDER_SYNC_WORKER_ENABLED` 默认 true，只启动三十秒扫描；数据库开关默认 false，所以不会自动发起 ERP 请求。测试 profile 关闭自动扫描，集成测试显式调用 `runDue`，仅连接回环合成 ERP 和一次性数据库。部署时可通过上述变量停用本实例扫描；其他启用扫描的实例仍受同一个 MySQL 执行权约束。

开启、改间隔或换保存者时，从数据库当前时间重新计时；完全相同的保存不推迟下次执行。关闭或设置变化会将已抢占但未提交的运行登记失败；已经完成发布的结果不撤销。设置和成功审计同事务。

执行者在短事务中按“快照协调行→设置行”抢占本次运行，记录 `scheduled/FETCHING` 同步历史并推进下一次时间。网络拉取在事务外完成；执行前重新加载责任人员，停用、强制改密和失去全局同步权限均不允许调用 ERP。发布事务重新复核主体和权限，按“安全协调→快照协调→设置行”的顺序校验原运行号、开关和五分钟租期，再原子写入订单、分录、来源额度初始化、同步终态和成功审计。

旧执行者、过期执行者和设置改变后的执行者不能继续发布；返回/登记 `1004000026` 表示执行权失效。中断运行租期到期后标记失败，下一到期周期以新运行号重新完整读取；不会把中断前缓存的 ERP 数据作为已完成结果。同步失败不改变现有快照，失败状态不会覆盖并发已提交的成功状态。人工触发保留原有快照版本冲突保护。

组织同步仍需责任人员当前 `sn:factory:sync` 全局资格，采用显式可信主体，不依赖调度线程的 HTTP 上下文。若无该资格，订单同步沿用原组织映射；外部组织拉取失败沿用原行为，记录提示。

## 订单候选与精确汇总

订单列表关键词增加客户匹配；物料关键词采用存在性筛选，返回命中订单的完整汇总，不能只累计命中分录。`pending=true` 表示还有可生成额度，或者已有生成量尚未分配。每条有效分录分别核算剩余额度后相加，禁止把不同分录的超用和剩余抵消；含不符合数量契约的分录时保持不可生成，不能用取整掩盖问题。

`GET /api/v1/sn/orders/pis` 返回当前用户可见的 PI 候选、订单数、订单数量、生成量、分配量、待分配量和可生成额度。先按当前权限的工厂交集过滤订单，再按完整 PI 汇总后应用待办条件；候选关键词只匹配 PI，客户为独立条件。所有数量和业务 ID 都是精确字符串。

生成页面按客户、PI、订单逐级选择，默认只显示待生成或待分配候选；从订单详情进入时保留指定订单。订单切换，包括浏览器前进、后退，清空局部数量、起号、规则选择及预演，避免将另一张订单的预演用于当前页面。

## 首次规则选择与沿用

按用户确认的 DEC-20261004-002，生成规则优先级为显式 PI 绑定、显式客户绑定、该 PI 首次成功生成所选规则；仍无规则时必须人工选择，不能自动套用通用规则。`GET /api/v1/sn/generation/rules` 提供分页候选，要求生成查看权限，不要求规则维护权限。

生成上下文返回 `ruleChoiceRequired`、`ruleSource` 和可空的规则。需要选择时，预演请求必须传精确字符串 `ruleId`；缺少选择返回 `1004000027`。预演只固定条件，不写沿用记录；真正生成成功时，规则选择、SN、来源额度、水位及成功审计在同一事务提交。失败不留下选择，另一请求已成功选择或绑定变化会使旧预演失效。已有固定规则时以当前绑定/沿用为准，不接受客户端覆写。

V19 新建 `sn_pi_rule_choice`，按 PI 二进制精确区分。升级已有 Java 库时，只回填每个 PI 最近成功生成的规则 ID；失败、待执行、初始化作业不参与。查询保留从最近成功作业读取的兼容路径。规则更新仍受既有使用/版本约束；这里保存规则身份，并不复制或改写历史规则。

## 起号避让、预演与转厂提示

按 DEC-20261004-002/005，使用当前有效编码严格反解当前 PI 中流水归属为其他 PI 或尚未解析的 SN，得到可解析最大号。默认起号为“本 PI 自有水位与上述最大号的较大者 + 1”；首次手工起号及初始化起号也必须高于上述最大号，否则返回 `1004000028`。例如先无规则导入 G0600，随后使用 G 加四位十进制规则，默认从 G0601 开始。不同格式不参与最大号计算。

这项计算不修改导入号的原流水归属，不在转厂提交时抬高目标计数器、不消耗目标来源额度。真正生成成功才推进自身水位。计算出起号后仍连续生成；实际完整 SN 唯一冲突保持整批回滚，不逐枚试探跳过冲突。预演固定自有水位、外来可解析最大号及匹配 SN，执行前重新校验，新增转入号、规则变化等使旧预演失效。

`nextStart` 提示提供精确字符串 `ownLastSeq/startSeq`、可空 `startSn`、是否因外来号调整及对应 `bySeq/bySn`。编码容量用尽时保留数学上的下一流水，`startSn=null`；生成返回既有容量错误，不溢出或回绕。候选按 SN 键分页读取，每页 1000；`adtek.sn.work.max-incoming-scan` 默认 1000000、允许 1000—10000000。超过预算返回资源错误 `1004000011`，禁止截断后使用错误最大号；增加预算须先量测事务成本。

`POST /api/v1/sn/transfers/target-hint` 为提交前只读测算；`GET /api/v1/sn/transfers/{id}/target-hint` 依据待审批申请的固定成员重新测算。提示包括规则、转入前后建议起号及跳过的空档数量；批准/驳回后的申请不重建历史提示。页面打开确认/审批窗口时读取，并每十五秒刷新；提示不锁定库存，也不承诺最终结果，执行时仍重新校验。

提交前提示同时检查转厂查看和目标读取权限；待审批提示先检查该申请的查看范围。两者都只有转厂查看覆盖全部工厂的用户才能读取目标全 PI 水位；受限用户获得 `available=false`，不能借提示读取其他工厂库存。未绑定的目标 PI 使用当前可用通用规则作参考，实际首次生成仍须选择规则，结果可随选择变化。

## 输入与导出边界

PI 保留 Java 已发布的 128 字符上限，129 字符在创建任务之前拒绝；不把原型 64 字符限制作为收窄既有契约的理由。转厂的物料、客户、完整 SN 和原因分别遵守 DTO 上限，超长输入不能部分写入。

既有领取、打印重放、固定成员、回调、作业代次恢复及导出契约继续有效。CSV 仅对自由文本执行公式防护，业务编码不添加字符；XLSX 使用显式文本单元格。下载及恢复仍复核当前权限，不因持有旧任务号而绕过范围。

## 数据版本与验证入口

V1—V17 的内容/摘要不改。V18 扩展同步模式及设置表，V19 保存 PI 规则选择；旧库暂存、主数据、有限库存工具增加对目标 V19 的明确识别。原型源版本白名单仍为既有 19 表、254 字段，不放宽到当前新增表的原型结构。用户确认本轮不搬历史数据，相关工具继续保留，不在本轮连接旧业务库。

后端：`AuthenticationIT` 覆盖锁定、成功清零、跨实例并发和到期；`SnFoundationIT` 覆盖设置校验、权限、双执行者、失败结果、进程中断后的过期恢复、设置变化和拉取中撤权；`RuntimeIT` 验证空库迁移和实际 OpenAPI。前端：`sn.test.ts` 验证调度响应边界，真实浏览器位于 `auth.spec.ts`、`sn.spec.ts`。具体执行结果以本轮报告为准。

`SnWorkIT` 验证选择、事务回滚、未解析导入避让、扫描分页与预算、容量和输入边界；`SnTransferIT` 验证连续/不连续/不同格式转入、批准时重算及范围防泄漏；`IncrementalMigrationIT` 验证 V17 到 V19 升级、历史校验和/水位不变和成功规则回填。最终全套回归与浏览器证据单独记录，不把分批测试数量相加作为完整验收数量。

Windows 构建脚本将 JDK 的临时 Unix-domain 套接字路径设为本工程 `.tools/tmp`，绕开长用户 TEMP 路径造成的 `Invalid argument: connect`；不改变系统 TEMP、不升级 JDK。Maven 用户属性会传入 Surefire/Failsafe；手工启动其他 JVM 时如遇相同问题，应使用相同短临时目录设置。

验收入口启用 `acceptance` profile，将本次源码打包为 `adtek-server-acceptance.jar`；CLI 和进程恢复测试通过 `adtek.test.jar` 使用该产物。四个旧库脚本新增可选 `-JarPath`，省略时仍用原默认产物。这样既能验证实际打包入口，也不会覆盖常驻开发 JVM 已打开的默认 JAR。不能跳过打包后用旧 JAR 的结果证明当前源码正确。
