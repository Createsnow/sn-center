## 1. 业务概述

### 1.1 业务流程

![图 1-1 端到端业务时序](images/MES对接说明/f0-business.png)

| 阶段 | 说明 |
| --- | --- |
| 订单与生成 | SN 系统定时同步金蝶已审核的生产订单；总部按 PI 生成 SN，号池全局不重复 |
| 分配与下发 | 总部把 SN 分配到生产组织；SN 系统分批推送给该组织的 MES，MES 回执确认；推送失败时 MES 主动拉取 |
| 生产打标 | MES 下发 SN，现场打标、过站、LINK（MES 内部流程，不涉及本接口） |
| 转移 | 转单、转组织后 SN 系统改挂，给转入方下发新挂靠，给原组织发转移批次；原组织停止打标已转走的 SN，旧标签按「转出号清单」作废 |

### 1.2 SN 状态

![图 1-2 SN 状态与 MES 收到的批次](images/MES对接说明/f9-sn-state.png)

| SN 状态 | 含义 | 与 MES 的关系 |
| --- | --- | --- |
| 待分配 | 已生成，尚未分到生产组织 | 不可见 |
| 待推送（未入批） | 已分到对接 MES 的组织，尚未组批 | 等待推送或拉取 |
| 待推送（批次未确认） | 已组批，MES 尚未回执 | 正在推送，或可拉取 |
| 待推送（批次失败） | MES 整批退回，或回执与批次不符 | MES 修正后拉取重处理，或总部续推 |
| 已推送 | MES 已确认（推送应答、拉取回执或总部人工确认） | MES 已持有 |
| 已分配 | 分到未对接 MES 的组织 | 不经过 MES |
| 申请中 | 已提交转组织申请，等待总部处理 | 仅在 ⑤ 中提醒（`APPLYING`） |

- 总部作废未确认的批次后，SN 回到「待推送（未入批）」，重新组批送达
- 单据反审核、订单变更待确认时，未下发的 SN **暂停下发**：不组批，③ 应答的 `paused` 为暂停枚数

### 1.3 挂靠版本 rev 与批次类型

- **SN 字符串永不改变**，变的只是挂靠（生产组织、PI、单据行、物料、客户）
- 生成时 `rev = 1`；每次转单、转组织、订单变更改挂 `rev` 加 1，**越大越新**；MES 原样保存，不得自行加减
- **`rev` 相同则挂靠相同**，同一 `rev` 重复送达覆盖一次结果不变
- `batchType` 说明这批 SN 从哪来，**一批只有一种**；按 **MES 已有的数据** 判断：SN 系统收到 `OK` 回执（或总部人工确认）后才认定 MES 已持有，未持有时被转移的 SN 对 MES 仍是 `NEW`

| 触发事件 | `rev` | 收件 MES | `batchType` | MES 处理 |
| --- | --- | --- | --- | --- |
| 首次下发 | 不变 | 本组织 | `NEW` | 新增 |
| 同组织转移 | +1 | 本组织 | 已持有：`SAME_ORG_TRANSFER`；未持有：`NEW` | 覆盖挂靠 / 新增 |
| 跨组织转移 | +1 | 转入组织 | 原组织已持有：`TRANSFER_IN`；未持有：`NEW` | 新增 |
| 跨组织转移 | +1 | 原组织（仅曾持有时发） | `TRANSFER_OUT` | 标记「已转走」，停止打标 |
| 转回原组织（A → B → A） | +1 | A 收交付、B 收转出 | A：`TRANSFER_IN`；B：`TRANSFER_OUT` | A 覆盖并清除「已转走」；B 标记「已转走」 |
| 订单变更「确认对应」、告警重推 | +1 | 本组织（已持有） | `REMAP` | 覆盖挂靠 |
| 批次重送、重新拉取 | 不变 | — | 同一批次，内容逐字节相同 | 按 `batchNo` 幂等 |

MES 已持有的 SN 在转移、改挂当时单独建批（`SAME_ORG_TRANSFER` / `TRANSFER_IN` / `REMAP`）；其余 SN 从号池按流水顺序认领，绝大多数为 `NEW`。

## 2. 接口总览

### 2.1 接口清单

| # | 接口 | 方向 | 提供方 | 请求 | 调用时机 |
| --- | --- | --- | --- | --- | --- |
| ① | 接收批次 | SN → MES | **MES** | `POST {MES 地址}` | 分配、转移、续推后；连接测试 |
| ③ | 拉取批次 | MES → SN | SN 系统 | `POST /api/mes/v1/batches/next` | 推送失败后、本地 SN 不足、每 5 分钟兜底 |
| ④ | 提交回执 | MES → SN | SN 系统 | `POST /api/mes/v1/batches/{batchNo}/receipt` | ③ 拉取的批次落库后 |
| ⑤ | 查询已下发 SN | MES → SN | SN 系统 | `GET /api/mes/v1/sn/delivered` | 可选，对账 |
| ⑥ | 查询批次明细 | MES → SN | SN 系统 | `GET /api/mes/v1/batches/{batchNo}/items` | 可选，对账 |

- ① 的回执在**同一应答**中返回；④ 只用于 ③ 拉取的批次
- 编号沿用历史编号（② 已移除）

### 2.2 交互通道

![图 2-1 接口交互时序](images/MES对接说明/f2-interface.png)

| 通道 | 说明 |
| --- | --- |
| 推送（主通道） | SN 系统调 ①，MES 处理后在应答中回执；失败按 1、5、15 分钟重送 |
| 转移通知 | 跨组织转移时，给转入组织发交付批次的同时给原组织发 `TRANSFER_OUT`，互不等待 |
| 拉取（补偿） | MES 调 ③ 取批，落库后调 ④ 回执；可取回未送达的推送批次和转移批次 |
| 对账 | ⑤⑥ 只读，**不得**据此入库、打标或删除 |

推送与拉取的批次**格式完全相同**，MES 只需实现一套处理逻辑（第 3 章）；同一批次可能经两条通道到达，按 `batchNo` 只处理一次。

## 3. MES 批次处理规范

### 3.1 批次报文

所有批次结构相同，按 `batchType` 区分明细内容：

| 批次 | `batchType` | `batchNo` 前缀 | 送达 | 明细 |
| --- | --- | --- | --- | --- |
| 交付批次 | `NEW` / `SAME_ORG_TRANSFER` / `TRANSFER_IN` / `REMAP` | `PS`（推送时建）/ `PL`（拉取时建） | ① 或 ③ | 交付项，≤ 5000 枚 |
| 转移批次 | `TRANSFER_OUT` | `XO` | ① 或 ③ | 转出项，≤ 5000 枚 |
| 测试批次 | `PING` | `PING` | ① | 空数组 |

> 报文以带注释的 JSON 展示，注释格式：`类型，含义`，全部字段必填（标「可空」的值可为 `null`）；★ 标出 MES 用于判断的字段。实际报文不含注释。

**交付批次**

```jsonc
{
  "schemaVersion": "1.0",              // String，协议版本
  "batchNo": "PS-110-20261019-000123", // String，批次号，全局唯一 ★ 幂等键
  "batchType": "SAME_ORG_TRANSFER",    // String ★ 分流（3.2 步骤 1）
  "orgCode": "110",                    // String，收件组织 ★ 非本组织 → 整批退回
  "itemsDigest": "sha256:9f2c4e…",     // String，内容指纹，MES 存储并按字符串比对，无需自行计算 ★ 幂等校验
  "items": [
    {
      "sn": "HX100000001A",            // String，完整 SN
      "rev": 2,                        // Number，挂靠版本 ★ 不小于本地才新增或覆盖
      "serial": "000001",              // String，流水号（可能为 36 进制写法）
      "serialDec": "1",                // String，十进制流水，按字符串保存
      "serialPi": "000001",            // String，流水所属 PI；转入的 SN 可能 ≠ pi，不要互相校验
      "pi": "000001",                  // String，当前所属 PI（一个交付批次只含一张 PI）
      "billNo": "VT2026090001",        // String，单据号（EEP 生产订单号）
      "billSeq": 1,                    // Number，单据行号；同一单据可能有相同物料，以行号区分
      "materialCode": "9148363",       // String，可空，物料编码
      "length": "0100",                // String，可空，米标，原样保存（不得变为 100）
      "customerCode": "0001"           // String，客户编码
    }
  ]
}
```

**转移批次**　跨组织转移后发给原组织

```jsonc
{
  "schemaVersion": "1.0",
  "batchNo": "XO-110-20261019-000007",
  "batchType": "TRANSFER_OUT",
  "orgCode": "110",                    // 原组织（收件方）
  "itemsDigest": "sha256:51ab07…",
  "items": [
    {
      "sn": "HX100000003A",            // String，完整 SN
      "rev": 3,                        // Number ★ 不小于本地才标记；本地没有时按 sn、rev 建一条「已转走」记录
      "toOrgCode": "120"               // String，转入组织，记录备查
    }
  ]
}
```

**测试批次**　总部点「连接测试」时发送

```jsonc
{"schemaVersion": "1.0", "batchNo": "PING-202610190237001234", "batchType": "PING", "orgCode": "110", "itemsDigest": "sha256:…", "items": []}
```

### 3.2 处理步骤

![图 3-1 MES 批次处理流程](images/MES对接说明/f3-batch-check.png)

| 步骤 | 规则 | 结果 |
| --- | --- | --- |
| 1 分流 | 交付类 4 种、`TRANSFER_OUT` 继续；`PING` 只校验身份和 `orgCode`，不存储、不记批次号；其他取值整批退回 | `PING`：`OK` / `NG` |
| 2 整批校验 | `orgCode` 为本组织；批内 SN 不重复；必填字段齐全、长度在本侧允许范围内 | 不通过：`NG` + 原因，**不写任何数据、不记 `batchNo`** |
| 3 幂等 | `batchNo` 已处理过：`itemsDigest` 相同直接回 `OK`；不同返回 409 `BATCH_CONTENT_MISMATCH` | — |
| 4 逐枚处理 | 见下表 | — |
| 5 落库 | 按 `batchNo` 加锁，同一批次不得并发处理；批次号、`itemsDigest`、SN 数据同一事务落库；5000 枚建议 10 秒内（推送超时 60 秒） | 成功 `OK`；出错整批回滚 `NG` |

**逐枚处理**（只看批次类别、本地有无该 SN、`rev`）

| 批次 | 本地没有 | 批次 `rev` ≥ 本地 | 批次 `rev` < 本地 |
| --- | --- | --- | --- |
| 交付批次 | 按报文新增，可打标 | 覆盖挂靠（PI、单据、行号、物料、米标、客户），清除「已转走」，保留打标状态 | 跳过 |
| 转移批次 | 建一条只有 `sn`、`rev` 的「已转走」记录 | 更新 `rev`，标记「已转走」、记 `toOrgCode`，停止打标 | 跳过 |

- 跳过不算失败，整批仍回 `OK`；SN 系统不需要逐枚结果
- 转移批次本地没有也要建档：同一 SN 迟到的旧交付（`rev` 更小）会被跳过，不会被当作本组织持有而继续打标
- **不得**因「批次里没有某枚 SN」作废本地数据：批次是增量的
- 已转走的 SN 不删除；已打出的旧标签由现场按「转出号清单」作废

### 3.3 交付类批次类型

| `batchType` | 含义 | MES 本地通常 | MES 可选的内部处理 |
| --- | --- | --- | --- |
| `NEW` | 首次交给本 MES（含：未下发时被转移） | 没有 | — |
| `SAME_ORG_TRANSFER` | 本 MES 已持有的号转到本组织另一订单 | 有 | 切换数据链的订单关联（见 4.2） |
| `TRANSFER_IN` | 原组织 MES 已持有的号转入本组织（与原组织的 `TRANSFER_OUT` 成对） | 没有（转回时有「已转走」记录） | 提示从原组织调拨实物、补打标签 |
| `REMAP` | 本 MES 已持有的号因订单变更改挂，或总部以 SN 系统为准重推 | 有 | 同 `SAME_ORG_TRANSFER` |

- 4 种处理完全相同，是否接收、是否覆盖**只按 3.2 逐枚处理**，不得因具体类型拒收、跳过或回 `NG`
- 本地情况与「通常」不符时（如 `SAME_ORG_TRANSFER` 但本地没有）仍按 3.2 处理，可记日志备查
- SN 系统增加 `batchType` 取值前先与 MES 书面确认

### 3.4 回执

推送时作为 ① 的应答返回；拉取时作为 ④ 的请求体提交，格式相同。

```jsonc
{
  "batchNo": "PS-110-20261019-000123", // String，照抄批次号
  "code": "OK",                        // String，OK 整批已处理（含逐枚跳过）/ NG 整批退回
  "message": null                      // String，可空；NG 时必填退回原因，显示在总部页面
}
```

| 情况 | ① 应答 |
| --- | --- |
| 整批写入成功（含逐枚跳过） | HTTP 200 + `code = OK` |
| 整批校验不通过、写入出错 | HTTP 200 + `code = NG` + `message` |
| 同一批次正在处理 | 处理完返回同一回执，或 409 `BATCH_IN_PROGRESS` |
| 同一批次号内容不同 | 409 `BATCH_CONTENT_MISMATCH` |
| 认证失败 / 报文无法解析 / 报文过大 | 401、403 / 400 / 413 |

`OK` 必须在 SN 数据写入成功后才返回：SN 系统据此认定 MES 已持有这些 SN。

## 4. 转移

![图 4-1 转移交互时序](images/MES对接说明/f11-transfer-seq.png)

### 4.1 SN 系统侧规则

![图 4-2 SN 系统侧转移流程](images/MES对接说明/f10-transfer-sn.png)

1. **发起**：转单由总部发起；转组织由生产组织申请、总部确认，或总部直接转移；单次最大一整张单据，不支持整张 PI
2. **可转校验**：SN 所在批次（含转移批次）未确认或失败时不可再转，确保同一 SN 的批次按顺序到达；迟到的旧请求由 `rev` 比对跳过
3. **改挂**：清除 SN 原批次，`rev` 加 1
4. **下发**：MES 已持有的当场建批（同组织 `SAME_ORG_TRANSFER`；跨组织给转入方 `TRANSFER_IN`、同时给原组织 `TRANSFER_OUT`），按转入组织的单批枚数拆分；未持有的回号池，作为 `NEW` 下发；目标单据暂停交付时不建批，解除后照常下发
5. **不等待 MES**：不发撤回指令、不等 MES 同意；推送失败按普通批次重试、续推，MES 也可拉取

### 4.2 MES 侧规则

**同组织转移**

![图 4-3 同组织转移](images/MES对接说明/f12-same-org.png)

转移在 SN 系统中立即生效，**无需现场或 MES 事先确认**；MES 按 `rev` 覆盖挂靠、回 `OK`，回执没有「拒绝转移」选项。MES 因过站方式、LINK 状态等无法在本侧完成转移时**自行处理**，SN 系统不感知、不等待、不回滚。MES 内部可参考：

1. **客户 SN 过站**：将该 SN 整条数据链的订单关联切换到新订单（数据混乱风险由 MES 控制）
2. **内部 SN 过站**：客户 SN 已 LINK 的不能转移，由 MES 自行处理；未 LINK 的直接转移

**跨组织转移**　直接同步到新组织，不考虑原组织 MES 的数据：

- **转入组织**：本地无此 SN，按报文新增，无需与原组织核对
- **原组织**：无需同步、回滚或清理原数据链，只按转移批次标记「已转走」并停止打标，防止两个工厂使用同一 SN；旧标签由现场按「转出号清单」作废（报文不带转移单号）

## 5. 异常处理

| 场景 | SN 系统 | MES |
| --- | --- | --- |
| 推送超时、宕机、5xx、429、503 | 按 1、5、15 分钟重送，内容逐字节相同；用尽后停止，页面显示「继续推送」 | 按 `batchNo` 幂等；恢复后也可直接拉取该批次 |
| MES 整批退回（`NG`） | 批次记失败，显示 `message`；同一 PI 后续推送暂停 | 修正后：③ 带 `batchNo` 取回 → 重新处理 → ④ 提交回执 → 请总部「继续推送」 |
| 总部作废批次 | ③④ 对该批次返回 409 `BATCH_VOIDED`；SN 以新批次号重新送达，`rev` 不变：`NEW` 回号池重新组批，其余类型按原 SN 当场重建同类型批次并推送 | 丢弃该批次，**不得**用本地缓存继续处理 |
| 某枚 SN `rev` 小于本地 | — | 跳过该枚、保留本地，整批照常 `OK`；如需排查用 ⑤ 查当前 `rev` 与挂靠 |
| 回执长期缺失 | 总部按 MES 书面答复处理：已入库 →「人工确认」，SN 变为已推送；未处理 →「作废」，重新组批 | 书面告知总部是否已入库 |
| 回执与批次不符（422 `RECEIPT_MISMATCH`） | 批次记失败 | 按 `details` 改正后重交 |

## 6. 通用约定

### 6.1 传输与编码

| 项目 | 约定 |
| --- | --- |
| 协议 | HTTPS，不跟随 3xx 跳转 |
| 格式 | JSON（UTF-8）；请求带 `Content-Encoding: gzip` 时请求体为 gzip，先解压再解析 |
| 应答压缩 | 请求带 `Accept-Encoding: gzip` 时应答可 gzip；SN 系统（③～⑥）对 1 KB 以上的应答压缩 |
| ① 推送 | 默认原始 JSON；生产组织开启「gzip 压缩」时请求体 gzip（开启前须确认 MES 支持解压） |
| 协议版本 | SN 系统发出的报文带 `schemaVersion`，现为 `1.0`；MES 发出的请求、回执无需携带 |

### 6.2 字段与数据格式

| 项目 | 约定 |
| --- | --- |
| 命名 | 英文小驼峰 |
| 兼容性 | 后续只增加字段、不修改已有字段；**不认识的字段直接忽略** |
| 时间 | UTC，ISO 8601，如 `2026-10-19T02:37:00Z` |
| SN | ≤ 64 位，仅字母、数字、`-`、`.`、`_`；**区分大小写** |
| 字符串型数字 | `serialDec`、`length` 按字符串保存，不得转数字（防止丢失前导 0 或溢出） |
| 多组织 | 一套 MES 服务多个组织时，以「组织 + SN」为唯一标识，数据按组织隔离 |

### 6.3 认证与签名

**① SN 系统 → MES（待定）**

> **待定**：① 由 MES 方提供，认证方式以 MES 方书面确认为准。SN 系统已实现以下两种，每个组织二选一，总部在「MES 配置」中设定，密钥线下提供给 MES 方。

| 方式 | 适用 | 请求头 | MES 校验 |
| --- | --- | --- | --- |
| A 固定令牌 | 内网 | `Authorization: Bearer <令牌>` | 核对令牌，并限制来源为 SN 系统服务器 IP |
| B HMAC 签名 | 公网（推荐） | `X-Sn-Timestamp`、`X-Sn-Signature` | 校验时间差 ≤ 5 分钟，重算签名用常量时间比对 |

![图 6-1 HMAC 签名与校验](images/MES对接说明/f8-hmac.png)

```text
签名串 = X-Sn-Timestamp + "\n" + hex(SHA256(解压后的请求体字节))
签名   = hex(HMAC-SHA256(密钥, 签名串))          // 小写十六进制，UTF-8
```

摘要按**解压后的原始字节**计算，不得先解析 JSON 再序列化。

**③～⑥ MES → SN 系统**

- 每次请求带 `Authorization: Bearer <工号>:<密钥>`，无需换取令牌；账户由总部在「账户 → MES 接口账户」创建后提供
- 账户只能访问所绑定的生产组织；可设来源 IP 白名单；连续认证失败 10 次锁定 15 分钟

### 6.4 响应判定与限流

| 项目 | 约定 |
| --- | --- |
| ① 成功判定 | MES 能拆包处理即返回 HTTP 200 + 回执（含整批退回 `NG`），见 7.1 |
| ③～⑥ 成功判定 | HTTP 200 且 `code = OK`；出错时 HTTP 状态码一定不是 200，程序按 `code` 处理，`message` 仅供阅读 |
| 限流 | ③～⑥ 每个组织每分钟 60 次；超出返回 429 `RATE_LIMITED`，按应答头 `Retry-After` 秒数等待 |

### 6.5 错误响应与错误码

③～⑥ 出错时的应答：

```jsonc
{
  "schemaVersion": "1.0",
  "code": "RECEIPT_MISMATCH",          // String ★ 错误码，程序按它处理
  "message": "回执与批次不符",           // String，中文说明，仅供阅读
  "batchNo": "PL-110-20261019-000045", // String，可空，相关批次号
  "details": [{"field": "code", "reason": "只能是 OK / NG，收到 DONE"}] // Array，错误明细，可能为空
}
```

| HTTP | `code` | 接口 | 含义 | 处理 |
| --- | --- | --- | --- | --- |
| 400 | `INVALID_REQUEST` | ③～⑥ | 请求体不是合法 gzip / JSON，或参数不合法 | 修正请求 |
| 401 | `INVALID_CREDENTIALS` | ③～⑥ | 缺少认证头，或工号、密钥错误（含密钥已重置） | 核对后重试 |
| 403 | `IP_NOT_ALLOWED` | ③～⑥ | 来源 IP 不在白名单 | 联系总部 |
| 403 | `ACCOUNT_DISABLED` | ③～⑥ | 账户已停用 | 联系总部 |
| 403 | `FORBIDDEN` | ③④ | 非 MES 接口账户 | 改用 MES 接口账户 |
| 403 | `ORG_NOT_ALLOWED` | ③ | 该 PI 下没有分到本组织的 SN，也没有本组织的转移批次 | 检查 `pi` |
| 404 | `BATCH_NOT_FOUND` | ③④⑥ | 批次号不存在，或不属于本组织 | 检查 `batchNo` |
| 409 | `BATCH_CONFIRMED` | ③ | 批次已回执 | 无需再处理 |
| 409 | `BATCH_VOIDED` | ③④ | 批次已作废 | 丢弃，不得用本地缓存处理 |
| 422 | `RECEIPT_MISMATCH` | ④ | 回执与批次不符 | 按 `details` 改正后重交 |
| 423 | `ACCOUNT_LOCKED` | ③～⑥ | 连续认证失败已锁定，期间密钥正确也拒绝 | 等待解锁 |
| 429 | `RATE_LIMITED` | ③～⑥ | 调用过于频繁 | 按 `Retry-After` 等待 |
| 5xx / 超时 | — | ③～⑥ | — | 直接重试（③ 返回同一批次，④ 以同一回执重交） |

MES 在 ① 中返回的 409 `BATCH_IN_PROGRESS`、`BATCH_CONTENT_MISMATCH` 见 7.1。

## 7. 接口定义

### 7.1 ① 接收批次

> **待定**：由 MES 方提供，地址、认证方式待 MES 方书面确认（见 6.3）。

SN 系统把批次（3.1）推送给 MES；MES 按第 3 章处理并落库后，在**同一应答**中返回回执（3.4）。

| 项目 | 内容 |
| --- | --- |
| 请求 | `POST {MES 地址}`，地址由 MES 方提供，总部在「生产组织 → MES 配置」中填写 |
| 调用时机 | 分配、转移、续推后；总部点「连接测试」时发 `PING` |
| 请求体 | 批次，见 3.1 |
| 应答 | HTTP 200 + 回执，见 3.4 |

![图 7-1 推送与回执](images/MES对接说明/f6-push.png)

**请求头**

| 参数 | 必填 | 示例 | 说明 |
| --- | --- | --- | --- |
| `Content-Type` | 是 | `application/json; charset=utf-8` | 固定 |
| `Content-Encoding` | 否 | `gzip` | 开启「gzip 压缩」时才带 |
| `Authorization` | 方式 A | `Bearer 7f3c…` | 见 6.3 |
| `X-Sn-Timestamp`、`X-Sn-Signature` | 方式 B | `2026-10-19T02:37:00Z`、`a3f9…` | 见 6.3 |
| `X-Sn-Attempt` | 是 | `1` | 第几次送达，仅供日志 |
| `X-Request-Id` | 是 | UUID | 请求编号，仅供日志，**不得用于去重** |

**MES 返回的 HTTP 状态码**

| 场景 | MES 返回 | SN 系统处理 |
| --- | --- | --- |
| 处理完成（`OK`）或整批退回（`NG`） | **200** + 回执 | `OK`：批次确认，SN 变为已推送；`NG`：批次记失败并显示原因 |
| 同一批次正在处理 | 409 `BATCH_IN_PROGRESS` | 稍后重送 |
| 批次号相同、内容不同 | 409 `BATCH_CONTENT_MISMATCH` | 不重送，告警 |
| 认证失败（令牌、签名错误，时间超差） | 401 / 403 | 不重送 |
| 地址错误 | 404 | 不重送 |
| 报文过大 | 413 | 不重送；总部作废后按更小的单批枚数重发 |
| 报文无法解析 | 400 | 不重送 |
| 超时、5xx、网络中断、429、503 | — | 1、5、15 分钟后重送 |

只要能拆包处理就返回 200 + 回执，4xx 仅用于「完全无法处理」；缺字段、`orgCode` 不符等业务问题返回 200 + `NG`。HTTP 200 但 `code` 不是 `OK` / `NG` 时，SN 系统记为应答无效，不重送。

### 7.2 ③ 拉取批次

`POST /api/mes/v1/batches/next`　请求头：`Authorization: Bearer <工号>:<密钥>`；请求体可 gzip（带 `Content-Encoding: gzip`）

优先返回范围内**最早的未回执批次**（推送未送达的、拉取后未回执的、转移批次），没有时才新建拉取批次；已退回、已作废的批次不自动返回。

![图 7-2 拉取与提交回执](images/MES对接说明/f7-pull.png)

**请求**（字段均选填，不填即不限）

```jsonc
{
  "pi": "000001",   // String，限定 PI
  "billNo": null,   // String，限定单据；可与 pi 同时使用
  "batchNo": null   // String，取回指定批次（如修正后重处理被退回的批次）；填写后 pi、billNo 不生效，且不会新建批次
}
```

转移批次按其中 SN 转出前的 PI、单据判断是否在范围内。

**应答**

```jsonc
{
  "schemaVersion": "1.0",
  "code": "OK",
  "batch": { /* 批次，见 3.1 */ }, // Object，可空 ★ null = 暂无可拉取批次，1 分钟以上再试
  "remaining": 1200,              // Number ★ 范围内剩余可拉取枚数，> 0 时继续拉取
  "paused": 0                     // Number，暂停下发的枚数，等待总部处理，无需反复拉取
}
```

- 处理完成须**立即调 ④ 提交回执**；回执前重复拉取返回同一批次（`batchNo`、`itemsDigest` 相同）
- 错误码：`ORG_NOT_ALLOWED`、`BATCH_NOT_FOUND`、`BATCH_CONFIRMED`、`BATCH_VOIDED` 及通用错误码（6.5）

---

### 7.3 ④ 提交回执

`POST /api/mes/v1/batches/{batchNo}/receipt`　请求头同 7.2

对 ③ 拉取的批次提交回执（含整批退回）；推送的批次已随 ① 应答回执，无需再提交。

- **请求体**：回执（3.4）；`batchNo` 须与路径一致，`code` 为 `OK` 或 `NG`，否则 422 `RECEIPT_MISMATCH`
- **应答**：`{"schemaVersion": "1.0", "code": "OK"}`
- 按批次号幂等：重复提交同一回执照常返回 `OK`；批次已确认的只存档
- 错误码：`RECEIPT_MISMATCH`、`BATCH_VOIDED`、`BATCH_NOT_FOUND` 及通用错误码（6.5）

---

### 7.4 ⑤ 查询已下发 SN

`GET /api/mes/v1/sn/delivered`　请求头：`Authorization: Bearer <工号>:<密钥>`

返回 SN 系统认定已下发给本组织 MES 的 SN（含推送和拉取），已转至其他组织的不返回。**仅用于对账**，不得据此入库、打标或删除。

**Query**

| 参数 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `pi` | 否 | 不限 | 限定 PI |
| `cursor` | 否 | 空 | 分页游标：首页留空，之后填上一页的 `nextCursor` |
| `pageSize` | 否 | `1000` | 每页条数，最大 5000 |

**应答**

```jsonc
{
  "schemaVersion": "1.0",
  "code": "OK",
  "items": [
    {
      // sn、rev、serial、serialDec、serialPi、pi、billNo、billSeq、materialCode、length、customerCode：同 3.1 交付项
      "sn": "HX100000001A",
      "rev": 2,
      "…": "…",
      "status": "PUSHED",                 // String，PUSHED 已推送 / TO_PUSH 改挂待推送 / APPLYING 转组织申请中（仅提醒）
      "batchNo": "PS-110-20261019-000123" // String，可空，当前所在批次
    }
  ],
  "nextCursor": "10086"                   // String，可空 ★ 下一页游标；null = 最后一页
}
```

错误码：通用错误码（6.5）。

---

### 7.5 ⑥ 查询批次明细

`GET /api/mes/v1/batches/{batchNo}/items?cursor=&pageSize=`　请求头同 7.4

返回该批次中**仍属于该批次**的 SN（已转至其他组织的不返回，整批移出时为 0 枚）。仅用于对账。

- Query `cursor`、`pageSize` 同 7.4
- 应答同 7.4：`{schemaVersion, code, items, nextCursor}`
- 错误码：`BATCH_NOT_FOUND` 及通用错误码（6.5）
