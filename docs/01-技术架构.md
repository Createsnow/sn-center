# 技术架构 0.1.0

本模板是前后端同仓的独立工程：React 单页应用 + Spring Boot 模块化单体 + MySQL + Redis。模板只提供架构、规范与代码结构，不包含业务功能。

## 总体结构

```text
浏览器 ──HTTPS──> TLS 入口（Ingress / 负载均衡 / 主机反向代理）
                     │
                     └──HTTP──> Web（nginx：静态资源 + /api 反向代理，8080）
                                  │
                                  └──HTTP（容器内网）──> API × N（Spring Boot，18090）
                                                          ├── MySQL 8.4：业务数据与任务的最终状态
                                                          └── Redis 8.4：会话与入口限流预算
迁移 Job（同一 API 镜像，migrate profile）──DDL 账号──> MySQL
```

- 前端与后端只通过 `/api/v1/**` 的 HTTP JSON 契约交互；契约以后端导出的 OpenAPI 为准，前端生成 TypeScript 类型。
- API 只在容器内网开放，由 Web 转发；TLS 在入口层终止。API 无状态，可水平扩展。
- 不引入消息队列、分布式缓存或微服务拆分；需要时先在文档中论证，再新增组件。

## 后端模块

依赖方向固定为：`server → system / 业务模块 → framework → common`。

| 模块 | 职责 | 允许依赖 |
| --- | --- | --- |
| `adtek-common` | 纯契约：统一结果 `Result`、错误码 `ErrorCode`/`CommonErrorCode`、`BusinessException`、分页 `PageResult`、主体、注解 | 仅 JDK 与校验 API |
| `adtek-framework` | 基础设施：安全（已有默认拒绝的过滤链骨架）、会话、数据范围、审计、任务/文件、Web 通用设施（已有全局异常处理与 traceId）；定义跨模块窄端口（Port） | common |
| `adtek-system` | 平台能力：身份、认证、用户、角色、部门、菜单、字典、审计查询；实现 framework 端口 | framework |
| `adtek-sample` | 业务模块骨架，新业务按此复制为 `adtek-{业务}`；不打包进 server，只在 server 测试类路径上供架构测试检查 | framework |
| `adtek-server` | 装配入口：启动类、运行配置、数据库迁移、架构与错误码目录测试、集成测试 | 全部模块 |

约束（由 `ArchitectureTest` 在构建时强制）：

- common、framework 不依赖 system、业务模块或 server；common 不依赖 framework。
- 只有 server 可以依赖 server；模块之间无循环依赖。
- 任一模块的 `mapper` 与 `service.impl` 只允许本模块访问；跨模块交互通过对方 `service` 接口或 framework 中的端口。
- 全局扩展点只在 framework 与 server 声明：过滤器、拦截器、`@ControllerAdvice`、切面、安全链、MyBatis 插件与自动填充、JSON/转换器配置、Bean 后处理器、`@Primary`、`@Enable*` 全局开关、数据源/事务/缓存/线程池/Redis Bean。业务模块（含 system）的类只在本模块包内，资源只在 `mapper/{module}/`、`db/migration/{module}/` 与本模块包路径下，不得携带 `application.yml`、`spring.factories`、`static/` 等全局资源。由 `boundary/ModuleBoundaryTest` 强制。
- 外部系统适配器（ERP、MES 等）放在独立 `adtek-integration-*` 模块，由 server 装配，不混入 common。

## 数据与状态

- MySQL 是业务和任务的最终状态；Redis 只保存会话与入口预算，不保存替代事务的额度、版本或任务成功标志。
- Redis 不可用时返回依赖失败，不放行请求。
- 表归属：每个模块只创建和访问以模块名为前缀的表（`system_*`、`order_*`），迁移随模块 jar 发布（`db/migration/{module}/`）；跨模块数据只经 framework 端口取得，不跨模块联表。由 `DataOwnershipTest` 强制。
- 数据库结构只通过 Flyway 版本迁移演进；`V1__baseline.sql` 固定库默认字符集 `utf8mb4` 与排序规则 `utf8mb4_0900_as_cs`。运行账号只有 DML 权限，迁移由单独的 DDL 账号执行。
- 成功审计与业务写入在同一事务提交；审计写失败则业务回滚。

## 安全架构

- 过滤链骨架 `framework.security.SecurityConfiguration`：只放行健康探针（local profile 另放行 `/v3/api-docs`），`/api/**` 要求认证，其余默认拒绝；无状态、SPA 模式 CSRF，401/403 统一写出 `Result` 信封。模板不内置认证机制与账号，项目在该链中加入以下认证实现。
- 认证：JWT 访问令牌 + Redis 服务端会话 + MySQL 当前授权共同生效，任何一项失效即拒绝。
- 主体只从服务端解析的当前会话读取；不接受客户端提交的权限、操作者或所有者作为授权依据。
- 授权在服务用例中检查；Controller 注解和前端按钮隐藏不能替代服务检查。
- 数据范围（部门、部门树、本人、全部等）由服务端可信数据决定，并精确登记到 Mapper 语句；新语句默认拒绝。
- 令牌不写入 localStorage/sessionStorage；写请求校验 CSRF；登录与刷新入口有失败锁定与限流。

## 运行与部署架构

- **Windows 本地**：`tools\*.bat` 在命令行直接运行 JAR 与 Vite；MySQL/Redis 由 `deploy/compose.infra.yml` 在 Docker Desktop 中提供。
- **Linux 部署**：`deploy/compose.yml` 中 migrate、api、web 各为独立单进程容器，可与 `compose.infra.yml` 合并成单机部署，或连接外部 MySQL/Redis。
- **K8s 扩展**：服务一一对应 Job / Deployment / Service / Ingress；配置走环境变量，秘密走 `/run/secrets` 文件，健康检查对应 liveness / readiness 探针。详见[工程要求与命令](06-工程要求与命令.md#k8s-扩展基础)。
- 后端构建产物为 `backend/adtek-server/target/adtek-server-0.1.0.jar`，前端为 `frontend/dist`；`deploy/api/Dockerfile`、`deploy/web/Dockerfile` 只复制这两个已验证的产物，构建上下文由 `.dockerignore` 白名单限制。镜像使用固定摘要（`deploy/images.lock.json`）。
- 迁移：API 关闭 Flyway，不持有 DDL 密码；`migrate` profile 以 DDL 账号单次执行后退出，禁止 clean/baseline。
- 生产环境需自行提供 TLS 证书、备份恢复、容量、日志保留与监控方案。
