# 多工厂 SN 防重管控需求说明（修订版）

总部统一生成并分配 SN，具备全部操作权限，也可以代工厂领取、打印。工厂按本厂数量领取、打印。同一张 PI 下的 SN 不得重复。本文约定号的挂靠、生成、分配、领取、打印、转厂、账户和留痕。

## 角色

总部账号就是系统管理员，不绑定厂区，具备全部操作权限。可以创建和停用账户、维护规则、生成、分配、代任一工厂领取和打印、确认或驳回转厂、不经申请直接转厂，并查看全部工厂的号。

系统管理员用公司工号创建账户，工号唯一。账户只停用、不删除；停用后不能登录，历史痕迹保留。新账户首次登录必须修改初始密码。

厂区操作员必须绑定一个厂，只能操作本厂。查询员可以不绑厂；不绑则跨厂只读，绑了则只看该厂。查询员可以打开领取页和转厂页，只能查看，不能领取，也不能提交转厂申请。

工厂不能自己生成 SN，不能代其他厂领取或打印，也不能在查询界面里直接把号转走。规则模板、生成和分配，工厂不能操作。

## SN 与 PI

SN 挂在 PI 上。每一枚 SN 同时记录：工厂、客户编码、PI、物料编码、来源生产订单单据编号、规则版本、流水归属 PI、十进制流水和状态。

一张 PI 可以对应多张生产订单。集团主客户与集团子客户的编码不同，客户不参与查重。

查重只认同一张 PI：

1. 同一张 PI 下，完整 SN 不重复。转入这张 PI 的号也参与这项检查。
2. 这张 PI 自己生成的号，十进制流水不重复。转入的号，流水仍归属原 PI，不占用本 PI 的流水。

不同 PI 可以出现相同的 SN 字符串。实际上各 PI 规则的前缀、后缀和字符集基本不同，不会相撞。SN 一经写出，字符串不再修改。

## 数据来源

生产订单来自金蝶生产订单快照，先落入本地，生成和领取不在当时现读金蝶。快照按物料明细保存，一张生产订单的每一条物料一行。不另存单据头，也不保存金蝶单据内码和分录内码。客户编码、单据编号、PO、PI、生产组织来自表头，写在该单每一行上。

每一行有这些内容：客户编码、单据编号、PO、PI、物料编码、物料名称、该物料行数量、业务状态、需求单据号、生产组织、本次同步时间。业务状态只保留计划、计划确认。需求单据号是销售订单号，可以空着。生产组织就是工厂。一张生产订单只属于一个厂。同一张单据下，客户编码、PO、PI、生产组织相同。同一单据、同一物料在金蝶有多行时，快照保留多行，不合并。

快照里没有单独的 PI 数量列。一张生产订单含有一个 PI，以及 0 个或多个物料编码。这张订单要生成的 SN 数，是该单据下各物料行数量之和。订单页左表显示这个合计，右表仍是各物料的编码、名称和数量。物料编码为空的行，也用该行自己的数量计入合计。没有任何明细的单据不会进入快照。客户编码为空的行留在快照里，订单列表不显示。

全量同步先完整拉取金蝶数据，再在同一个事务里清空旧快照、写入新快照；写入失败时整体回滚，不出现快照为空的时刻。按单据编号同步时，只替换该编号下的行。金蝶调用失败时，已有快照保持不动。

订单进入下达及之后，会从快照中消失。已经生成的号不受影响，仍按号上记录的来源单据编号查询。

## 生成与分配

### 额度

生成以一张生产订单为单位。这张订单的可生成额度为：快照中该单各物料行数量之和，减去该单已生成的号数。额度为 0 时不能生成。只有仍处于计划、计划确认的订单可以生成和领取。

同一厂、同一张 PI 出现在多张生产订单上时，各订单分别生成，在同一张 PI 的一套流水上依次接续。页面按「工厂 + PI」汇总显示各订单的已生成数和额度。物料行数量不另起一套流水。

PI 必须与 ERP 生产订单上的 PI 一致，才允许生成和领取。不要求这张 PI 一定有销售订单。已经生成或已经分配的号，在订单状态变化后仍然保留。

### 状态

号的状态依次是待分配、待领取、待打印、已打印。另有一个状态：申请中，表示工厂已提交转厂申请，等待总部处理。

号生成后写入中心化号池，状态为待分配。总部确认分配后，号挂到该生产组织，状态变为待领取，本厂或总部才能领取。同一厂、同一张 PI 不另发一套新号。

### 预演与生成

生成和分配在同一个页面，分成两步：先按额度准备号，再确认分给该生产组织。分配之前不能领。

生成前必须先预演。预演只给出起止号和数量，不逐条生成，也不落库。预演时记下这张 PI 当前的最大号。以下任一情况发生，预演结果失效，必须重新预演：

1. 预演条件改变。
2. 点击生成时，这张 PI 的最大号已经和预演时不同，例如有人在此期间生成过。

没有完成本次预演，不能生成。用户点击生成后，后台才真正生成并写入数据库。同一张 PI 同一时刻只允许一个生成操作，其他人提交时提示稍后再试。

一次生成在一个事务内完成；失败时整批回滚，不留下半批号。数量较大时后台作为任务执行，页面显示进度。

本 PI 下一次生成的起点，取以下两者中较大的一个再加 1：本 PI 自己的最大号；已转入本 PI 的号按本 PI 当前规则解析出的最大流水。转入的号与本 PI 接续时，就是接着排；不接续时，越过中间的号（这些号本 PI 不再生成）。按本 PI 规则解析不出的转入号（格式不同）将来不会重复，不参与计算。预演时注明起点因哪个转入号而后移；预演之后又有号转入、起点变化时，预演失效，须重新预演。

生成时，如果某个完整 SN 仍与本 PI 已有的号相同，停止生成并提示，不自动跳号。

### 号段与物料

生成的号仍是这一张 PI 的一套连续流水。按快照中物料行的顺序，把这套流水切成连续号段，每一行一段，并给每一枚 SN 标上该行的物料编码。同一物料有多行时，就有多段。物料编码为空的行，对应号段的物料为空。

分配按整张生产订单一次完成，同一张订单上的各个物料一起分到同一个工厂。页面上的分配数量默认填入这次生成的全部数量，分配工厂默认填入该订单上的生产组织，不能分到别的厂。

### 单次数量

页面上单次生成、单次分配的默认上限是 10000 枚，用户可以在页面上手动修改这个上限。后台不设上限。

### 规则

规则可以按通用、按客户或按单张 PI 绑定。生成时有绑定（按 PI 优先，其次按客户）就用绑定的规则；都没有绑定时，由用户选择一条规则模板（默认通用规则），首次生成后这张 PI 一直沿用所选规则。改了前缀、后缀、进制、位数或字符集，必须另出一版。新规则只作用于之后新生成的号，已经发出的号仍用旧版。该版本下还没有生成过任何号时，可以就地修改当前版。只改名称，不另出一版。

单张 PI 的累计生成数量不设 99999 上限。规则位数用尽时停止并提示。

### 起始号

上线导入历史数据时，每张 PI 在首次生成前可以指定一次起始号。指定的起始号须大于已转入本 PI 的号的流水（见「生成与分配」）。指定后，页面不再提供这张 PI 的起始号。此后按「生成与分配」中的起点规则继续排，不另行跳号。每张 PI 的流水各自延续，互不影响。

可以选择同时导入该 PI 历史上已发出的 SN 清单。导入的号状态为已打印，参与查重。

## 领取与打印

统一在领取页面领取、打印。总部可以在该页选择任一工厂，代为领取和打印。工厂只能操作已经分给本厂的号。接口领取和页面看的是同一批号。状态记在每一枚 SN 上，不记在整张 PI 上。页面按「工厂 + PI + 物料 + 连续号段 + 状态」分行。

对外只有领取接口和回调接口，不提供转厂接口。领取只按 PI 整批进行，页面和接口一样，都不按物料、不按单枚拆开领。处于申请中的号不参与领取。

1. 领取页。点某一张 PI 的待领取，该厂该 PI 下全部待领取的号一起变为待打印。再点待打印，这些号一起变为已打印，并给出打印文件。其他 PI 不动。
2. 接口。领取只负责把 SN 传出去，只按 PI，传出该厂该 PI 下全部待领取的号，不提供按物料编码领取。传出的同时，这些 SN 从待领取改为待打印。

### 领取批次与幂等

每次领取生成一个领取批次号。接口调用方必须传入请求号：

- 同一请求号重复调用，返回同一个批次，不再改动任何号的状态。
- 第一次调用超时或网络中断后，调用方用原请求号重试，就能拿回这批号。
- 已经变成待打印、属于其他批次的号，不会被再次领取传出。

领取接口返回批次号和本批数量，号明细按页返回。另提供按批次号查询明细的接口，可以反复读取。每一枚都给出完整 SN、进制流水和十进制数。

### 回调

回调用领取时传出的 SN 来对。调用方把这批 SN，或领取返回的连续起止号，连同批次号和目标状态发回。回调只把属于该厂、属于这个批次、当前为待打印的号写成已打印，不在这批里的号不动。已经是已打印的，重复回调不再改别的号。已经转走或处于申请中的号不改，并在返回结果中逐一列出。

### 页面与查询

领取页不另存一套状态。分配确认后，打开或刷新领取页，按每一枚 SN 上的工厂、PI、物料编码和当前状态重新拼号段。整单虽然一次分给一个工厂，页面仍按物料分行，每一行都是待领取，工厂都是刚才那个默认工厂。没有物料编码时，整单合成一行，物料为空。

按 PI 领取后刷新，该厂该 PI 下各物料的待领取行一起变成待打印。回调写成已打印之后，领取页不再显示这些号。某一物料不该留在本厂时，先在转厂页转走，再按剩下的整张 PI 领取。

一枚 SN 对应一台出货产品。生产数量是多少，就准备多少枚号，每台各用各的号。

可以按 PI 筛选，也可以按 PI 加物料编码筛选。

另有按生产组织、客户和 PI 的拉取，物料编码可以不传。这次拉取只读，不改变领取或打印状态，也不能代替领取。

客户和打印都认完整 SN。查询、领取详情和打印文件同时给出完整 SN、当前规则所用的进制流水，以及对应的十进制数。详情按页给出，不在 100 条处截断。

工厂登录后，默认只看总部已分给本厂的 PI 和号。可以切换为只读，查看同一张 PI 下已经分到各个厂的号。尚未分配、工厂为空的号不在这个只读范围里。总部登录后可看全部工厂，并可切换到任一厂做领取、打印和转厂。

## 转厂

转厂只在转厂页操作，没有转厂接口。

### 可转移范围

待分配、申请中的号不能转移。待领取、待打印、已打印的号可以转移。一次转移的来源限定在同一张 PI 内，可以按三种范围选择：

1. 这一张 PI 下当前可以转移的全部 SN。
2. 这一张 PI 加一个物料编码下的全部 SN。其他物料不动。
3. 这一张 PI 下的某一枚 SN。只转这一枚。

同一枚号同时只能有一张未完成的转厂申请。

### 转入目标

转入目标包括生产组织、客户编码、PI 和物料编码。可以从生产订单快照中选择，也可以手工填写：

- 生产组织必须是系统中已有的工厂。
- PI 必填。
- 客户编码、物料编码留空时，沿用原值。
- 手工填写的内容不与金蝶核对，转厂记录中标为「手工填写」。

转厂后，这批号的查询、领取和打印都按新的工厂、客户编码、PI 和物料编码进行。SN 字符串保持不变。

### 流程

1. 工厂在转厂页提交申请，必须填写原因。这批号的状态改为申请中，不能领取、打印，回调也不改动它们。
2. 总部确认后，号改挂到转入目标，在转入厂的状态为待领取。转入厂按正常流程重新领取、打印。原来打出的标签不再使用，由工厂现场处理。
3. 总部驳回后，这批号恢复为申请前的状态。
4. 总部确认或驳回之前，申请工厂可以撤回申请，号恢复为申请前的状态。

总部也可以不经申请直接转移，这批号直接成为转入厂的待领取。

转出厂仍能在转厂记录中查到这些号，标为已转出，不能再领取、打印。

### 查重与流水

转入 PI 下已经存在相同完整 SN 时，拒绝整次转移，并列出重复的号（数量与示例）。页面在提交前就提示重复。

转厂不改号的流水归属，这批号的流水仍归属原 PI。原 PI 之后生成新号时，从原 PI 的最大号加 1 接着排。转入 PI 自己的最大号不被这批号抬高，但转入 PI 之后生成时会越过这批号（见「生成与分配」中的起点规则），不会与转入号重复。如果这次转移会让转入 PI 的下一个号后移，提交、确认前提示「下一次生成将从某号开始（原为某号），有多少个号不再生成」，只提示、不拒绝。转入号流水很大、转入 PI 的位数不够用时，给该 PI 配置位数更多的「按 PI」规则即可继续生成。其他 PI 的流水不受这次转移影响。

转走的号仍计入来源订单的已生成数。

## 留痕与容量

以下操作留下痕迹：

- 账户：创建、停用。
- 规则：修改、另出一版。
- SN：生成、分配、领取、打印、回调。
- 转厂：申请、撤回、确认、驳回、直接转移。

页面上的领取和打印，与接口领取、状态回写记在同一类审计里。每条痕迹记录操作人、时间、来源（页面或接口）、PI、工厂、号段或数量、操作前后状态，以及批次号、请求号或原因（有则记）。领取即占用，不另设激活。

痕迹至少保存 3 年，也可以配置为永久。

按每月约 400 万枚 SN、每天都会生成并领取来准备容量，3 年约 1.5 亿枚。SN 和痕迹按月分区，过期的痕迹归档。查询、导出和领取详情按条件分页读取，不把全部号一次装入内存。

## 界面约定

数量、起始号、起止 SN、转厂原因这些手填框单独占一行，放在该步操作的上方。

## 附：按经验补充、待业务确认的项

以下各项原文没有写明，本版按常见做法补全，请业务方逐条确认：

1. 每枚 SN 记录来源生产订单单据编号，额度按「订单数量减去已生成数量」计算，防止同一张订单重复生成。
2. 同一张 PI 的生成加锁串行执行；生成时发现最大号已变化，预演失效。
3. 快照中物料行按顺序切段，物料编码为空的行对应号段物料为空。
4. 领取接口用请求号保证幂等；新增按批次号查询明细的接口；明细分页返回。
5. 转厂申请可撤回；驳回或撤回后号恢复申请前的状态；申请中的号回调不改。
6. 已打印的号转厂后变为待领取、重新打印，原标签不再使用，由现场处理。
7. 转走的号仍计入来源订单的已生成数。
8. 历史起始号按 PI 指定一次，可以选择导入历史 SN 清单参与查重。
9. 账户只停用不删除，首次登录修改密码。
