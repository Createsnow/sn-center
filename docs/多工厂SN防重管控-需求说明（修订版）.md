# 多工厂 SN 防重管控需求说明（修订版）

> **读者**：业务方、项目负责人、测试　**更新**：2026-10-10
> **相关**：[关键节点说明](关键节点说明.md)　需求如何落地见 [技术文档 §9](技术文档.md#9-关键设计与需求落地说明)　[文档导航](README.md)

总部统一生成并分配 SN，具备全部操作权限，也可以代工厂领取、打印。工厂按本厂数量领取、打印。同一张 PI 下的 SN 不得重复。本文约定号的挂靠、生成、分配、领取、打印、转厂、账户和留痕。

## 角色与账户

系统只有三种角色：系统管理员（总部）、厂区操作员、查询员。

总部账号就是系统管理员，不绑定厂区，具备全部操作权限。可以管理账户、工厂和规则，同步订单，生成、分配、撤销生成，代任一工厂领取和打印，确认或驳回转厂，不经申请直接转厂，并查看全部工厂的号。

厂区操作员必须绑定一个厂，只能操作本厂：领取、打印、提交和撤回本厂的转厂申请。工厂不能自己生成 SN，不能代其他厂领取或打印，也不能在查询界面里直接把号转走。规则模板、生成和分配，工厂不能操作，也看不到生产订单页。

查询员可以不绑厂；不绑则跨厂只读，绑了则只看该厂。查询员可以打开生产订单、领取、转厂、查询和操作痕迹页，只能查看，不能领取、打印，也不能提交转厂申请。

各角色可见的页面：

| 页面 | 系统管理员 | 厂区操作员 | 查询员 |
| --- | --- | --- | --- |
| 首页看板、领取与打印、转厂、SN 查询、操作痕迹 | ✓ | ✓（本厂） | ✓（只读） |
| 生产订单 | ✓ | — | ✓（只读） |
| 生成与分配、规则模板、账户、工厂 | ✓ | — | — |

### 账户

1. 系统管理员用公司工号创建账户，工号唯一（2–32 位字母、数字、`_`、`-`）。创建时选角色、绑定工厂（按上面的绑定要求），并设定初始密码。
2. 新账户用创建时设定的密码直接登录，不强制改密；本人可随时修改自己的密码。
3. 管理员可以重置他人的密码；重置后该账户下次登录必须先修改密码。改密或重置后，旧的登录令牌失效。
4. 账户可以修改姓名、角色和绑定工厂。
5. 账户只停用、不删除；停用后不能登录，历史痕迹保留。停用的账户可以重新启用。不能停用自己；系统至少保留一名启用的管理员，最后一名管理员不能停用，也不能改成其他角色。
6. 密码 8–64 位，同时含字母和数字。
7. 同一工号连续登录失败达到上限（默认 15 分钟内 5 次）后锁定一段时间（默认 15 分钟），锁定期间密码正确也拒绝。
8. 内置管理员的工号和初始密码由部署配置给出，空库首次启动时创建。

## SN 与 PI

SN 挂在 PI 上。每一枚 SN 同时记录：工厂、客户编码、PI、物料编码、来源生产订单单据编号、规则版本、流水归属 PI、十进制流水和状态。

一张 PI 可以对应多张生产订单。集团主客户与集团子客户的编码不同，客户不参与查重。

查重只认同一张 PI：

1. 同一张 PI 下，完整 SN 不重复。转入这张 PI 的号也参与这项检查。
2. 这张 PI 自己生成的号，十进制流水不重复。转入的号，流水仍归属原 PI，不占用本 PI 的流水。

不同 PI 可以出现相同的 SN 字符串。实际上各 PI 规则的前缀、后缀和字符集基本不同，不会相撞。SN 一经写出，字符串不再修改。

## 数据来源

### 工厂

工厂主数据来自金蝶组织机构，总部在工厂页同步，也可以手工建档。生产订单上的生产组织按工厂名称对应到工厂。生产组织还没有建档为工厂的订单，订单页和生成页都会提示，不能生成。

### 生产订单快照

生产订单来自金蝶生产订单快照，先落入本地，生成和领取不在当时现读金蝶。快照按物料明细保存，一张生产订单的每一条物料一行。不另存单据头，也不保存金蝶单据内码和分录内码。客户编码、单据编号、PO、PI、生产组织来自表头，写在该单每一行上。

每一行有这些内容：客户编码、单据编号、PO、PI、物料编码、物料名称、该物料行数量、业务状态、需求单据号、生产组织、本次同步时间。业务状态只保留计划、计划确认。需求单据号是销售订单号，可以空着。生产组织就是工厂。一张生产订单只属于一个厂。同一张单据下，客户编码、PO、PI、生产组织相同。同一单据、同一物料在金蝶有多行时，快照保留多行，不合并。

快照里没有单独的 PI 数量列。一张生产订单含有一个 PI，以及 0 个或多个物料编码。这张订单要生成的 SN 数，是该单据下各物料行数量之和；物料行数量有小数时按整数部分计。订单页左表显示这个合计以及已生成数、可生成数，右表是各物料的编码、名称和数量。物料编码为空的行，也用该行自己的数量计入合计。没有任何明细的单据不会进入快照。客户编码为空的行留在快照里，订单列表不显示，页面注明有几张这样的单据。

### 同步

订单页提供全量同步和按单据编号同步，只有总部能操作。

全量同步先完整拉取金蝶数据，再在同一个事务里清空旧快照、写入新快照；写入失败时整体回滚，不出现快照为空的时刻。按单据编号同步时，只替换该编号下的行；该单已不在计划、计划确认时，从快照移除。金蝶调用失败时，已有快照保持不动。

快照不会自己更新。除了手动同步，总部可以开启定时全量同步，并设定间隔（最短 10 分钟，最长 7 天）。开启或改了间隔后，从保存时起算下一次。每次定时执行与手动全量同步完全相同，操作人记为 system；失败时快照不动，记下失败原因，下个周期再试。订单页显示是否开启、间隔、下次执行时间和最近一次结果；只有总部能修改，查询员只能查看。改设置和每次执行都留痕。

订单进入下达及之后，会从快照中消失。已经生成的号不受影响，仍按号上记录的来源单据编号查询；这张 PI 还有订单留在快照中时，生成页详情里仍列出已离开快照的订单（额度为 0），其已生成、未分配的号仍可分配；整张 PI 的订单都离开快照后，生成页列表里不再出现这张 PI。

## 生成与分配

### 额度

每张生产订单的可生成额度为：快照中该单各物料行数量之和，减去该单已生成的号数。额度为 0 时不能生成。只有仍处于计划、计划确认的订单可以生成。

生成前，订单必须同时满足：有客户编码、有 PI、生产组织已建档为工厂、有可用规则、额度大于 0。少一项，页面提示原因。

PI 必须与 ERP 生产订单上的 PI 一致，才允许生成和领取。不要求这张 PI 一定有销售订单。已经生成或已经分配的号，在订单状态变化后仍然保留。

### 以 PI 为单位

生成与分配页面以 PI 为单位，每张 PI 一行，显示客户、单据数、生产组织、进度（已分配 / 已生成待分配 / 未生成）、可生成额度和待分配数。页面显示订单快照的最近同步时间。

页面分两个页签：

1. **待生成**：列出快照中的全部 PI（含已经生成完的），最近下单（单据编号大）的在前。只列最近 3 页，更早的 PI 用搜索找。
2. **待分配**：只列还有号待分配的 PI。

可以按 PI、客户、单据编号、PO 搜索。

每行的按钮写着下一步：

| 情况 | 行上按钮 |
| --- | --- |
| 在「待分配」页签，或这张 PI 已没有额度但还有号待分配 | 分配 N 枚 |
| 生成过一部分，还有额度 | 继续生成（打开详情） |
| 规则已确定、生产组织已建档，还没生成过 | 生成 N 枚（预演后确认即生成） |
| 其他还有额度的 PI（如需要先选规则） | 首次生成（打开详情） |

点一行打开该 PI 的详情：当前规则、下一个号、当前最大号、进度、各订单的明细（物料行、已分配、待分配、可生成）、生成任务与分配记录。

同一张 PI 出现在多张生产订单上时，各订单在这张 PI 的一套流水上依次接续。按 PI 生成时，本次数量按单据编号从小到大依次占用各订单的额度。生产组织未建档的订单先跳过，不挡住同 PI 其他订单。物料行数量不另起一套流水。

### 状态

号的状态依次是待分配、待领取、待打印、已打印。另有一个状态：申请中，表示工厂已提交转厂申请，等待总部处理。

号生成后写入中心化号池，状态为待分配，还没有工厂。总部确认分配后，号挂到该生产组织，状态变为待领取，本厂或总部才能领取。同一厂、同一张 PI 不另发一套新号。

### 预演与生成

生成和分配在同一个页面，分成两步：先按额度准备号，再确认分给生产组织。分配之前不能领。

生成前必须先预演。详情里填好数量（以及需要时选好规则）后停顿片刻，页面自动预演。预演只给出起止号、各订单分到的数量和按物料切出的号段，不逐条生成，也不落库。预演时记下这张 PI 当前的最大号。预演只对发起人本人有效，默认 30 分钟后过期。以下任一情况发生，预演结果失效，必须重新预演：

1. 预演条件改变（数量、规则、订单、物料行）。
2. 点击生成时，这张 PI 的最大号已经和预演时不同，例如有人在此期间生成过。
3. 预演之后又有号转入这张 PI，起点变化。

没有完成本次预演，不能生成。用户确认生成后，后台才真正生成并写入数据库。同一张 PI 同一时刻只允许一个生成操作，其他人提交时提示稍后再试。

整张 PI 的这次生成在一个事务内完成：各订单依次生成，任何一张失败，整张 PI 全部回滚，不留下半批号。数量较大时（默认超过 5000 枚）后台作为任务执行，页面显示进度；关掉页面再打开，仍能看到进度。服务重启时没跑完的任务视为失败，已整批回滚，重新预演后可以再生成。

本 PI 下一次生成的起点，取以下两者中较大的一个再加 1：本 PI 自己的最大号；已转入本 PI 的号按本 PI 当前规则解析出的最大流水。转入的号与本 PI 接续时，就是接着排；不接续时，越过中间的号（这些号本 PI 不再生成）。按本 PI 规则解析不出的转入号（格式不同）将来不会重复，不参与计算。预演和详情里注明起点因哪个转入号而后移。

生成时，如果某个完整 SN 仍与本 PI 已有的号相同，停止生成并提示，不自动跳号。

### 单次数量

页面上的生成数量默认填入「可生成额度」与 10000 两者中较小的一个，用户可以在额度之内手动改大或改小。后台不另设上限，只受额度和规则位数约束。

### 撤销生成

生成后发现点错了（数量、订单或规则选错），总部可以撤销这次生成，再重新预演、生成。详情里显眼处给出「撤销这次生成」，生成任务列表里也可以撤销。撤销须填写原因，并留下痕迹。

1. 只能撤销这张 PI 流水排在最后的一次生成。之后还有生成的，先撤销之后的。整张 PI 一次生成多张订单的，从最后一张订单起逐张撤销。
2. 这次生成的号必须全部仍是待分配。只要有一枚已经分配出去，就不能撤销。这张 PI 正在生成时也不能撤销。
3. 撤销后，这次的号从号池中删除；这张 PI 的最大号、订单的已生成数一起退回，可生成额度恢复。重新生成的号与撤销前相同，号段不留空洞。
4. 撤销不改动规则：该规则版本仍算已使用，给 PI 指定的规则仍保留；需要换规则时先解绑再重新选择。

### 号段与物料

生成的号仍是这一张 PI 的一套连续流水。按快照中物料行的顺序，把这一张订单分到的号切成连续号段，每一行一段，并给每一枚 SN 标上该行的物料编码。订单已生成过一部分时，从上次切到的位置接着切。同一物料有多行时，就有多段。物料编码为空的行，对应号段的物料为空。

### 分配

分配把号分到订单上的生产组织，不能分到别的厂。

1. 默认按整张 PI 分配：这张 PI 下各订单全部待分配的号，在一个事务里分别分到各自订单的生产组织。分配前页面按生产组织汇总数量和订单，供核对。
2. 一张 PI 有多张订单待分配时，也可以只分配其中一张订单。
3. 同一张订单上的各个物料一起分到同一个工厂。

分配后状态变为待领取，留下分配记录（订单、工厂、起止号、数量、操作人、时间）。

### 规则

规则决定 SN 的前缀、后缀、进制、流水位数和字符集。规则可以按通用、按客户或按单张 PI 绑定。

1. 生效顺序：按 PI 绑定 ＞ 按客户绑定 ＞ 已指定给这张 PI 的规则。
2. 都没有时，由用户从全部通用规则中选一条（默认编码最小的一条）。可以先点「指定给此 PI」固定下来；不指定时，首次生成会自动把所选规则指定给这张 PI，之后一直沿用。
3. 指定给 PI 的规则可以解绑后重新选择。换规则后流水接续，已生成的号不变，之后生成的号换成新规则的格式。按客户或按 PI 绑定的规则不能在生成页解绑，要在规则模板页修改它的绑定。
4. 通用规则可以有多条；按客户、按 PI，每个对象只能绑一条规则。规则的绑定可以修改，改成「通用」即解绑。
5. 改了前缀、后缀、进制、位数或字符集：该版本下还没有生成过任何号时，就地修改当前版；已经生成过的，必须另出一版。新版本只作用于之后新生成的号，已经发出的号仍记旧版。只改名称，不另出一版。
6. 自定义字符集的长度须等于进制，且字符不重复；留空用该进制的系统默认字符表。

单张 PI 的累计生成数量不设 99999 上限。规则位数用尽时停止并提示。

## 领取与打印

统一在领取页面领取、打印。总部可以在该页选择任一工厂，代为领取和打印。工厂只能操作已经分给本厂的号。接口领取和页面看的是同一批号。状态记在每一枚 SN 上，不记在整张 PI 上。

对外只有领取接口和回调接口，不提供转厂接口。领取只按 PI 整批进行，页面和接口一样，都不按物料、不按单枚拆开领。处于申请中的号不参与领取。

1. 领取页。点某一张 PI 的「领取」，该厂该 PI 下全部待领取的号一起变为待打印。再点「打印」，该厂该 PI 下全部待打印的号一起变为已打印，并给出打印文件。其他 PI 不动。
2. 接口。领取只负责把 SN 传出去，只按 PI，传出该厂该 PI 下全部待领取的号，不提供按物料编码领取。传出的同时，这些 SN 从待领取改为待打印。

### 领取页

领取页每个「工厂 + PI」一行，显示客户、待领取 → 待打印的数量和申请中的数量。页面分四个页签：全部、待领取、待打印、申请中。可以按 PI 搜索，总部可以按工厂筛选。

每行的按钮写着下一步：在「待领取」「待打印」页签分别是领取、打印；在「全部」页签，还有待领取的先显示领取，否则显示打印。可以勾选多张 PI 批量领取或批量打印，每张 PI 只做它行上按钮那一步。批量打印的打印文件在页面上逐个下载，之后也可以在 SN 查询页重新下载。

点一行打开详情：按「工厂 + PI + 物料 + 连续号段 + 状态」分行列出号段，可从这里转厂（如转走某个物料），查看这张 PI 的领取批次和打印记录。

页面打印同样以请求号防重：网络重试不会重复改号。号已被 MES 回调或他人先处理时，页面提示实际处理的枚数。

### 领取批次与幂等

每次领取生成一个领取批次号。接口调用方必须传入请求号：

- 同一请求号重复调用，返回同一个批次，不再改动任何号的状态。
- 第一次调用超时或网络中断后，调用方用原请求号重试，就能拿回这批号。
- 同一请求号换了 PI 再调用，拒绝。
- 已经变成待打印、属于其他批次的号，不会被再次领取传出。

领取接口返回批次号和本批数量，号明细按页返回。另提供按批次号查询明细的接口，可以反复读取。每一枚都给出完整 SN、进制流水和十进制数。批次也可以导出为文件（格式同打印文件），导出只读，不改状态。

### 回调

回调用领取时传出的 SN 来对。调用方把这批 SN，或领取返回的连续起止号，连同批次号和目标状态发回；目标状态只能是已打印。回调只把属于该厂、属于这个批次、当前为待打印的号写成已打印，不在这批里的号不动。已经是已打印的，重复回调不再改别的号。已经转走或处于申请中的号不改，并在返回结果中逐一列出。单次回调枚数有上限（默认 20 万枚）。

### 页面与查询

领取页不另存一套状态。分配确认后，打开或刷新领取页，按每一枚 SN 上的工厂、PI、物料编码和当前状态重新拼号段。整单虽然一次分给一个工厂，详情仍按物料分行，每一行都是待领取，工厂都是该订单的生产组织。没有物料编码时，整单合成一行，物料为空。

按 PI 领取后刷新，该厂该 PI 下各物料的待领取行一起变成待打印。打印或回调写成已打印之后，领取页不再显示这些号。某一物料不该留在本厂时，先在转厂页转走，再按剩下的整张 PI 领取。

一枚 SN 对应一台出货产品。生产数量是多少，就准备多少枚号，每台各用各的号。

另有按生产组织和 PI 的拉取接口，客户编码、物料编码可以不传。这次拉取只读，不改变领取或打印状态，也不能代替领取。

客户和打印都认完整 SN。查询、领取详情和打印文件同时给出完整 SN、当前规则所用的进制流水，以及对应的十进制数。详情按页给出，不在 100 条处截断。

工厂登录后，默认只看总部已分给本厂的 PI 和号。可以切换为只读，查看同一张 PI 下已经分到各个厂的号（只限本厂也有号的 PI）。尚未分配、工厂为空的号不在这个只读范围里。总部登录后可看全部工厂，并可切换到任一厂做领取、打印和转厂。

## SN 查询

SN 查询页只读，不能在这里转走号。分三个页签：

1. **SN 明细**：按工厂、客户、PI、物料、状态、完整 SN、来源订单、领取批次筛选。厂区可切换为只读查看同一 PI 各厂的号。
2. **领取批次**：按 PI、批次号、请求号、来源（页面或 MES 接口）查找，查看批次明细，导出批次文件。
3. **打印记录**：按 PI、打印单号、请求号查找，重新下载打印文件。

按流水号范围查询：

1. 必须先填 PI。起止可以填流水号（左侧补位的 0 可省略）或完整 SN，两端都包含；只填一端表示另一端不限。起号大于止号时提示。
2. 只查本 PI 自己生成的流水；转入本 PI 的号不在范围内。
3. 结果附范围小计：查到几枚、各状态几枚；两端都填时给出范围应有枚数，并提示有几枚不在结果中（未生成、已转出，或不符合其他筛选条件）。

查询结果可以导出 xlsx 或 csv（默认最多 100 万行，超出时提示缩小条件）。列表总数超过 10 万时只统计到 10 万。

## 转厂

转厂只在转厂页操作，没有转厂接口。工厂提交申请，总部直接转移；总部代厂转厂时用直接转移，不走申请。

### 可转移范围

待分配、申请中的号不能转移。待领取、待打印、已打印的号可以转移。一次转移的来源限定在同一张 PI 内，可以按三种范围选择：

1. 这一张 PI 下当前可以转移的全部 SN。
2. 这一张 PI 加一个物料编码下的全部 SN。其他物料不动。
3. 这一张 PI 下的某一枚 SN。只转这一枚。

同一枚号同时只能有一张未完成的转厂申请。提交前页面显示范围内共有多少枚、可转移多少枚。

### 转入目标

转入目标包括生产组织、客户编码、PI 和物料编码。可以从生产订单快照中选择，也可以手工填写：

- 生产组织必须是系统中已有的工厂。
- PI 必填。
- 客户编码、物料编码留空时，沿用原值。
- 转入目标与来源完全相同（工厂、PI 相同，客户、物料也没有变化）时拒绝。
- 手工填写的内容不与金蝶核对，转厂记录中标为「手工填写」。

转厂后，这批号的查询、领取和打印都按新的工厂、客户编码、PI 和物料编码进行。SN 字符串保持不变。

### 流程

1. 工厂在转厂页提交申请，必须填写原因。这批号的状态改为申请中，不能领取、打印，回调也不改动它们。
2. 总部确认后，号改挂到转入目标，在转入厂的状态为待领取。转入厂按正常流程重新领取、打印。原来打出的标签不再使用，由工厂现场处理。
3. 总部驳回后，这批号恢复为申请前的状态。
4. 总部确认或驳回之前，申请工厂可以撤回申请，号恢复为申请前的状态。只有申请工厂能撤回。

总部确认、驳回时可以填写处理意见。总部也可以不经申请直接转移，必须填写原因，这批号直接成为转入厂的待领取。

转出厂仍能在转厂记录中查到这些号，标为已转出，不能再领取、打印。转厂记录按转出、转入方向区分，可以查看每张转厂单的号及其申请前状态、当前状态和当前挂靠。

### 查重与流水

转入 PI 下已经存在相同完整 SN 时，拒绝整次转移，并列出重复的号（数量与示例）。页面在提交前就提示重复；提交和确认时各再查一次。

转厂不改号的流水归属，这批号的流水仍归属原 PI。原 PI 之后生成新号时，从原 PI 的最大号加 1 接着排。转入 PI 自己的最大号不被这批号抬高，但转入 PI 之后生成时会越过这批号（见「生成与分配」中的起点规则），不会与转入号重复。如果这次转移会让转入 PI 的下一个号后移，提交、确认前提示「下一次生成将从某号开始（原为某号），有多少个号不再生成」，只提示、不拒绝。转入号流水很大、转入 PI 的位数不够用时，给该 PI 配置位数更多的「按 PI」规则即可继续生成。其他 PI 的流水不受这次转移影响。

转走的号仍计入来源订单的已生成数。

## 首页看板

首页按当前账户的范围（总部看全部，绑厂账户看本厂）显示在途的号：待分配、待领取、待打印、申请中各多少枚，以及待处理的转厂申请、生成任务和今日动作。

## 留痕与容量

以下操作留下痕迹：

- 登录：成功、失败、锁定（含来源地址）；修改密码。
- 账户：创建、修改、停用、启用、重置密码。
- 工厂：同步、手工建档。
- 订单：同步（手动与定时）、修改定时同步设置。
- 规则：创建、就地修改、另出一版、改名、修改绑定、指定给 PI、解绑。
- SN：生成、撤销生成、分配、领取、打印、回调。
- 转厂：申请、撤回、确认、驳回、直接转移。
- 痕迹归档。

被拒绝的写操作也留下一条失败痕迹。页面上的领取和打印，与接口领取、状态回写记在同一类审计里。每条痕迹记录操作人、时间、来源（页面或接口）、PI、工厂、号段或数量、操作前后状态，以及批次号、请求号或原因（有则记）。领取即占用，不另设激活。

所有角色都能打开操作痕迹页，按账户的工厂范围查看，可以导出。

痕迹至少保存 3 年，也可以配置为永久。

按每月约 400 万枚 SN、每天都会生成并领取来准备容量，3 年约 1.5 亿枚。SN 和痕迹按月分区，过期的痕迹归档。查询、导出和领取详情按条件分页读取，不把全部号一次装入内存。

## 界面约定

1. 页面支持简体中文、英文、越南文，每个账户记住自己的语言。
2. 列表页（生成与分配、领取与打印）每张 PI 一行，行上按钮写着下一步；点一行在右侧打开详情。
3. 数量、起止 SN、转厂原因这些手填框单独占一行，放在该步操作的上方。

## 附：按经验补充、待业务确认的项

以下各项原文没有写明，本版按常见做法补全，请业务方逐条确认：

1. 每枚 SN 记录来源生产订单单据编号，额度按「订单数量减去已生成数量」计算，防止同一张订单重复生成。
2. 同一张 PI 的生成加锁串行执行；生成时发现最大号已变化，预演失效。
3. 快照中物料行按顺序切段，物料编码为空的行对应号段物料为空。
4. 领取接口用请求号保证幂等；新增按批次号查询明细的接口；明细分页返回。
5. 转厂申请可撤回；驳回或撤回后号恢复申请前的状态；申请中的号回调不改。
6. 已打印的号转厂后变为待领取、重新打印，原标签不再使用，由现场处理。
7. 转走的号仍计入来源订单的已生成数。
8. 账户只停用不删除，停用后可重新启用；新账户用创建时的密码直接登录，管理员重置密码后下次登录必须修改。
9. 生成点错可撤销：只撤销 PI 流水排在最后、号全部仍待分配的一次生成，号删除，最大号与额度退回，原因必填。
10. 生成以 PI 为单位：数量按单据编号从小到大依次占用各订单额度，整张 PI 在一个事务里生成，任何一张失败全部回滚。
11. 规则绑定唯一：同一客户、同一 PI 各只允许一条规则；通用规则可以有多条，未绑定的 PI 从中选择并可解绑重选。
12. 领取时 PI 须仍在订单快照（计划、计划确认）中。现场若有「订单已下达但号还没领」或「转入的 PI 不在金蝶」的情况，可以关闭这项检查。
13. 物料行数量有小数时，按整数部分计 SN 枚数。
14. 页面打印与接口领取一样以请求号防重。
15. 整张 PI 的订单都离开快照后，还没分配的号在页面上无处分配。请确认这种情况是否存在：存在时需要另给入口（例如按 PI 打开详情），或要求先分配再让订单下达。
