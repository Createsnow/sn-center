# 能力边界与版本继承 0.1.0

模板是独立工程，提供通用平台底座和一个可替换的设备业务样板，不依赖其他项目的代码、数据库或秘密。

| 能力 | 模板处理 | 项目责任 |
| --- | --- | --- |
| 统一结果、异常、日志、格式、架构 | 保留 | 新模块增加真实契约和错误目录 |
| 身份、CSRF、会话轮换、失败锁定 | 保留 | 账号、部署 Secret、角色决定 |
| 角色、部门、菜单、字典、审计 | 保留 | 业务菜单注册和字段投影 |
| 部门/本人数据范围 | 保留 | 每个用例与 Mapper 精确登记 |
| 工厂资格 | 改为 ResourceMembershipPort | 默认空且非空绑定拒绝；业务扩展才提供实际资格 |
| 所属部门 | OrganizationMembershipPort | 仅可信 Actor，写入持安全协调锁 |
| 后台任务与文件 | 保留；在线审计 CSV 为运行样例 | 每个 handler 实现权限、快照、幂等/恢复规则 |
| 外部系统集成（ERP/MES 等）、旧库导入 | 不装配 | 按业务另建 integration 模块和协议验证 |
| 密码算法历史兼容 | 保留显式带前缀 PBKDF2-120k 读取和登录后升级，默认新写 600k | 不提供旧账号导入接口、不推测未标记哈希；AuthenticationIT/PasswordEncodingTest 约束 |
| 设备台账 | 独立完整样板 | 可替换，迁移和错误号段需独立管理 |

模块由通用底座（common/framework/system）加 equipment 业务与 server 装配组成；模板自有 V1/V2 迁移，只用于新库。资源维度授权为可关闭扩展，不含具体外部协议。模板工具只读取自己的路径和秘密。

新项目的 template-origin.json 记录采用版本与准确来源提交。公共修复通过模板新版本发布说明给出影响、文件清单、迁移及回归要求；各产品挑选修复并记录采纳结果，不自动覆盖已有业务文件/SQL。破坏性契约变更提升次版本，兼容修复提升补丁版本；批准的依赖升级另行验证。

GitLab 文件面向 Windows PowerShell shell runner，需 windows-pwsh-docker 标签、Node 24、Edge、Docker Linux engine。流水线执行本地同一门禁并上传受控结果；runner 名称需按项目实际配置。
