## 1. 概述

### 1.1 接口一览

| 接口 | 调用方向 | 地址 | 什么时候调 | 接口文档 |
| --- | --- | --- | --- | --- |
| 推送接口 | SN 系统 → MES | `{MES 地址}`（MES 提供） | 连接测试；分配、转移、续推后推送批次 | 3.1 |
| 回执接口 | MES → SN 系统 | `POST /api/mes/v1/receipts` | 推送来的、拉取到的批次处理完后，每一批都要调 | 3.3 |
| 拉取接口 | MES → SN 系统 | `POST /api/mes/v1/batches/next` | 推送失败后、本地 SN 不够用时、每 5 分钟兜底 | 3.2 |
| 查询接口 | MES → SN 系统 | `POST /api/mes/v1/sn/delivered`、`POST /api/mes/v1/batches/items` | 可选，对账 | 3.4、3.5 |

### 1.2 两个「OK」的含义

| 出现在 | `code = OK` 的含义 | 不表示 |
| --- | --- | --- |
| 推送接口的应答（MES 回给 SN） | MES **已收到**这一批（连接测试同样回 `OK`） | 不表示已处理、已落库 |
| 回执接口的请求（MES 发给 SN） | MES **已处理**这一批（整批落库） | — |
| 回执接口的响应（SN 回给 MES） | SN **已收到这份回执** | 不表示批次成功；批次结果看 `batchResult` |

### 1.3 总体规则

- **批次确认以回执为准**：推送接口的应答只表示收到。SN 系统收到回执 `OK` 才确认这一批；收到 `NG` 批次记失败。人工确认除外（第 6 节）。
- **串行推送**：同一生产组织、同一 PI 的批次一批一批地推，上一批回执 `OK` 后才推下一批；转出批次单独一个推送任务。
- **批次号是幂等键**：同一批次可能多次送达，也可能经推送接口、拉取接口都到达，MES 按 `batchNo` 只处理一次；同一批次每次送达内容逐字节相同。
- **回执也幂等**：同一份回执可以重复提交，SN 系统按批次号处理，已确认的批次只存档。
- **业务问题不用 4xx**：缺字段、组织不符、本组织没有这张 PI 等，推送接口照常回 `OK`，再用回执 `NG` 整批退回。4xx 只用于认证、地址、报文过大、无法解析。

## 2. 推送接口（SN 系统 → MES）

### 2.1 连接测试

| 步骤 | 说明 |
| --- | --- |
| 触发 | 总部在「生产组织」页填好 MES 对接配置，点「连接测试」 |
| SN 发什么 | 调推送接口，发测试批次：`batchType = PING`、`count = 0`、`items = []`、不带 `pi`，批次号 `PING-` 加时间戳。认证方式、gzip、超时都与真实推送相同 |
| MES 回什么 | 校验身份和 `orgCode`，通过回 HTTP 200 + `code = OK`；`orgCode` 不是本组织回 `NG`。测试批次不落库、不记批次号、**不调回执接口** |
| SN 怎么判断 | 只有 HTTP 200 + `code = OK` 算连接成功，其他一律失败；不核对 `batchNo` |
| 结果的作用 | 测通后记下这份配置的摘要（组织、地址、认证方式、凭证、gzip）。开启「对接 MES」须当前配置已测通；已开启时改了地址、认证、凭证或 gzip，须先用新配置测通才能保存 |

### 2.2 真实推送：正常流程

1. SN 调推送接口，MES 回 HTTP 200 + `code = OK`，`batchNo` 照抄请求体，表示数据已到 MES。
2. SN 把这一批标为「等回执」，推送任务暂停等待，后面的批次先不推。
3. MES 校验、落库后调**回执接口**，报告处理结果（`OK` / `NG`）。
4. MES 检查回执接口的响应：HTTP 200 + `code = OK` 才算回执已送达，否则重交（3.3）。
5. SN 收到回执 `OK`：这一批成功，号改为「已推送」，**立即**推下一批。

```
SN 系统 ──推送接口：批次──────────▶ MES      应答 200 + OK（已收到）
                                    MES      校验、落库
SN 系统 ◀──回执接口：OK / NG─────── MES
SN 系统 ──回执接口的响应──────────▶ MES      200 + OK（回执已送达）
SN 系统 ──推送接口：下一批────────▶ MES      ……
```

### 2.3 真实推送：MES 整批退回

| 一方 | 做什么 |
| --- | --- |
| MES | 推送接口照常回 `OK`；处理时发现整批不能接收，调回执接口报 `NG`，`message` 写原因，不写入任何数据，也不登记批次号（修正后同一批次号重送能正常处理） |
| SN 系统 | 批次记失败（失败码 `REJECTED`，可作废），推送任务停止，总部页面显示原因 |
| 总部 | 问题修好后点「继续推送」，用原批次号、原内容重推；或作废这一批，号回到号池重新建批 |

### 2.4 真实推送：MES 已收到但一直没交回执

| 阶段 | 说明 |
| --- | --- |
| 等回执、重推 | 收到 `OK` 后等 1 分钟，没有回执就用原批次号、原内容重推，再等 5 分钟；再重推，再等 10 分钟；再重推，再等 10 分钟。一共重推 3 次 |
| MES 收到重复的同一批 | 照常回 `OK`，并**立即重交第一次的处理结果**（第一次的回执可能没交上来） |
| 仍然没有回执 | 批次推送状态记为「重试用尽」（失败码 `RECEIPT_TIMEOUT`），推送任务停止，后面的批次不推 |
| MES 之后补交回执 | 这一批确认成功；但推送任务已停止，后面的号要总部点「继续推送」，或 MES 用拉取接口去取（见第 9 节） |

### 2.5 真实推送：没送达，自动重试

| 项目 | 说明 |
| --- | --- |
| 哪些情况 | 超时（默认 60 秒）、断连、5xx、429、503、409 `BATCH_IN_PROGRESS` |
| 怎么重试 | 隔 1、5、15 分钟重送相同内容；MES 带 `Retry-After`（秒）时取两者中较大的 |
| 重试用尽 | 批次推送状态「重试用尽」，推送任务停止 |
| 其实已经送到 | MES 照常交回执，SN 收到即确认，并接着推下一批 |

### 2.6 真实推送：直接失败，不重试

| MES 的应答 | SN 的处理 | 能否作废 |
| --- | --- | --- |
| HTTP 200，但 `code` 不是 `OK`（如 `RECEIVED`、`NG`） | 应答无效（`RESPONSE_INVALID`），批次失败 | 否（MES 可能已处理） |
| HTTP 200，但 `batchNo` 不是这一批 | 应答不符（`RESPONSE_MISMATCH`），批次失败 | 否 |
| 401 / 403 | 认证失败，批次失败；组织配置状态标为「异常」 | 是 |
| 404 | 地址错误，批次失败；组织配置状态标为「异常」 | 是 |
| 413 | 报文过大，批次失败 | 是 |
| 400 | MES 无法解析，批次失败 | 是 |
| 409 `BATCH_CONTENT_MISMATCH` | 同一批次号内容不同，批次失败，需排查 | 否 |
| 其他 4xx | 批次失败 | 否 |

所有情况推送任务都停止，失败原因显示在总部页面。

### 2.7 回执比推送应答先到

MES 可能先调回执接口、后回推送应答（或推送应答在网络上丢失）：

- 回执 `OK` 先到：批次直接确认，推送应答到了也按「已确认」处理，接着推下一批。
- 回执 `NG` 先到（首次推送，或「继续推送」重推失败批次时）：批次记失败，推送应答到了不会改回等回执，推送任务停止并显示原因。
- 推送任务刚进入等待时回执到了：SN 发现批次状态已变，立即再跑一次推送任务。

## 3. 回执接口（MES → SN 系统）

### 3.1 提交回执

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `batchNo` | 是 | 所回执的批次号，与下发的完全一致（区分大小写、不带空格） |
| `code` | 是 | `OK` 整批已处理（含逐枚跳过的旧版本）/ `NG` 整批退回，只能是这两个值 |
| `message` | 是 | 处理说明；`NG` 时为退回原因，显示在总部页面 |
| `processedAt` | 是 | MES 处理完成时间，UTC+8，`yyyy-MM-dd HH:mm:ss.SSS` |

- 请求头带 `Authorization: Bearer <工号>:<密钥>`（MES 接口账户），只能回执本组织的批次。
- 请求体必须是原始 JSON，不支持 gzip。
- 推送来的批次和拉取到的批次，**每一批都要交回执**。

### 3.2 SN 系统的处理与返回

| 情形 | SN 的处理 | 返回 |
| --- | --- | --- |
| 第一次报 `OK` | 整批成功：逐枚记为已接收，号改为「已推送」并记 MES 持有组织；唤醒推送任务推下一批 | 200，`code = OK`，`batchResult = SUCCESS`，`firstConfirmation = true` |
| 第一次报 `NG` | 整批失败（`REJECTED`，可作废）；推送任务停止并显示原因 | 200，`code = OK`，`batchResult = FAILED`，`firstConfirmation = true` |
| 已成功的批次再报 | 只存档，不改变批次 | 200，`code = OK`，`batchResult = SUCCESS`，`firstConfirmation = false` |
| 报过 `NG` 的批次修正后报 `OK` | 改为成功（MES 经拉取接口带 `batchNo` 取回重处理时用） | 200，`code = OK`，`batchResult = SUCCESS`，`firstConfirmation = true` |
| `code` 不是 `OK` / `NG`、缺 `batchNo`、请求体为 gzip | 批次不变 | 400 `INVALID_REQUEST`，`details` 指出字段 |
| 批次不存在、不属于本组织、大小写或空格不一致 | — | 404 `BATCH_NOT_FOUND` |
| 批次已作废 | — | 409 `BATCH_VOIDED` |
| 太频繁 | — | 429 `RATE_LIMITED` + `Retry-After` |

每一份回执（包括只存档的）都留档，可在总部「交付批次」详情里查看。

### 3.3 回执送达确认（MES 侧）

MES 根据回执接口的响应判断回执是否送到 SN 系统，并在本地记下每批回执的提交状态（待提交 / 已送达 / 送达失败 / 已作废）：

| 回执接口的响应 | 判定 | MES 怎么做 |
| --- | --- | --- |
| HTTP 200 + `code = OK`，`batchNo` 与提交的一致 | **已送达**（`firstConfirmation` 为 `true` 或 `false` 都算） | 记为「已送达」，结束 |
| 超时、断连、5xx | 没送达（SN 可能收到也可能没收到） | 用**同一份回执**重交：立即 1 次，之后 10 秒、1 分钟、5 分钟，再每 5 分钟 1 次，直到送达 |
| 429 | 没送达 | 按 `Retry-After` 等待后重交 |
| 400 | 送达失败，回执内容有误（批次状态不变） | 按 `details` 改正后重交 |
| 401 / 403 / 423 | 送达失败，账户有问题 | 告警，核对 MES 接口账户后重交 |
| 404 | 送达失败 | 告警，人工核对 `batchNo`，不自动重交 |
| 409 `BATCH_VOIDED` | 批次已作废 | 记为「已作废」，丢弃这批，不再重交，不得用本地缓存处理 |

其他要求：

- **先存后交**：回执先写入 MES 本地（待提交），再调回执接口；MES 重启后继续提交没送达的回执。
- **拿不准就重交**：回执接口按批次号幂等，重交不会被重复处理；已确认的批次返回 `firstConfirmation = false`，同样表示已送达。
- **SN 还没收到回执的信号**：同一批又经推送接口送来，或拉取接口仍返回这一批，说明 SN 还没收到回执：照常应答已收到，并立即重交第一次的回执。
- **一直送达不了**：SN 等回执超时、重推 3 次后停止推送（2.4）；MES 补交成功后批次即确认。
- **自测**：契约测试 `devtools/mes_conformance.py` 的 C25 会让回执接收地址先返回 503，检查 MES 是否用同一份回执重交（见 [MES 联调指南](<MES 联调指南.md>) 第 3 节）。

## 4. 拉取接口（MES → SN 系统）

### 4.1 什么时候拉

推送失败后、本地 SN 不够用时，以及每 5 分钟兜底拉一次。拉取到的批次与推送的批次结构相同、处理相同，处理完同样调回执接口。

### 4.2 正常拉取（不带 batchNo）

| 项目 | 说明 |
| --- | --- |
| 请求 | 可按 `pi`、`billNo` 限定范围，都不填表示不限；`pi`、`billNo`、`batchNo` 须为字符串，否则 400 `INVALID_REQUEST` |
| 返回哪一批 | 范围内**最早一批未确认的批次**：推送中正在等回执或等重试的、拉取后还没回执的、转出批次都算；没有才从号池认领新号建一批 |
| 怎么拿下一批 | 交回执之前，每次拉都返回同一批；交了回执才轮到下一批 |
| 剩余数量 | 应答里 `remaining` 为范围内剩余可拉枚数，`> 0` 时继续拉；`paused` 为暂停下发的枚数 |
| 没有可拉的 | `batch = null`，`message` 为「暂无可拉取批次」（有暂停时注明枚数） |

### 4.3 取回指定批次（带 batchNo）

| 批次状态 | 返回 |
| --- | --- |
| 未确认、已失败（如整批退回后修正重处理） | 返回该批次（只读取回，不新建批次；`pi`、`billNo` 不生效） |
| 已确认 | 409 `BATCH_CONFIRMED`，无需再处理 |
| 已作废 | 409 `BATCH_VOIDED`，丢弃这批内容 |
| 不存在或不属于本组织 | 404 `BATCH_NOT_FOUND` |

### 4.4 拉取的批次被整批退回

- 这一批记失败，正常拉取不再返回它，要带 `batchNo` 才能取回。
- 同一 PI 的推送任务遇到这个失败批次也会停止，需要总部「继续推送」或作废。

### 4.5 推送与拉取同时进行

- 同一批可能经推送接口、拉取接口都到达 MES，MES 按 `batchNo` 只处理一次，回执按首次结果提交。
- MES 拉走、还没回执的批次，推送任务自动运行时不会抢着发，只有「继续推送」时才重推。
- 未开启「对接 MES」的组织，拉取接口只返回转出批次。

### 4.6 权限与限流

- 只有 MES 接口账户能调拉取接口和回执接口，且只限所绑的生产组织。
- 指定的 PI 下没有本组织的号、也没有本组织的转出批次时，返回 403 `ORG_NOT_ALLOWED`。
- 拉取接口、回执接口、查询接口合计限流：每个生产组织每分钟 60 次（查询接口每页算一次），超出返回 429 `RATE_LIMITED` + `Retry-After`。

## 5. 查询接口（MES → SN 系统，只读）

| 接口 | 用途 |
| --- | --- |
| 查询已下发 SN（`/api/mes/v1/sn/delivered`） | 查已交付给本组织 MES 的号（已推送，含拉取），按 `cursor` 分页 |
| 查询批次明细（`/api/mes/v1/batches/items`） | 查某个批次里仍在该批次中的号，已转到别的组织的不返回 |

只用于对账，**不得据此入库、打标或删除**。首页不带 `cursor`，之后原样填上一页的 `nextCursor`（其他值返回 400，不会当作首页）；超时、5xx 用同一 `cursor` 重查。

## 6. 总部人工操作

| 操作 | 什么时候用 | 结果 |
| --- | --- | --- |
| 继续推送 | 推送任务停止后（整批退回已修正、重试用尽、回执晚到等） | 清零重试与等回执次数，先用原批次号、原内容重推未确认或失败的批次（含 MES 拉取建立的），再认领新号建批 |
| 人工确认 | MES 方确认这一批已全部入库，但回执交不上来（未确认或失败的批次） | 批次成功，号改为「已推送」；推送任务正在等这一批的接着推下一批，已停止的须再点「继续推送」；原因、依据必填 |
| 作废 | MES 确实没有处理的批次：失败中可作废的（整批退回、认证 / 地址错误、报文过大、无法解析），或 MES 书面确认未处理的未确认批次 | 首次下发（`NEW`）的号回到号池重新建批；转移、改挂类的号按原号当场重建同类型新批次，转出批次按原明细重建，都自动推送；作废后 MES 再交回执或带 `batchNo` 拉取，返回 409 `BATCH_VOIDED`；原因、依据必填 |
| 转出批次 | 跨组织转移时自动建立，发给原组织 MES | 由单独的推送任务发送；回执 `OK` 后清除这些号在原组织 MES 的持有记录 |

## 7. SN 系统侧的状态

**批次结果**（`sn_delivery_batch.result`）

| 取值 | 含义 |
| --- | --- |
| `UNCONFIRMED` | 未确认：已建批，还没有回执 |
| `SUCCESS` | 成功：回执 `OK` 或人工确认 |
| `FAILED` | 失败：回执 `NG`、应答无效或不符、不重试的错误 |
| `VOIDED` | 已作废 |

**批次推送状态**（`sn_delivery_batch.push_state`）

| 取值 | 含义 |
| --- | --- |
| `IDLE` | 空闲：待发送，或已确认 / 已失败 |
| `WAIT_RECEIPT` | 等回执：MES 已应答收到，等回执接口 |
| `WAIT_RETRY` | 等重试：没送达，等下次自动重试 |
| `EXHAUSTED` | 重试用尽：自动重试或等回执重推已用完 |

**推送任务**（`sn_push_task.state`，每个「生产组织 + PI」一个，转出批次为 `#XO`）

| 取值 | 含义 |
| --- | --- |
| `QUEUED` | 排队，等调度器执行 |
| `RUNNING` | 运行中（带租约，实例宕机后由其他实例接手） |
| `WAITING` | 等待：等回执或等重试到期；回执到了立即转为排队 |
| `DONE` | 已完成：没有可推的号 |
| `STOPPED` | 已停止：失败或用尽，原因显示在页面，等「继续推送」 |

## 8. 默认参数

| 参数 | 默认值 | 配置 |
| --- | --- | --- |
| 单批枚数 | 5000 | 「生产组织」页，1–50000 |
| 推送超时 | 60 秒 | 「生产组织」页，5–600 秒 |
| 同组织同时运行的推送任务数 | 2 | 「生产组织」页，1–20 |
| 没送达的重试间隔 | 1、5、15 分钟 | `SN_PUSH_RETRY_INTERVALS_MINUTES` |
| 等回执时长（个数即重推次数） | 1、5、10 分钟 | `SN_PUSH_RECEIPT_WAIT_MINUTES` |
| MES 调用限流 | 每组织每分钟 60 次 | `SN_MES_PULL_RATE_PER_MINUTE` |
| 回执重交（MES 侧） | 立即、10 秒、1 分钟、5 分钟，之后每 5 分钟 | MES 实现 |

## 9. 已知待改进

| 问题 | 现状 | 影响 |
| --- | --- | --- |
| 回执晚到后不自动续推 | 等回执重推用尽、推送任务已停止后，MES 补交 `OK` 只确认这一批 | 后面的号要总部点「继续推送」，或 MES 用拉取接口去取 |
| 拉取批次没有超时 | MES 拉走后一直不交回执，拉取接口会一直先返回这一批 | 需人工确认、作废或继续推送 |
